# 매뉴얼 디자인 고정 프롬프트

SMART-EDC 검사패널 매뉴얼 v108의 디자인과 복사 순서 수정 기준을 정리했다. 아래 본문을 새 작업에 붙여 넣고, 수정할 원본 PDF와 디자인 기준 PDF를 함께 첨부한다. 검사패널 전용 내용을 다른 분권에 복사하지 않고 구성과 표현 방식을 맞추는 기준이다.

---

## 새 작업에 붙여 넣을 프롬프트

첨부한 원본 매뉴얼을 아래 기준으로 다시 디자인해줘. 설명이나 시안 제안에서 멈추지 말고, 수정한 PDF와 다시 편집할 수 있는 원본 파일을 만들어줘.

### 작업 자료

- 수정할 원본: [원본 파일명]
- 디자인 기준: [SMART-EDC 검사패널 매뉴얼 v108 (화면용 RGB · 인쇄용 CMYK) 또는 사용자가 지정한 최신 기준 PDF]
- 제품·브랜드명: [원본에서 확인]
- 화면 이미지: [원본과 별도 제공 자료]
- 브랜드 이미지: [제공한 이미지 또는 사용을 요청한 홈페이지]

대괄호 항목은 제공된 파일에서 확인해 채워줘. 판단할 근거가 없으면 지어내지 말고 `[확인 필요]`로 표시해줘. 적용 대상은 모두 SMART EDC 매뉴얼이야. 디자인 기준 PDF에서 SMART EDC가 있는 구간에는 같은 표기·위치·크기·굵기·색을 적용해. 검사패널 전용 목차·제목·예시는 다른 분권에 복사하지 마.

### 기준 파일과 충돌 처리

- 현재 디자인과 복사 구조의 최종 기준(SSOT)은 `prompt/기준PDF/SMART-EDC_검사패널_매뉴얼_리디자인_v108.pdf`(화면용 RGB)와 `prompt/기준PDF/SMART-EDC_검사패널_매뉴얼_리디자인_v108_CMYK.pdf`(인쇄용 CMYK)야. v105·v106은 쓰지 마. v108은 2-1절의 단순화한 색과 이 문서의 최근 수정 사항(뒤표지, 커닝 끔, 경로 색, 번호 원 색)을 모두 반영한 판이야(2026-11-09). 이 MD는 PDF를 다시 구현하기 위한 보조 문서야. 기준 PDF 이후 사용자가 명시한 변경 사항은 해당 범위에 우선 적용하고, 그 외 MD와 PDF의 차이는 PDF의 실제 배치·표현을 따라.
- 기존 매뉴얼을 수정할 때는 사용자가 지정한 최신 PDF의 글과 구성을 기준으로 해. 다른 분권에 적용할 때는 그 분권의 원본 PDF를 내용 기준으로, v108을 디자인 기준으로 사용해. 두 파일의 역할을 작업 기록에 구분해 적어.
- 기준 PDF 이후 사용자가 명시한 변경 요청은 해당 범위에만 적용해. 과거 요청의 ‘몇 px 늘리기·줄이기’를 현재 값에 다시 누적하지 마.
- 글꼴 포함 방식, 복사 순서, 이미지 해상도는 겉모양만으로 확인할 수 없어. 아래 제작·검수 기준을 별도로 확인하고, 실제로 확인하지 않은 값을 PDF에서 검증한 사실처럼 적지 마.

### 1. 원문과 사용 목적

- 글이 잘 읽히고 사용자가 화면을 보며 따라 할 수 있는 구성을 우선해.
- 원본에 없는 기능, 동작, 주의사항, 수치, 예시, 문장, 제목, 라벨을 만들지 마. 목적별 페이지, 읽는 법 페이지, 간지 설명, ‘이어서’, ‘위험·주의’ 같은 이름도 임의로 추가하지 마.
- 예외로 7절의 설정·결과·참고 안내, 8절의 유의사항 분류 제목과 기준 PDF에서 승인된 보조 문구는 사용자가 승인한 공통 디자인 표기이므로 사용해. 본문 내용과 분류는 원본에서 확인하고 추측하지 마. ‘데이터 손상 · 폼 완료 불가’ 보조 문구도 원본이 해당 위험을 설명할 때만 사용해.
- 같은 언어의 디자인 수정에서는 본문을 원본 그대로 사용해. 문장을 다듬거나 줄이거나 바꾸지 마. 기능명, 화면 표시명, 조건, 순서, 참조 관계를 유지해.
- 원본에 목적과 작업 순서가 있으면 그대로 드러내어 따라 할 수 있게 해. 목적이 없으면 새 목적 문장을 작성하지 말고 검수 기록에 `[확인 필요]`로 적어.
- 목적별 새 페이지를 만들거나 장·절·조작 항목의 순서를 바꾸지 마. 원본에 적힌 목적과 순서 안에서 읽기 편하게 배치해.
- 장·절과 조작 항목의 논리적 순서는 원본을 따라. 절 안의 배치는 ‘개요 → 화면 설명〔설정·결과·참고 안내 → 이미지와 기존 캡션 → 번호 설명 텍스트〕→ 유의사항 → 원본에 있는 기타 영역’ 순서야. 기타 영역끼리의 순서는 원본을 유지하고 없는 영역은 만들지 마.
- 문장부호는 내용 기준 PDF를 보존해. 예외는 9절의 장·절 참조 위첨자, 8절의 항목 시작 글머리표, 4·5절의 장 번호, 6절의 경로 구분자야. 승인된 이 표기만 해당 절의 기준으로 적용하고 일반 문장의 마침표·괄호는 바꾸지 마.

#### 원문 추출과 띄어쓰기

- PDF 추출 결과를 원문과 동일하다고 가정하지 마. 추출한 글과 실제 PDF를 대조해.
- PyMuPDF를 사용할 때는 `TEXT_INHIBIT_SPACES`를 켠 결과를 우선 확인해. 이 옵션만으로 원래 띄어쓰기가 복원된다고 단정하지 말고, 기본 추출 결과와 PDF 화면도 함께 비교해.
- 원본의 줄바꿈이 단어 중간인지 문장 사이인지 확인해. 문법만으로 공백을 확정하지 말고, 코드·단위·숫자 앞뒤의 공백도 원본에서 확인해.
- 줄바꿈을 합치거나 공백을 복원한 위치는 변경 전·후와 근거를 목록으로 남겨 사람이 검토할 수 있게 해. 판단이 불가능한 곳은 `[확인 필요]`로 표시해.

#### 공통 매뉴얼 페이지

- 내용 기준 PDF에 ‘매뉴얼 읽는 법’ 페이지가 있으면 그대로 보존해. 없으면 읽는 법·목적별 안내 페이지를 새로 만들지 마.
- 본문 화면 설명의 설정·결과·참고 안내는 7절의 디자인으로 유지해. 이를 확장해 별도 공통 안내 페이지나 새 설명을 만들지 마.
- 유의사항 명칭은 ‘필수 확인’, ‘오해하기 쉬운 동작’, ‘참고’로 통일해. ‘위험·주의·참고’로 바꾸지 마. 분류의 실제 의미와 본문 내용은 원본에서 확인해.
- 분류의 의미가 원본에 없으면 추측하지 말고 `[확인 필요]`로 남겨. 본문 범례에 설명이 생략된 경우에도 공통 페이지용 문구를 본문에 자동으로 추가하지 마.

#### 다국어 번역 시 원문 보존

- 영어·일본어·독일어로 번역할 때도 원문과 사용자가 승인한 자료에 없는 내용을 지어내지 마. 기능, 조작 단계, 버튼명, 조건, 예외, 경고, 수치, 예시를 추측해서 추가하지 마.
- 문화 차이는 문체와 읽기 편한 배치를 조정하는 데만 반영해. 문화적 관습이나 논문을 근거로 제품 동작, 필수 조건, 금지 사항을 추가·삭제하거나 경고의 강도를 바꾸지 마.
- 자연스러운 번역을 위한 문장 분리와 어순 조정은 가능하지만, 원문의 의미·조건·정보량은 유지해. 생략된 내용을 추측해 채우지 마.
- 불명확하거나 서로 모순되는 내용, 실제 화면과 일치하는지 확인할 수 없는 번역은 `[확인 필요]`로 표시하고 확인할 항목을 따로 정리해. 추측한 답을 확정된 내용처럼 넣지 마.
- 버튼·탭·메뉴·필드 라벨·경로·안내문은 확인된 해당 언어의 실제 화면 표기를 따라. 확인할 자료가 없으면 원문 표기를 남기지 말고 용어집 기준으로 번역해 넣고, 그 항목만 검수 기록의 `[확인 필요]` 목록에 적어. 본문에는 `[확인 필요]`나 원문을 적지 마.
- 코드 식별자(`fieldKey`, `field_m6ov`, `eq`, `NORMAL`, `{height}` 등)와 영문·숫자로 된 입력값은 번역하거나 현지 형식으로 바꾸지 마. 한국어로 된 입력값·예시값·선택지(예: `혈당`, `정상 · 낮음 · 높음`, `5.2이하`)는 화면 문구와 같은 방식으로 번역해. 본문과 캡처 이미지에서 같은 값은 같은 번역어로 써.
- 번역 후 원문과 문단별로 대조해 누락·추가·의미 변경을 확인해. 수치, 단위, 부정 표현, 필수 조건, 참조 번호는 별도로 대조해.

#### 번역본에 원문 언어 노출 금지

- 영어·일본어·독일어 매뉴얼에는 한국어가 한 글자도 보이면 안 돼. 본문, 경로, 탭·카드 제목, 표, 캡션, 목차, 간지, 헤더·푸터, 책갈피, PDF 메타데이터, **화면 이미지 안의 글자**까지 모두 해당 언어로 바꿔. 일본어판의 한자·가나는 허용하지만 한글은 허용하지 마.
- 디자인 고정 문구(개요·화면 설명·유의사항 탭, 설정·결과·참고 안내, 필수 확인·오해하기 쉬운 동작·참고 카드 제목과 보조 문구, 경로 라벨, 목차·간지·푸터 문구)도 언어별 용어집의 번역어로 통일해. 한 문서 안에서 같은 문구를 다르게 번역하지 마.
- `CRF 관리 (CRF Management)`, `[+ 필드 추가] (Add field)`, `혈당 (blood glucose)`처럼 원문 옆에 번역을 괄호로 붙이는 병기를 쓰지 마. 번역어만 써. 예: `CRF Management`, `[+ Add field]`, `Blood glucose`.
- 화면 표기의 번역어는 언어별 용어집 하나로 관리해(원문 · 번역어 · 확인 여부 · 쓰인 곳). 본문·경로·표·캡처 이미지에 같은 용어집을 적용해, 본문에서 `[+ Add test item]`이라고 쓴 버튼은 캡처 안에서도 같은 글자로 보이게 해.
- 출력 PDF에서 한글(U+AC00–U+D7A3, U+1100–U+11FF, U+3130–U+318F, U+A960–U+A97F, U+D7B0–U+D7FF) 글자 수를 세어 **0이어야** 해. 책갈피·메타데이터도 같이 검사해. 화면 이미지는 OCR(macOS Vision 등 한국어 인식 가능 도구)로 한글이 남았는지 검사해. 하나라도 남으면 결과물로 넘기지 말고 고쳐.
- 이미지 OCR 검사는 한국어 우선 모드로 돌리고, 한글이 잡힌 자리의 픽셀을 한국어판 이미지와 비교해. 픽셀이 그대로면 실제로 남은 한국어(실패), 바뀌었으면 새로 쓴 번역 글자(특히 일본어)나 아이콘을 잘못 읽은 것이야. 아이콘·기호 오인식(예: 종이비행기→`시`, 휴지통→`핑`, `≤`→`드`)은 눈으로 확인한 뒤 분권별 오탐 목록(이미지·글자·이유)에 올려야만 검사에서 뺄 수 있어. 일본어 우선 모드로 검사하면 남은 한국어를 일본어 잡음으로 읽어 놓치니 쓰지 마.
- 교체 대상을 찾는 1차 OCR은 원본 캡처와 2배 확대본에서 각각 돌려 합쳐. 작은 회색 글자·어두운 바탕 흰 글자는 한쪽 해상도에서만 잡히는 경우가 있어.
- 한글 글꼴 대체나 한글 줄바꿈 처리 같은 ‘번역본에 한글이 남는 것을 전제로 한’ 처리는 만들지 마. 그런 처리가 필요해졌다면 한글이 남았다는 뜻이니 원인을 고쳐.

#### 언어별 매뉴얼 구성 방향

- 언어별 문체와 문장 규칙은 `template/TRANSLATION_BRIEF.md`의 「Style per language」 한 곳에서만 관리한다(hy0909 결정, 2026-11-09). 이 문서에는 다시 적지 않는다. 두 곳에 두면 어긋난다.
- 근거 자료(표준·논문·협회 지침 21건의 확인 수준과 쓸 수 있는 범위)는 `prompt/언어별_구성방향_근거.md`에 있다. 예전 표가 인용한 Doherty 2012·Roturier 2006은 기계번역 출력을 읽는 실험이고 Miehle 2016은 대화 시스템 연구라, 인쇄 매뉴얼 문체의 직접 근거가 아니어서 보조로 낮추거나 뺐다.
- 어느 언어든 위 「다국어 번역 시 원문 보존」 규칙이 먼저다. 항목 수·순서·경고 강도·제품 동작은 문체 규칙으로 바꾸지 않는다.

### 2. 문서 공통 디자인

- A4 세로형으로 제작해. 표지·목차·간지·본문을 구분해.
- 좌우 기본 여백은 약 14.8mm로 맞춰. 기준 PDF가 있으면 해당 여백과 배치를 그대로 따라.
- 흰 바탕과 어두운 본문을 기본으로 쓰고, 컬러는 번호·참조·주의사항 등 뜻이 있는 지점에 집중해.
- 본문용 한글 글꼴은 Pretendard를 사용해. Regular 400, Medium 500, Bold 700을 구분해.
- 표지·목차·간지·본문·표·캡션·키값·코드 강조까지 모든 글자를 Pretendard로 출력해. 코드 강조에도 Consolas 같은 고정폭 글꼴을 따로 지정하지 말고 Pretendard를 상속해. 큰 번호의 800 굵기도 Pretendard ExtraBold를 써.
- 제목, 본문, 보조 설명, 참조 번호의 위계를 크기·굵기·색으로 구분해.
- 카드·경로·이미지 프레임의 모서리는 기본 8px로 통일해. 본문 소제목 탭은 위쪽 모서리만 둥글게 처리해.
- 한글은 10pt 초과일 때 자간 -3%를 적용해. 예외: 유의사항 카드 제목·본문, 상자 글, 범례, 표, 캡션, 경로, 푸터, 목차·간지 쪽번호, 목차 장 번호와 간지 목록 번호는 자간 0이고, 목차 항목 번호와 헤더 절 번호는 -1%다(2-2절 표). 10pt 이하는 기본 자간을 유지해. 영어는 크기와 관계없이 -1%를 적용해.
- 자간 때문에 PDF 선택 순서나 띄어쓰기가 깨지면 글자 복사 품질을 먼저 보장해. 텍스트를 이미지나 외곽선으로 바꿔 해결하지 마.
- 수치는 CSS px 기준이야. PDF 제작 도구에서 pt를 쓰면 1px = 0.75pt로 환산해.
- 글자 크기와 줄 높이는 소수점 없는 짝수 px로만 쓴다(hy0909 결정, 2026-11-09). 예전 82.5·28.5·33.5·31.5·15.5·14.5·13.5·12.5·10.5px은 82·28·34·32·16·14·14·12·10px로, 17·15·13·9px은 18·16·14·10px로, 줄 높이 1.5·1.52·1.55배는 22px, 1.45배는 18px(캡션)·20px(표), 19.33px은 20px, 99.6px/1.2는 100px/120px, 간지 제목 1.25배는 66px으로 바꿨다. 표·캡션·푸터는 12px이고, 그보다 작은 글자는 참조 번호(footnote 10px)와 안내 원 숫자(10px)뿐이다.

#### 가변 높이 법칙 (모든 영역 공통)

- 글이 들어가는 영역의 높이는 고정하지 마. 글이 길어져 줄이 늘면 **그 영역의 높이가 늘어난 줄만큼 커지고, 아래 영역과의 간격은 그대로 유지한 채 아래 내용 전체가 늘어난 높이만큼 내려가야 해.**
- 캡처 캡션은 끝 줄에 한 낱말만 남지 않게 `text-wrap: pretty`로 줄을 나눈다(2026-11-09, 검사패널 3.3 캡션 「펼쳐진다」).
- 넓은 표의 고정 폭 61 · 164 · 82px은 「탭 / 항목 / 무엇을 정하는가 / 본문」 요약표에만 쓴다. 첫 머리가 「탭」이 아닌 비교표는 `class="wide cmp"`로 표시하고 내용에 맞춰 폭을 나눈다(2026-11-09, 검사패널 7.1 「검사 패널 (LAB)」 열이 82px에 갇혀 한두 글자씩 끊김).
- 적용 대상: 본문 헤더(절 제목), 경로, 소제목 탭, 설정·결과·참고 안내, 이미지 캡션, 번호 설명, 유의사항 카드, 표 셀·행, 목차 항목, 간지 큰 제목과 목록, 표지 제목·보조 설명, 푸터. 새로 생기는 영역도 같은 법칙을 따라.
- 글자 크기는 줄이지 마. 예외는 표지 제목 하나로, 한 낱말이 폭을 넘으면 `paginate.js`가 48px까지 줄인다.
- 늘어날 때 영역 안쪽 여백(위·아래 padding)은 한 줄일 때와 같게 유지해. 예: 본문 헤더는 한 줄 98px(제목 위 여백 + 한 줄 + 아래 여백)이고, 두 줄이면 98px + 제목 한 줄 높이만큼 커져. 제목 마지막 줄과 헤더 아래끝 사이 여백은 한 줄일 때와 같아.
- 아래 영역을 `top:120px`처럼 절대 좌표로 고정하지 마. 위 영역의 실제 아래끝에서 간격을 더해 위치를 정하거나, 일반 흐름(normal flow)에 두어 자동으로 밀리게 해.
- 글자 크기·자간·줄 간격을 줄여 한 줄에 맞추지 마. 넘치는 글은 줄바꿈과 높이 증가로 해결해.
- 영역이 늘어 쪽 아래로 넘치면 11절의 쪽 나눔 규칙에 따라 다음 쪽으로 넘겨. 늘어난 영역이 다른 영역과 겹치거나 잘리면 안 돼.
- 검수: 가장 긴 번역문이 들어간 쪽을 포함해 렌더링하고, 영역 사이 간격이 기준값과 같은지, 겹침·잘림이 없는지 측정해 기록해.

#### 제목 끝 줄 1~3글자 보정 (모든 언어·모든 제목 공통)

- 여러 줄 제목의 마지막 줄에 1~3글자만 떨어지면 안 돼(hy0909 결정, 2026-10-21). 예: 일본어 `検証タブ — 保存前の値チェッ` / `ク`. 이럴 때는 글자를 줄이지 말고, 문맥상 끊어도 되는 단어·구절 경계에서 줄을 다시 바꿔 `検証タブ —` / `保存前の値チェック`처럼 만들어.
- 적용 대상: 표지 제목·보조 설명, 간지 큰 제목과 목록 제목, 본문 헤더(절 제목), 목차 장 제목과 항목. 줄 수는 늘리지 마.
- HTML 처리 순서(쪽 나눔 스크립트 안에서 제목이 실제 폭에 놓인 직후, 높이를 재기 전에 실행):
  1. 마지막 줄의 글자 수(공백 제외)를 재서 1~3이면 `text-wrap:balance`로 줄 길이를 고르게 나눠. 일본어는 `word-break:auto-phrase`(문절 단위), 한국어는 `word-break:keep-all`(어절 단위), 영어·독일어는 띄어쓰기 단위야.
  2. 그래도 짧으면(가타카나 합성어처럼 한 문절이 긴 경우) `Intl.Segmenter`로 낱말 경계를 찾아 그 자리에만 `<wbr>`를 넣고 `keep-all`로 다시 나눠. 예: `ファイルアップロード` / `フィールドとは`. `<wbr>`는 복사한 글에 아무 글자도 남기지 않아.
  3. 그래도 안 되면 제목 폭을 2%씩 좁혀 앞줄 끝 낱말을 넘겨. 줄 수가 늘면 되돌리고 검수 기록에 적어.
- 바꾼 제목에는 `data-balanced="3→9"`처럼 전후 끝 줄 글자 수를 남겨. 검수 때 끝 줄이 1~3글자인 제목이 0개인지 확인해.

#### 원·아이콘 + 제목 + 설명 한 줄 구성: 위 정렬·기준선 고정 규칙 (모든 템플릿 공통)

- 대상: 화면 설명 안내(원 + `설정`/`결과`/`참고` + 설명), 그 밖에 원·아이콘 다음에 굵은 제목과 설명이 한 줄로 이어지는 모든 구성(번호 설명 항목, 유의사항 카드 제목 + 보조 문구 등).
- **세로 정렬은 위 정렬(top)로 고정해.** 설명이 두 줄 이상으로 늘어나도 원·아이콘과 제목은 **설명의 첫 줄**에 붙어 있어야 해. 여러 줄 전체의 세로 가운데(`align-items:center`)로 내려가면 안 돼.
- **제목과 설명은 같은 수평선(첫 줄 기준선)에 놓아.** 제목과 설명을 같은 글자 크기·같은 줄 높이로 두고 둘 다 위 정렬하면 첫 줄 기준선이 같아져. 글자 크기가 다르면(예: 카드 제목 14px + 보조 문구 12px) `align-items:baseline`으로 기준선을 맞춰.
- 원·아이콘은 첫 줄 **글자 높이의 중심**(기준선 − 0.358em)에 원 중심이 오게 둬. 예: 안내 14px·줄 높이 20px·원 14px이면 원 `margin-top: 3px`. 줄 상자 중심((줄 높이 − 원)/2)으로 맞추면 0.5px 정도 아래로 처져.
- 설명이 길면 설명 칸 안에서만 줄바꿈되고, 둘째 줄부터는 설명 첫 글자 시작선에 맞춰(원·제목 아래로 돌아가지 않게).
- 가로 배치(안내 3칸 사이 간격·양끝 정렬)는 7절 기존 규칙을 따라. 칸이 좁아 설명이 줄바꿈되는 것은 가변 높이 법칙(2절)대로 높이만 늘어나.
- **검수:** 가장 긴 번역문(보통 독일어)이 들어간 쪽에서 ① 제목과 설명 첫 줄 기준선 차이 0px, ② 원 중심 − 첫 줄 글자 높이 중심 ≤ 0.3px, ③ 원·제목이 설명 첫 줄보다 아래에 있지 않은지를 화면과 PDF에서 재고 기록해.

#### 원형 번호 숫자: 정중앙 고정 규칙 (모든 원·모든 분권·모든 언어 공통)

- 대상은 모든 원형 번호야: 화면 설명 안내(설정·결과·참고) 14px, 번호 설명 23px(결과 원 22px), 화면 이미지 위 번호 22px. 새로 만드는 원형 번호도 같은 규칙을 따라.
- **숫자는 원의 가로·세로 정중앙에 와야 해.** 기준은 글자 상자가 아니라 숫자의 **실제 잉크(획) 경계**의 중심이야. Pretendard 숫자는 글자 상자 안에서 아래로 처지고 `1`은 획이 왼쪽으로 치우쳐, 상자를 가운데 두면 눈에 띄게 어긋나.
- **구현 방법(고정):** **원과 숫자를 같은 인라인 SVG 하나에 그려**(`<circle>` + `<text>`). CSS 배경으로 원을 그리고 숫자만 SVG로 그리면 화면 렌더링에서 둘이 서로 다르게 픽셀에 맞춰져 어긋나. 숫자 `<text>`는 `text-anchor="middle"`(텍스트 가운데 정렬), `text-rendering="geometricPrecision"`, `transform="rotate(0.2 cx cy)"`(눈에 보이지 않는 0.2° 회전: 화면의 기준선 픽셀 맞춤을 줄임)로 두고, 좌표는 빌드할 때 **폰트 파일의 글리프 값**으로 계산해. 테두리 원·흰 테두리 화면 번호도 `<circle>`의 선·겹친 원으로 그려.
  - 가로: `x = 원 지름/2 − (잉크 중심 − 진행폭 중심)`. Pretendard Bold 실측 `1`은 잉크 중심이 진행폭 중심보다 −0.0308em, 나머지 숫자는 ±0.007em 이내.
  - 세로: `y(기준선) = 원 지름/2 + 잉크 세로 중심`. Pretendard Bold 숫자 잉크 세로 중심은 기준선 위 0.3535em(`2`는 0.3584em, `5`는 0.3486em).
  - 여러 자리 숫자는 첫 글자 잉크 왼쪽 끝 ~ 마지막 글자 잉크 오른쪽 끝을 하나의 잉크 상자로 보고 같은 식을 적용해.
- **쓰지 말 것:** HTML 글자 + flex 가운데 정렬만으로 맞추기, `line-height`·`text-box-trim`·canvas `fontBoundingBox`로 맞추기, 화면·인쇄 반올림을 가정한 JS 보정. HTML 글자의 기준선은 화면(배율 1·2)과 PDF 인쇄에서 서로 다르게 정수 px로 반올림돼 한쪽을 맞추면 다른 쪽이 틀어져. SVG 글자는 반올림되지 않아 화면과 PDF가 같아.
- `position`·`transform`으로 숫자를 옮기지 마. PDF 텍스트 순서가 바뀌어 번호가 본문보다 늦게 복사돼. SVG 숫자는 일반 흐름 안에 두고, 실제 텍스트로 선택·복사되는지 확인해.
- 글꼴을 바꾸면(예: 다른 언어 글꼴) 그 글꼴 파일에서 숫자 글리프 값을 다시 읽어 계산해. 값을 추측하거나 다른 글꼴 값을 재사용하지 마.
- 숫자 위치를 화면 배율별 CSS(@media resolution)로 따로 보정하지 마. 위치마다 값이 달라 일정한 보정이 맞지 않고, 다른 배율에서 오히려 어긋나.
- **검수(필수, 눈으로 확인. `check_circles_render.py`는 아직 저장소에 없다 [확인 필요]):** 원 종류별로 ① PDF 12배 래스터, ② 화면 배율 2, ③ 화면 고배율(8배), ④ 화면 배율 1에서 **실제로 칠해진 원의 중심**과 숫자 잉크 중심의 차이를 픽셀로 재. 기준은 ①~③ **가로·세로 0.3px 이하**, ④는 1픽셀=1CSS px라 작은 숫자(10~12px)의 기준선 픽셀 맞춤이 남는 Chrome 렌더링 한계가 있어 **0.4px 이하**(실측 최대 0.36px). 측정법 자체의 오차(고배율 캡처를 평균 축소해 같은 방법으로 잰 값)도 함께 출력해. 결과를 언어 × 원 종류 표로 검수 기록에 남기고, 구현한 쪽과 다른 사람(서브에이전트)이 한 번 더 재.
- 키값·코드 강조(글자색 `#202F86`, 배경 card-bg-blue `#EEF1FB`, 유의사항 카드 안에서는 8절의 카드 계열 배경)는 배경을 위아래로만 넓혀(`padding:2px 0`, 줄이 바뀌면 `box-decoration-break:clone`). `box-shadow:0 0 0 2px`처럼 좌우로 넓히면 배경이 앞뒤 글자 위에 그려져 `키(fieldKey)`의 괄호가 가려져. 괄호 안에 강조가 들어가도 여는 괄호와 닫는 괄호가 모두 온전히 보여야 해. 좌우 padding·margin은 복사할 때 공백이 생길 수 있으니 쓰지 마.
- 안내 아래 이미지까지 간격은 8px로 둬.
- 이미지 프레임은 `#F6F7F9`, 모서리 8px로 표시하고 테두리와 그림자는 빼.
- 화면 이미지 아래부터 번호 설명을 배치해. 설명 번호가 이미지 영역으로 침범하지 않게 해.
- 설명 번호 원형은 23×23px, 번호와 텍스트 간격은 10px로 표시해. 두 번째 줄부터도 첫 문장의 텍스트 시작선에 맞춰.
- 설정 번호는 파랑 `#3C55EB`로 칠한 원과 흰 숫자, 결과 번호는 흰 배경과 파란 테두리·숫자로 표시해. 참고 번호는 회색 `#64748B`로 칠한 원을 사용해. 원본 PDF의 배지가 빨강·파랑이어도 이 색을 그대로 쓰고 다시 묻지 마(hy0909 결정, 2026-10-30. 프로젝트 CLAUDE.md도 같은 값).
- 이미지 아래 참고 설명(캡션)은 gray-60 `#475569`로 표시해. 캡션 안의 굵은 글자는 본문 굵은 글자와 같은 gray-100 `#111B2B`야.
- 설정 원의 아래 중앙에서 결과 원의 왼쪽 중앙까지 연결해. 결과 원의 왼쪽은 설정 설명의 텍스트 시작선에 맞춰.
- 연결선은 1px, 회색 `#94A3B8`, 짧고 촘촘한 점선으로 표시해. SVG 기준 dash 2, gap 2를 사용해.
- 항목 구분선은 원형 번호가 아닌 텍스트 시작선에서 시작해. 색은 아주 연한 `#F1F5F9`로 표시해.
- 한 줄 설명의 첫 줄 중심과 원형 중심을 맞추고, 여러 줄 설명도 같은 첫 줄 기준을 유지해.

### 9. 참조 번호

- 장·절 참조는 최신 PDF의 작은 위첨자 형태를 유지해. 새 원본에 `(2.1)`, `(3.2 · 3.7)`, `(3장)`, `(6장)`처럼 표기돼 있으면 참조용 괄호만 제거하고 같은 위첨자 형태를 적용해. 숫자·가운뎃점·‘장’ 글자는 보존해. 단 번역본에서는 ‘장’을 해당 언어 표기(EN `Ch.`, JA `章`, DE `Kap.`)로 바꿔. 이미 위첨자인 참조를 다시 괄호로 감싸거나 위치를 누적 이동하지 마.
- 참조는 10px, Bold 700으로 표시해. HTML은 `position:static; top:auto; vertical-align:3px; line-height:0`로 둬. v105의 2px보다 1px 위로 올린 값이고(hy0909 결정, 2026-10-21), 표 칸 안의 참조(`td .ref`)도 3px로 맞춰. 일반 문장 흐름 안에서 본문보다 살짝 높게 두고 PDF 기준 위치와 복사 순서를 함께 확인해.
- 일반 본문 안에서는 primary `#3C55EB`를 사용해.
- 유의사항 카드 안에서는 카드 계열의 채도를 낮춘 색을 사용해. 필수 확인은 `#A15E61`, 오해하기 쉬운 동작은 `#927341`, 참고는 `#64748B`로 표시해.
- 단순한 괄호 설명이나 정상범위 수치를 참조 번호로 오인하지 마. 실제로 다른 절이나 장을 가리키는 표기만 바꿔.
- 참조 숫자는 새 문서의 실제 절 번호와 일치해야 해. 쪽 나눔이나 내용 이동 후에도 확인해.

### 10. 표와 푸터

- 표의 항목명 아래 진한 선은 빼. 첫 본문 행의 윗선이 겹쳐 남지 않게 해. 일반 행 구분선은 연하게 유지해.
- 표의 모든 본문 셀과 본문 참조 번호는 위쪽 정렬해. ‘3.6’ 같은 번호만 아래에 붙이지 마.
- 첫 열의 항목명은 파란색 대신 진회색 `#475569`로 표시해.
- 첫 열(항목명 열) 너비는 글에 맞춰 조절해(hy0909 결정, 2026-10-21). 첫 열이 좁아 낱말이 중간에서 잘리거나(`YYYY-MM-DD`가 `YYYY-MM-` / `DD`로 나뉘는 경우 포함) 3줄 이상으로 길어지면, 첫 열을 4px씩 넓혀 보고 표 전체 높이가 가장 낮아지는 너비를 골라. 글자가 적어 2줄 안에 낱말이 잘리지 않고 들어가면 손대지 마.
  - 오른쪽 칸에 여유가 있으면 첫 열을 넓혀도 돼. 반대로 오른쪽 칸이 많거나 빽빽해서 넓혔을 때 표 전체 높이가 처음보다 늘어나면 넓히지 마.
  - 첫 열은 표 너비의 30%를 넘기지 마. 극단적으로 넓히지 않기 위한 상한이야.
  - 넓힌 뒤 모든 낱말이 칸 안에 들어가면 첫 열의 자동 하이픈을 꺼(`hyphens:manual`). 들어가는 낱말을 줄 끝에서 억지로 쪼개지 않게 하려는 거야.
  - HTML에서는 쪽 나눔 전에 스크립트로 표마다 재서 첫 열 칸에 너비를 직접 적고, 넓힌 표에는 `data-c0w`로 너비를 남겨. 한국어판도 같은 규칙을 쓰지만 대부분 2줄 안에 들어가 그대로 남아.
  - 낱말 하나 떨어짐 막기(hy0909 결정, 2026-11-04 데이터내보내기 1.1 독일어 「Priorität / 1」): 첫 열 칸이 두 줄 이상인데 마지막 줄에 3글자 이하만 남으면 손본다. 잘린 낱말·3줄 이상과 같은 순서로, 첫 열을 4px씩 좁히거나(96px까지) 넓혀(표 너비의 30%까지) 본다.
  - 어느 너비든 두 조건을 지켜야 쓴다. ① 표 전체 높이가 처음보다 늘지 않는다. ② 어느 칸도(오른쪽 열 포함) 3줄이 되지 않는다(원래 3줄이던 칸은 그 줄 수까지). 첫 열을 넓혀 오른쪽 칸이 3줄로 늘어나는 건 고친 게 아니다.
  - 고르는 순서: 잘린 낱말 적음 → 떨어진 낱말 적음 → 첫 열 3줄 없음 → 표 높이 낮음 → 원래 너비에 가까움. 조건에 맞는 너비가 없으면 그대로 둔다.
  - 머리글 칸에는 `build.py`가 적은 % 너비가 있어 첫 열만 px로 바꾸면 무시된다. 첫 열을 바꿀 때 나머지 머리글 칸은 남은 너비를 원래 비율로 나눠 갖는다.
  - CRF 필드 매뉴얼 16권(검사패널·날짜·…·필드그룹)은 `build.py`로 다시 만들지 않고 HTML 안에 같은 스크립트를 품고 있다. 표·제목 규칙을 바꾸면 `python3 tools/update_paginate.py manuals <분권 ...>`로 HTML 안 스크립트를 템플릿 것으로 바꿔 64개 파일(16권 × 4언어)에도 같이 적용한다(2026-11-04).
- 본문 푸터 왼쪽에는 상위 장 제목, 오른쪽에는 ‘SMART EDC 로고 + 쪽번호’를 표시해.
- SMART EDC는 글자가 아니라 로고 이미지(`template/assets/img/smart-edc-logo-footer.png`, 푸터 글자색 `#94A3B8` 단색)야. 높이 14px, 쪽번호 줄의 세로 가운데에서 1px 위, 쪽번호와 사이 간격은 20px(hy0909 결정, 2026-10-30). 쪽번호는 12px Regular 400, `#94A3B8`.
- 푸터 위 가로선은 표시하지 마.

### 11. 이미지 품질과 쪽 나눔

- 화면 이미지는 원본 PDF나 제공된 파일 중 해상도가 가장 높은 자료를 사용해. 기존 시안 미리보기, 채팅 이미지, PDF 화면 캡처를 다시 사용하지 마.
- 최종 배치 크기를 기준으로 가로·세로의 필요 픽셀 수를 계산해. 목표는 최소 300dpi이며, 필요 픽셀 수는 `배치 길이(mm) ÷ 25.4 × 300`을 올림해 구해. DPI 속성만 바꾸지 말고 실제 픽셀 수를 확인해.
- 래스터 이미지의 최초 개선 시 원본 대비 최소 2배와 300dpi에 필요한 크기 중 큰 쪽으로 확대해. Lanczos 등 글자와 UI를 보존하는 고품질 보간을 사용하고, 선명도는 번짐·테두리 잔상이 생기지 않을 정도로 약하게 보정해.
- 이미 확대된 파일을 반복 확대하지 마. 다음 수정에서는 검수한 고해상도 파일을 유지하고, 이미지가 바뀌면 새 원본에서 다시 처리해.
- AI로 화면 글자·숫자·아이콘·선택값·버튼·배치·비율·색상을 생성하거나 바꾸지 마. 한글, 영문 필드명, 단위와 소수점을 확대 전후로 대조해. 예외는 아래 ‘번역본 화면 이미지’ 규칙의 글자 교체뿐이야.

#### 번역본 화면 이미지

- 번역본의 화면 이미지 안 글자도 매뉴얼 언어로 보여야 해. 한국어 화면 캡처를 그대로 넣지 마.
- 1순위: 같은 화면을 해당 언어 UI로 다시 캡처한 이미지를 써. 원본과 같은 상태(선택값·입력값·펼친 패널·스크롤 위치)와 같은 잘라내기 범위로 맞추고, 화면 위 번호 위치를 새 캡처 기준으로 다시 잡아.
- 2순위(현지화 캡처가 없을 때): 원본 캡처의 **한국어 글자 영역만** 번역어로 바꿔. 글자 위치·정렬·색·굵기·크기 단계는 원본을 따르고, 버튼·아이콘·선·입력칸·숫자·영문 식별자·배치·비율·색상은 그대로 둬. 생성형 AI로 화면 전체를 다시 그리지 말고, 글자 영역을 지우고 Pretendard 등 화면과 비슷한 글꼴로 다시 쓰는 결정적 편집으로 해.
- 번역어는 1절의 언어별 용어집과 같아야 해. 본문에서 가리키는 버튼·라벨·값이 캡처 안 글자와 한 글자도 다르면 안 돼.
- **2순위의 실제 도구(화면별 분권, 2026-10-30부터):** 순서대로 돌려. 모두 저장소 `template/`에 있고, `template/localize_all.sh <분권>`이 글자 교체부터 검사까지 한 번에 한다.
  1. `img_segments.py <분권>`: 한국어판 캡처(`<분권>/ko/img`, 2배 확대본)를 macOS Vision(`img_ocr.swift`, 1배와 2배 확대본을 합침)으로 읽어 한글 덩어리를 `img/loc/segments.json`에 적고 확인 시트(`img/loc/sheets/`)를 만든다.
  2. 검수(에이전트, `IMG_VERIFY_BRIEF.md`): 시트를 눈으로 보고 덩어리마다 실제 글·건너뜀·줄 이어짐·굵기·정렬·역할·잘림·아이콘 유무를 `img/loc/verified.json`에 적는다. 분권마다 한 명.
  3. `img_localize.py <분권> --dump` → `img/loc/strings_ko.json`(원문 묶음). 번역(에이전트, `IMG_TRANSLATION_BRIEF.md`)은 본문 번역·분권 용어집과 같은 말을 쓰고 `i18n/image_<lang>.json`에 `{원문: 번역어}`로 적는다. 같은 한국어가 역할에 따라 달라야 하면(「취소」 버튼 Cancel / 상태 Canceled) `원문@역할` 키를 더 둔다. 검사는 `check_img_tr.py <분권>`(빠짐·한글·용어집 불일치 0).
  4. `img_localize.py <분권> <lang>`: 한국어 글자 자리를 주변 바탕색으로 덮고 번역어를 Chrome canvas에 Pretendard(일본어 Pretendard JP)로 그린다. 크기는 한글 잉크 높이로 역산, 입력칸 테두리 같은 가로줄은 글자 줄에서 뺀다. 결과는 `img/<lang>/*.png`와 `replacements.json`(덩어리별 원문·번역어·위치·크기·굵기·정렬·축소율·플래그). `build.py`가 이 파일이 있으면 그 캡처를 쓰고 품질 기록(`quality-manifest.json`)에 합친다.
  5. `tools/widen_buttons.py` → `tools/extend_cut_buttons.py`(좁은 버튼·칩, 잘린 버튼) → `tools/place_markers.py`(번호 원이 번역 글자를 가리면 옮김) → `check_img_hangul.py <분권> <lang>`(한국어 우선 OCR, 한글이 잡힌 자리의 **글자 픽셀** 가운데 바뀐 비율이 15% 미만이면 남은 한국어, 번역 안 된 캡처 0) → `check_img_patch.py`(덮은 자리 얼룩·지워진 선 0) → `check.py`.
  5-1. `localize_all.sh`는 `LANGS` 환경변수로 언어를 골라 돌릴 수 있다(기본 en de ja). 18권을 다시 만들 때는 언어별로 세 개를 동시에 돌리면 10분 안에 끝난다(2026-11-03). 한국어판(`make_all.sh ko`)은 번역본 `img_localize.py`가 한국어 캡처를 읽는 동안 같은 파일을 다시 쓰면 「cannot identify image file」로 실패하니 번역본과 동시에 돌리지 않는다. Chrome 그리기가 멈추면(기계가 바쁠 때) `img_localize.py`가 60초 뒤 페이지를 다시 열어 3번까지 다시 그린다.
  6-1. 다 만든 뒤 언어마다 에이전트 한 명이 `img_review_sheets.py <lang> <폴더>`로 만든 시트(위 한국어·아래 번역본)를 **모두** 보고 `IMG_REVIEW_BRIEF.md`대로 문제를 적는다. 자동 검사가 못 잡는 모양 틀어짐(가장자리 얼룩·색 뒤집힘·정렬)은 이 눈 검토로만 잡힌다. 문제가 나오면 이미지 하나를 손보지 말고 도구 규칙을 고친 뒤 다시 만든다.
  6. 한글 검사에서 남은 자리는 `img_extra.py <분권>`이 2차 덩어리(`x_` id)로 더해 준다. 읽을 수 있는 것만 번역을 넣고, 모달 뒤에 흐려진 배경 글처럼 읽을 수 없는 것은 `skip`으로 두고 검수 기록에 남겨.
  6-1. 윈도우·오피스 같은 다른 프로그램 화면(엑셀 리본, 파일 탐색기 도구 모음)의 아이콘 속 글자(「가·가·간」, 「가나다」, 「ㄱ↓」 정렬 아이콘 등)는 아이콘이라 바꾸지 마. 한글 검사에서 걸려도 눈으로 확인한 뒤 오탐으로 두면 된다(hy0909 결정, 2026-11-13 데이터내보내기 s4_1_1).
  7. 캡처 파일 이름은 `s절_항_번호.png`에 더해 `s2_4b_1.png`처럼 항 번호 뒤에 글자가 붙은 것도 모두 대상이야. 캡처가 뒤에 추가되면 `img_segments.py <분권> --add`로 새 파일 덩어리만 덧붙이고 검수·번역을 이어서 해. `check_img_hangul.py`는 한국어판에 있는데 번역본에 없거나 픽셀이 같은 캡처를 `untranslated_images`로 잡아 실패시킨다(2026-10-30 로그인 2.4 두 번째 캡처가 한국어 그대로 나갔던 문제).
  7-1. 가로로 아주 긴 캡처(폭이 높이의 2.5배 넘고 1200px 넘는 표 한 줄 조각)는 macOS Vision OCR이 글자를 거의 못 읽는다(2026-11-03 Query 3.1 둘째 캡처 3130×196px에서 「대상」 둘만 읽고 「단일 필드·중요·상태·답변됨」을 놓쳤고, 사용자관리 표 머리글 「소속 기관·상태·최근 로그인·생성일」도 같은 이유로 한국어로 남았다). `img_ocr.swift`는 이런 이미지를 폭이 높이의 3배(최소 1200px)인 조각으로 200px씩 겹쳐 잘라 읽고, 자른 가장자리에 걸린 글자는 버린 뒤 합친다. 한글 검사도 같은 OCR을 쓰므로 함께 고쳐진다. 이미 검수한 권에 OCR 규칙이 바뀌면 `img_segments.py <분권> --reocr`로 긴 캡처만 다시 읽어, 기존 덩어리와 겹치지 않는 것만 `r_` id로 덧붙이고(기존 검수는 그대로) 새 덩어리만 검수·번역한다(2026-11-03 18권 107장에서 60개 추가, 그중 아이콘 오독 9개는 skip).
  8. `img_localize.py`가 검수 결과 위에 자동으로 덧씌우는 규칙(verified.json은 고치지 않고 실행 때마다 적용, 적용한 id를 출력):
     - 모달 화면이면 모달 바깥은 손대지 않는다. 판정은 `img_common.modal_bbox`: 이미지의 1%가 넘는 밝은(모든 채널 240 이상) 덩어리를 합친 상자가 이미지의 25% 이상이고 그 바깥 픽셀의 절반 이상이 무채색 중간 회색(밝기 60~215)이면 모달이고, 상자 밖 덩어리는 모두 `skip`이다. 상자 안이라도 바탕이 무채색 중간 회색(밝기 70~205, 채널 차 18 이하)이고 글자가 바탕보다 30 이상 어두우면 덮개 뒤 글자로 보고 `skip`이다. 잘려서 읽히지 않는 배경 글이고, 덮으면 덮개 색과 어긋나 모달 가장자리가 울퉁불퉁해진다(2026-10-30 워크스페이스 생성 모달·방문정의 CRF 폼 순서 모달 왼쪽). 한글 검사는 이런 자리를 `behind_overlay_kept`로 따로 세고 실패로 치지 않는다.
     - 덩어리의 바탕색·글자색은 글자 잉크 바로 옆 띠(위·아래·좌·우 2~6px) 네 곳의 대표색 가운데 서로 가장 많이 일치하는 색으로 다시 잰다. 작은 버튼·칩은 글자 상자가 칸을 거의 채워 crop 테두리로 잰 바탕색이 칸 바깥 흰색이 되고, 그러면 분홍 버튼이 연분홍 바탕·진분홍 글자로 뒤집힌다(2026-10-30 워크스페이스 「워크스페이스 삭제」). 글자를 덮는 색도 같은 방식으로 잰다.
     - 진한 칩(검은 바탕·흰 글자)은 OCR 덩어리가 칩 전체로 잡힌다. 상자 테두리가 대부분 잉크이고 상자 안 대표색이 바깥 바탕색과 40 이상 다르면 칩으로 보고, 칩 색을 바탕으로 삼아 칩 안에 갇힌 밝은 글자 덩어리의 상자만 글자 자리로 쓴다. 칩을 지우고 검은 글자를 쓰면 안 된다(2026-10-30 워크스페이스 「지금 할 차례」).
     - 글자 줄 범위(지우는 세로 범위)는 행 잉크가 5% 이상인 행만 세고, 입력칸 테두리 같은 가로줄로 끊긴 구간 가운데 잉크가 가장 많은 연속 구간만 쓴다. 잉크 1~2%인 행(상자 안에 걸친 세로 테두리)을 세면 자리표시 글의 줄 높이가 입력칸 전체가 돼 글자가 거대해진다(2026-10-30 AuditTrail 「예: age」). 좌우도 그 글자 줄 안에서 실제 잉크가 있는 열로 다시 좁히되, 줄 위아래 바깥까지 이어지는 세로줄(입력칸 왼쪽 테두리)은 글자로 세지 않는다. 넓히지는 않는다.
     - 덩어리 상자 안에 더 작은 다른 덩어리가 들어 있으면(OCR이 제목+설명+아이콘을 한 덩어리로 묶고 검수는 설명만 적은 경우) 그 덩어리의 줄은 경계로 취급해 빼고 잰다. 안 빼면 제목 줄까지 지우고 번역을 겹쳐 그린다(2026-11-03 배정 「배정 설정 / 설정 완료」).
     - 상자 위·아래 끝에 걸친 낮은 줄(가장 높은 줄의 0.4배 미만)은 이웃 덩어리 글자의 윗부분·아랫부분이 잘려 들어온 조각이니 글자 줄로 세지 마. 세면 줄 높이 중앙값이 작아져 조각 줄이 뽑히고, 진짜 한글 줄은 그대로 남은 채 번역이 조각 높이로 아주 작게 그려진다(2026-11-13 AE지정 「해제하면 이 양식은…」 두 줄 문단, 기관관리 「통합병원 제1기관」, 방문정의 워크스페이스 선택칸).
     - 한 구간 안에 빈 줄로 나뉜 글 줄이 둘 이상인데 검수 글이 한 줄이면, 검수 글의 예상 폭(한글 1em·라틴 0.55em·공백 0.3em)에 맞는 줄만 쓴다. 두 줄 높이로 그리면 글자가 거대해지고 다른 줄이 지워진다(2026-11-03 배정 「삼중 맹검」). 이런 덩어리는 검수에서 미리 나누는 게 맞다: 제목과 설명이 한 덩어리로 잡혔으면 `note`에 적고 설명 줄은 2차(`img_extra.py`)에서 따로 더한다.
     - 칩 판정에는 칩 색이 상자 네 변 모두에 절반 넘게 닿아야 한다는 조건이 붙는다. 「필수」 라벨 + 「3/3 완료」 배지처럼 흰 바탕 라벨과 색 배지가 한 덩어리로 잡힌 것은 칩이 아니고, 이런 덩어리는 검수·번역 데이터에서 둘로 나눈다(2026-11-03 Query 3.2).
     - 바탕색은 먼저 상자 안 최빈색을 본다. 상자의 절반 이상이 한 색이면 그 색이 바탕이다(테두리 있는 버튼은 상자가 버튼 안쪽 전체라 네 방향 띠가 테두리 색이 된다, 2026-10-30 플랫폼관리 「편집」). 아니면 네 방향 띠와 최빈색 가운데 서로 일치하는 색을 고른다. 칩 색도 중앙값이 아니라 최빈색이다(흰 글자 번짐이 섞이면 어긋난다, SAE통보 「테이블」 칩). 선택된 표 행처럼 글자 상자가 색 띠를 꽉 채우면 네 방향 띠가 모두 띠 바깥이라 서로 맞지 않는다(2026-10-30 데이터내보내기 파일 목록 선택 행). 덮는 색은 이렇게 바로잡은 바탕색 그대로 쓴다. 띠를 또 재면 바로 옆 강조 칸 색이 섞인다.
     - 잘리지 않은 버튼·칩은 오른쪽에 다른 요소(카드 테두리·선)가 있으면 그것을 넘어 넓히지 않는다(2026-10-30 로그인 3.1 「만료 29일」 칩). 넘게 되면 넓히지 말고 둔다. 넓히지 않기로 한 버튼은 지웠던 글자를 그대로 되돌려야 한다. 지운 뒤 건너뛰면 글자 없는 빈 버튼이 남는다(2026-11-03 독일어판 눈 검토에서 빈 버튼 41곳).
     - `icon_lead` 덩어리는 앞 낱말이 둘 이상 아이콘·테두리로 잡혔을 수 있다(2026-11-03 방문정의 1.1 「수정」: 버튼 왼쪽 선 + 연필 + 글자). 검수 글의 낱말 수만 남을 때까지 좁은(글자 높이 1.5배 미만) 앞 낱말을 뺀다.
     - 두께 3px 이하이고 상자 폭을 거의 다 채운(잉크 80% 이상) 가로줄 덩어리는 좁은 버튼의 위아래 테두리라 글자 줄에서 뺀다. 글자 오른쪽 바깥까지 이어지는지 보는 규칙은 버튼이 좁으면 안 걸린다(2026-11-03 같은 「수정」 버튼: 윗선 2px이 글자 줄에 들어가 글자가 거대해지고 윗선이 지워짐).
     - OCR이 첫 글자를 빼고 읽은 덩어리(「기간 (from)」→「간 (tro」)는 검수에서 `truncated`로 넘기지 말고 상자를 글자 끝까지 넓히고 글을 바로잡는다. 그대로 두면 「기Period (from)n)」처럼 원래 글자 조각이 남는다(2026-10-30 SAE통보 4.3). 테두리 아래 둥근 모서리의 몇 픽셀까지 글자로 잡으면 지우는 범위가 테두리를 덮어 입력칸 윗선이 사라진다(2026-10-30 플랫폼관리 코드 값 추가 모달 「라벨 *」·「정렬 순서」).
     - 왼쪽 정렬로 검수된 안내문·제목이라도 바로 위아래(글자 높이 3.5배 안) 가운데 정렬 글(제목·버튼·안내문)과 중심이 2px 안에서 같으면 가운데 정렬로 그린다. 두 줄로 줄바꿈될 때 왼쪽으로 쏠리는 문제를 막는다(2026-10-30 로그인 「비밀번호 재설정」 아래 안내문).
- 번역어가 원래 칸보다 길면 칸 안에서 줄바꿈하거나 글자 크기를 원본의 85%까지만 줄여. 그래도 안 들어가면 화면 구성을 바꾸지 말고 해당 이미지와 글자를 검수 기록에 `[확인 필요]`로 적어.
- 확대는 원본 캡처에서 한 번만 해(한국어판과 같은 배율). 글자 지우기와 새 글자 쓰기는 **확대된 최종 해상도 이미지에서** 해. 새 글자를 원본 해상도로 쓰고 확대하면 번역 글자만 흐려져. 원본·현지화본을 따로 보관하고, `quality-manifest.json`에 이미지별 교체 목록(원문 · 번역어 · 위치 · 글자 크기 · 굵기 · 정렬 · 축소율)과 방법(재캡처/글자 교체)을 기록해.
- 글자 영역은 OCR 줄 상자를 그대로 쓰지 말고, 픽셀의 빈 간격으로 실제 글자 덩어리를 나눠. OCR은 여러 라벨·체크박스·입력값을 한 줄로 묶기 때문이야. 덩어리 가장자리의 아이콘(체크박스·폴더·눈 등)은 떼어 내서 남기고, 떼어 낸 뒤 한글 글자 수가 줄면 글자를 잘못 뗀 것이니 되돌려. 입력칸 테두리·밑줄 조각이 덩어리에 걸리면 재OCR 글자 상자로 잘라 선을 지우지 마.
- 새 글자의 크기·기준선은 원래 한글 잉크 높이로 역산하고(Pretendard 한글 잉크 0.88em, 기준선 아래 0.09em), 색은 원래 글자 잉크 색, 굵기는 획 굵기 ÷ 글자 높이로 400·500·700을 판정해. 정렬은 주변 빈 공간으로 왼쪽·가운데(버튼·배지)·오른쪽을 판정해.
- 굵기는 원래 한국어 글자를 Pretendard 400·500·700으로 같은 높이에 실제로 그려 보고 잉크 밀도가 가장 가까운 것을 골라. 저해상도 캡처는 번짐 때문에 획 굵기 비율만으로는 구분되지 않아.
- 옆 여백 재기: 덩어리 바로 옆 2px는 원래 글자의 번짐이라 막힘으로 보지 마(`img_localize.py`는 오른쪽 2px·왼쪽 3px를 건너뛰고 잰다. 번짐 픽셀에서 바로 멈추면 자리 폭이 글자 폭 그대로가 되어 「설명」→「Description」처럼 번역어가 잘린다, 2026-10-30). 진한 글자·아이콘을 만나면 글자 높이의 0.9배(탭·버튼은 1.5배) 간격, 연한 테두리·칩 경계는 0.25배 여백만 둬. 가운데 정렬 덩어리는 양옆 빈 공간을 모두 쓰고 넘치는 쪽만큼 중심을 옮겨.
- 문단 재흘림: 같은 문단(같은 시작선·같은 색·가까운 줄 간격)의 줄들을 줄마다 따로 줄이면 85% 아래로 작아질 때는, 번역문 전체를 원래 줄 수 안에서 각 줄이 쓸 수 있는 폭에 단어 단위로 다시 흘려 넣어(라벨처럼 색이 다른 줄은 다른 문단).
- 오른쪽 한계: 번역문이 원래 덩어리보다 길어 오른쪽 빈 공간으로 늘어날 때, ① 캡처 이미지 오른쪽 끝에서 글자 높이의 0.6배 안쪽까지만 쓰고(원본 글자가 끝까지 닿아 있어도), ② 연회색 점선·패널 테두리(흰 배경과 RGB 합 차 30 이상)도 막힘으로 보고 간격을 둬. 크기는 반올림 후 실제 글자 폭으로 다시 재서 한계 안에 들 때까지 줄여(최저 45%). 끝이 잘린 번역문은 넘친 것과 같은 불합격이야.
- 정렬: 가운데 정렬은 짧은 덩어리(글자 높이의 6배 미만: 버튼·배지·탭)만 해. 긴 안내문은 좌우 여백이 좁아도 왼쪽 정렬이고, 새 글자가 원래 시작선보다 왼쪽 빈 공간 밖으로 나가면 안 돼.
- 옆에 다른 글자·요소가 있으면 그 사이 빈 공간을 다 쓰지 말고 글자 높이의 0.9배 이상 간격을 남겨(탭 라벨끼리 붙지 않게).
- 같은 문단의 여러 줄(왼쪽 시작선이 같고 줄 간격이 가까운 연속 줄)은 글자 크기·굵기·축소율을 하나로 맞춰. 줄마다 따로 재면 한 문단 안에서 크기가 들쭉날쭉해져.
- 줄 간격이 좁아 두 줄이 한 덩어리로 잡히면, 재OCR 줄 상자로 줄을 나눠 번역문을 같은 줄 수로 단어 단위 줄바꿈하고 각 줄 기준선에 써. 지우는 영역은 덩어리와 줄 상자를 합친 범위로 잡아 아래 줄이 덜 지워지지 않게 해. 줄 높이는 한글 줄 기준(영문 대문자 줄은 낮음).
- 축소 한계: 버튼·라벨은 65%, 긴 안내문(원래도 아주 작은 글자)은 55%까지. 85% 미만은 모두 `[확인 필요]`로 기록하고, 한국어판과 나란히 붙인 확인 시트를 만들어 눈으로 확인해. 칸이 좁은 곳은 번역 검수에서 같은 뜻의 더 짧은 표준 UI 표현으로 바꿔(예: JA `ルール`→`規則`, 개수 배지 `フィールド`→`項目`).

  - 대상: 원래 한글 덩어리가 글자 높이의 6배보다 짧고, 테두리나 바탕색으로 닫힌 칸 안에 있는 한 줄 글자. 칸의 적어도 한쪽은 글자와 테두리 사이에 다른 요소가 없어야 해.
  - 제외: 입력칸 예시 글(연한 회색 글자), 칸 왼쪽 끝에서 시작해 오른쪽이 빈 입력값, 양옆이 체크박스 같은 다른 요소로 막힌 선택지 라벨, 긴 안내문.

- 이미지 끝에서 잘린 버튼(hy0909 결정, 2026-10-21): 오른쪽 위 '발행'처럼 버튼이 이미지 오른쪽 끝에 걸려 잘렸거나, 끝에 붙어 넓힐 자리가 없어 글자가 85% 미만으로 줄었으면 이미지 오른쪽에 **빈 흰 여백**을 붙여. 도구는 `tools/extend_cut_buttons.py`이고 `widen_buttons.py` 다음에 돌려.
  - 버튼 글자는 아이콘 바로 뒤(왼쪽)에 두고 원래 한글 크기의 90%로 키워. 글자 오른쪽에는 아이콘 앞과 비슷한 여백(최소 글자 높이 0.9배)을 둬.
  - 버튼 오른쪽 끝은 왼쪽 모서리를 좌우로 뒤집어 붙여 마무리해. 모서리 폭은 버튼 윗선 바로 안쪽 행에서 실제로 잰 값만 써서 아이콘 조각이 같이 복사되지 않게 해.
  - 버튼 오른쪽 끝에서 글자 높이 1.2배(최소 24px) 이상 흰 여백을 남기고, 다른 행은 모두 흰색으로 채워. 잘린 다른 요소를 이어 그리지 마.
  - 이미지 폭이 바뀌면 HTML의 `imgbox` 비율과 화면 위 번호 위치(가로·세로 모두 폭 기준 %)를 새 폭에 맞춰 고쳐. `quality-manifest.json`에 `output_px`, `right_margin_added_px`, 덩어리별 `button_completed`를 남겨.
  - 앞 단계에서 이미 넓힌 버튼(`button_widened_px`)과 한 글자짜리 덩어리는 다시 처리하지 마. 이미 흰 여백을 붙인 이미지(한국어판과 크기가 다른 이미지)도 건너뛰어.
- 화면 위 번호 원 자리(hy0909 결정, 2026-10-30 · 2026-11-03): 번호 원은 캡처 기준 위치(%)로 찍히는데, 원이 글자·아이콘(×·체크·화살표)·테두리를 가리면 안 된다. 한국어판을 포함한 모든 언어에서 `tools/place_markers.py`로 원을 옮긴다(`make_all.sh`·`localize_all.sh`에 들어 있다. 언어마다 번역 글자 길이가 달라 원 위치는 언어마다 달라도 된다).
  - 가림 판정: 원 둘레 4px 여유까지 포함한 디스크 안에 잉크(48px 블록마다 최빈색을 바탕으로 보고 그와 40 넘게 다른 픽셀)가 2% 넘으면 가린 것이다. 버튼·칸의 평평한 안쪽은 잉크가 아니라, 원이 버튼의 빈 부분에 놓이는 건 된다.
  - 옮길 자리: 가리키던 요소 바로 옆. 같은 줄 오른쪽·왼쪽, 같은 열 아래·위로 2px씩 넓혀 가며 찾고, 네 방향 가운데 가장 가까운 빈자리를 쓴다. 위아래 거리는 2.5배로 쳐서 같은 줄을 우선한다(위아래로 옮기면 다른 줄·다른 상자 안으로 들어가 엉뚱한 것을 가리킨다). 최대 이동은 이미지 폭의 25%. 그 안에 빈자리가 없으면 그대로 두고 `stuck`으로 기록해 눈으로 본다.
  - 이미지 밖으로는 절대 나가지 않는다(원 전체가 이미지 안, 가장자리 2px 여유). 원래 자리가 이미지 끝에 걸쳐 있으면 안쪽으로 들어온다.
  - 세로로 비슷한 열(x 차가 이미지 폭의 4% 안)에 있는 원들은 같은 x에서 시작한다. 내용이 달라도 같은 선에 둔다. 묶음의 가장 오른쪽 x부터 왼쪽으로 2px씩 내려가며 모두 빈자리인 x를 찾고, 없으면 오른쪽으로도 4%까지 찾는다. 그래도 없으면 각자 자리에 둔다.
  - 기록은 `quality-manifest.json`의 `files[*].markers_moved`(원래 %·새 %·px·가리던 잉크 비율, 또는 `stuck`).
  - 원끼리 겹치지 않는다(hy0909 결정, 2026-11-09 Query 2.1 일본어 「1·①」「4·6」「5·5」가 포개짐). 원 중심 사이 거리는 지름 + 4px 이상이어야 한다. 4px은 화면(CSS) px 기준이다. 원본 이미지 px로 재면 2배 확대 캡처에서 틈이 1~2px만 남아 원이 붙어 보인다(hy0909 지시 반영, 2026-11-09 검사패널 3.4·3.8). 먼저 놓인 원이 자리를 차지하고 뒤 원이 피하며, 그래도 겹치면 뒤 원을, 안 되면 앞 원을 다른 원 전부를 피해 옮긴다(세 번까지). 열 맞춤도 다른 원과 겹치지 않는 x만 쓴다.
  - 빈자리는 네 방향 직선이 아니라 이미지 폭 25% 안 격자 전체에서 찾는다(위아래 거리는 2.5배로 침). 이미지 가장자리에 걸친 원은 먼저 안쪽으로 끌어들인 뒤 찾는다. 기록은 `markers_overlapped`(처음 겹친 쌍)·`markers_overlap_left`(남은 쌍)로 남기고, 남은 쌍이 있으면 실행 때 「겹침 남음」으로 출력한다.
  - CRF 필드 매뉴얼 16권도 `tools/place_markers.py manuals --only <분권>/<lang>`로 같은 규칙을 적용한다.
- 얼룩 검사(`template/check_img_patch.py <분권> <lang>`, 2026-10-30): 글자를 덮은 자리의 색이 주변 바탕과 어긋나거나(RGB 합 차 24 이상, 덩어리 12px 이상) 한국어판에서 덩어리 좌우 바깥까지 이어지던 가로선이 번역본에서 사라졌으면 잡는다. 결과는 `<lang>/img/patch_check.json`. 버튼·칩을 넓힌 자리처럼 한국어판에서도 같은 색이던 곳은 빼고 센다. 0이 아니면 눈으로 보고, 진짜 얼룩이면 위 규칙 가운데 어긋난 것을 고친 뒤 다시 만든다.
- 얼룩 검사에 둘을 더했다(2026-11-03). 「모달 바깥 변경」: 모달 화면에서 모달 상자 밖에 바뀐 픽셀이 30개 이상이면 실패. 「덮은 자리 글자 사라짐」: 한국어판에는 글자(잉크 3% 이상)가 있던 자리에 번역본은 같은 줄 양옆까지 넓혀 봐도 글자가 없으면(0.3% 이하) 덮기만 하고 안 쓴 것이라 실패(빈 버튼 41곳이 이걸로 잡힌다).
- 덩어리 경계 보정(모든 분권 공통): ① 줄 끝에 영문 꼬리(예: `… 는 후속 RF.`)가 남아 상자 밖에 있으면, 번역 글자가 그 꼬리와 겹치니 상자를 꼬리 끝까지 넓히고 꼬리를 번역문에 포함해(예전 도구 `fix_rf.py`는 저장소에 없다. 손으로 고친다). ② 한 글자짜리 접두 덩어리(예: placeholder `예: gender`의 `예`, 10px)는 번역어가 들어갈 수 없으니 뒤의 영문까지 한 덩어리로 묶어 통째로 교체해(예전 도구 `fix_eg.py`는 저장소에 없다. 손으로 고친다). ③ 상자가 체크박스·화살표 아이콘까지 덮으면 id는 그대로 두고 `seg_overrides`의 `box`로 글자 부분만 남겨. ④ OCR이 놓친 한국어는 `add`로 넣어. 어느 경우든 `segments.json`을 손으로 고치지 마(다시 돌리면 사라짐).
- 여러 분권을 나눠 번역한 뒤에는 언어마다 분권 간 통일을 한 번 더 해: 같은 한국어 원문이 분권마다 다르게 번역된 곳(예전 도구 `consistency.py`는 저장소에 없다. 용어집 `glossary/<lang>.json`으로 맞춘다)을 하나로 맞추고, 분권별 새 용어를 공통 용어집에 병합한 뒤 전 분권을 다시 출력·검사해. 다른 분권 번역을 재사용할 때는 문맥을 확인해(라디오 선택지 `예`=Yes/はい/Ja ↔ 예시 `예:`=e.g./例/z. B.).
- 같은 화면 문구는 이미지가 달라도 번역어가 같아야 해. 세그먼트가 바뀌어 새로 생긴 덩어리는 같은 한국어를 이미 번역한 덩어리의 번역을 그대로 쓰고, 없을 때만 새로 번역해.
- OCR 결과는 그대로 믿지 말고, 확대 crop을 사람이 보는 시트로 만들어 화면 글자와 대조해 교정한 뒤 번역해. 반복되는 오인식 예: 증→중, 출→존, `·`→`•`, `—`→`-`, `DataForm`→`Datarorm`.
- 교체한 뒤 OCR로 이미지 안 한글이 0인지 확인하고, 화면 위 번호가 바뀐 글자를 가리키는지 다시 맞춰.
- 원본의 벡터와 실제 텍스트는 그대로 유지해. 위의 최소 2배 확대 규칙을 적용하려고 벡터를 이미지로 바꾸지 마. 화면 위 번호는 원형 배경·테두리만 벡터 도형으로 만들고, 안쪽 숫자는 선택·복사 가능한 실제 텍스트로 유지해.
- 무손실 PNG 등으로 저장하고, PDF 출력 과정에서 저해상도로 축소되거나 손실 압축되지 않았는지 확인해. 비율, 표시 범위, 잘라내기 위치는 승인된 배치를 유지해.
- 원본과 개선본을 별도로 보관해. 파일별 원본·출력 픽셀 수, 배치 크기, 유효 dpi, 배율, 보정 방법, 검수 결과를 `quality-manifest.json`에 기록해. 기존 기록에 없는 항목은 실제 측정 후 채워.
- 기존 검사패널 작업의 기록 위치는 `smart-edc-source/img/hires300/quality-manifest.json`이야. ‘22개 이미지’, ‘가로 282~290px’ 같은 과거 수치는 다른 문서에 복사하지 말고 해당 문서에서 다시 측정해.
- 최종 PDF는 실제 크기와 200% 확대 상태에서 한글 획, 작은 숫자, 얇은 선, 경계와 잔상을 확인해. 보간 확대 후에도 읽기 어려우면 고해상도 원본이 필요한 파일을 검수 기록에 적어.
- 업스케일이 원본에 없는 세부 정보를 복구한다거나 어떤 확대율에서도 절대 깨지지 않는다고 표현하지 마.
- 화면 안의 원형 번호도 정원으로 표시해. 가로·세로 크기를 같게 하고 화면 비율 때문에 찌그러지지 않게 해.
- 화면 이미지 위 번호 규격(고정): 지름 22px, 흰 테두리 2px, 숫자 Pretendard Bold **12px**(설명 번호와 같은 크기, hy0909 결정 2026-11-09). 원에만 흰 테두리 바깥으로 연한 회색 그림자를 살짝 줘: `box-shadow: 0 0 0 0.5px rgba(100,116,139,.25), 0 1px 3px rgba(100,116,139,.35)`(결과 원은 안쪽 파란 테두리 `inset 0 0 0 1.5px #3C55EB` 뒤에 이어 붙임). 숫자에는 그림자를 주지 말고, 잘리거나 한쪽으로 길게 늘어지는 그림자도 쓰지 마. 화면 설명 안내·번호 설명 원에는 그림자를 주지 마.
- 표의 좁은 열(영어·독일어): 낱말을 하이픈 없이 중간에서 끊지 마. 표 칸은 `hyphens:auto`(html lang 지정)로 사전식 하이픈을 쓰고, 첫 열은 최소 96px로 두고, 그래도 잘리면 10절의 첫 열 너비 규칙으로 넓혀.

#### 쪽 나눔: 빈 공간 채우기 우선 규칙 (모든 템플릿 공통)

- **쪽을 비워 두지 마.** 절이 다음 쪽으로 이어지는데 앞 쪽 본문 영역이 크게 비면 안 돼. 이미지 설명이 다음 쪽으로 넘어가더라도 먼저 앞 쪽의 빈 공간을 채워.
- 넘칠 때 처리 순서(고정):
  1. 화면 설명 묶음(탭 + 안내 + 이미지 + 첫 설명)이 조금 모자라면 캡처 표시 크기를 최대 85%까지 줄여 같은 쪽에 둬.
  2. 그래도 안 들어가면 **이미지 뒤 설명만 다음 쪽으로 넘기고**, 탭 + 안내 + 이미지는 이 쪽에 둬(필요하면 캡처 최대 75%). 설명은 다음 쪽 맨 위에서 이어져.
  3. 탭 + 안내 + 이미지조차 안 들어가면 그 묶음을 원래 크기로 다음 쪽에 넘겨.
  4. 유의사항 카드는 통째로 넘기지 말고 항목(•) 단위로 나눠, 들어가는 항목까지 이 쪽에 두고 나머지는 다음 쪽에 같은 카드 제목을 다시 붙여 이어 써. ‘계속’·‘이어서’ 같은 말은 붙이지 마. 항목이 하나뿐인 카드는 나누지 마.
  5. 표는 행 단위로 나누고 다음 쪽에 머리행을 반복해.
- 묶음에서 떼면 안 되는 것: 소제목 탭은 다음 블록과, 안내는 이미지와 같은 쪽에 둬(탭이나 안내만 쪽 끝에 남기지 마). 설정 항목과 그 결과(점선으로 이어진 묶음)는 한 블록으로 다뤄.
- 캡처 축소는 표시 크기만 줄이는 것이라 유효 dpi는 올라가. 75% 아래로 줄이지 마.
- 절의 마지막 쪽은 짧아도 돼(다음 절은 새 쪽에서 시작).
- **검수(필수, 자동):** 같은 절이 다음 쪽으로 이어지는 쪽은 본문 영역의 **60% 이상**이 차 있어야 해. 쪽별 채움 비율과 최솟값을 검사 결과에 남기고, 60% 미만이 있으면 실패로 보고 고쳐.
- 설정과 이어지는 결과는 가능하면 같은 페이지에 묶어. 소제목만 페이지 끝에 남기지 마.
- 억지로 맞추려고 글자를 작게 줄이거나 캡처를 읽기 어려울 정도로 축소하지 마.

### 12. 선택·복사와 최종 확인

- 표지·제목·본문·본문 설명 번호와 화면 위 위치 표시 숫자는 모두 선택·복사 가능한 실제 글자로 만들어. 번호를 이미지나 글자 외곽선으로 바꾸지 마. 원형 배경·테두리는 벡터 도형으로 유지해. 화면 캡처에 원래 포함된 서비스 글자 전체를 새로 본문 텍스트로 만드는 작업까지 요구하는 것은 아니야.
- 사용자가 문단을 드래그하면 화면에 보이는 문장 순서대로 복사되어야 해. 위 문단, 옆 칸, 다음 항목이 섞이지 않게 해.
- 이미지 아래 설명은 번호와 문장을 함께 선택·복사할 수 있게 해. 여러 줄의 시작선과 문단 구분, 띄어쓰기를 유지해.
- 참조 위첨자 때문에 본문의 복사 순서가 바뀌지 않는지 확인해. 안내의 각 칸과 표의 각 셀도 따로 선택할 수 있어야 해.
- 참조 번호에 `position:relative; top:3px`를 적용하지 마. v104에서 이 방식으로 인해 참조가 본문과 다른 순서로 기록되고 선택하지 않은 문장이 섞이는 문제가 재현됐어. 9절의 v105 인라인 처리 방식을 사용하고 실제 드래그로 다시 확인해.
- 한글 본문은 검수한 Pretendard 고정 굵기 TTF를 우선 사용해. 기존 `fonts/Pretendard-400~800.ttf` 파일이 실제로 있는지 확인하고, 출력 PDF의 글꼴 포함 여부와 문자 매핑을 검사해. OTF나 가변 글꼴이 언제나 Type3로 변환된다고 단정하지 마. 실제로 Chrome 155에서는 CFF 윤곽 OTF(Pretendard JP)가 Type3로 들어갔어. 일본어판은 Pretendard JP를 TrueType 윤곽 TTF로 변환해(fontTools cu2qu) 쓰고, 출력 후 글꼴 종류를 반드시 확인해.
- 커닝은 꺼(`font-kerning: none`). 켜 두면 「7.1」이 PDF에서 「7 .1」처럼 빈칸이 끼어 복사된다(2026-11-09 검사패널 v106에서 15곳 확인, v105 HTML은 꺼져 있었다). 자간(letter-spacing)은 2절 값을 유지한다.
- HTML로 제작할 때 원문 문장 칸은 `white-space: pre-wrap`을 기본으로 사용해. 불필요한 수동 줄바꿈은 넣지 않고, 줄 끝 공백이 실제 PDF 복사 결과에서도 보존되는지 확인해. 이 속성만으로 복사 품질을 보장하지 마.
- 코드 강조는 7절의 키값·코드 강조 규칙을 따라 배경을 위아래로만 넓혀. 꾸밈 때문에 코드 앞뒤에 원문에 없는 공백이 생기거나 괄호·글자가 가려지지 않게 해.
- 출력 PDF에서 글꼴별 글자 수를 세어 Pretendard Regular·Medium·Bold·ExtraBold 외의 글꼴이 있는지 확인해. Pretendard에 글리프가 없는 컬러 이모지(⛔ 💡 🔗 🗑)와 논리 기호(∧ ∨)·연필 기호(✏)만 예외로 허용하고, 그 글자 목록을 검수 기록에 적어. 그 밖의 글자가 대체 글꼴로 나오면 실패야.
- 원본 블록을 숨긴(hidden) 상태에서 쪽 나눔·측정을 하면 웹 글꼴 요청이 늦게 시작돼 대체 글꼴로 측정될 수 있어. 측정 전에 쓰는 굵기를 모두 `document.fonts.load`로 먼저 불러오고 `document.fonts.check`로 확인해.
- 제목과 본문은 문서의 읽기 순서대로 배치해. 제목의 relative/absolute 위치 지정은 기본적으로 피하고, 사용해야 한다면 출력·선택 순서가 바뀌지 않았는지 확인해.
- 화면 위 원형 안의 숫자는 실제 숫자 텍스트 `1`, `2`, `3` 등으로 넣어. 원 자체는 복사 대상이 아니어도 되지만 숫자는 단독 선택·복사 시 같은 숫자로 인식돼야 해. `①` 같은 단일 원문자나 숫자 그림으로 대체하지 마.
- 화면 위 숫자는 그림 안의 위치와 읽기 순서에 맞춰 텍스트로 기록해. 겹치는 숨은 숫자를 중복으로 넣지 마. 숫자만 드래그하면 숫자만 복사되고, 아래 본문만 드래그하면 그 본문과 설명 번호만 복사돼야 해. 이미지와 본문을 함께 선택한 경우에는 화면 위 숫자도 해당 위치의 순서에 맞게 포함해.
- 원문에 있는 `⛔`, `⚠`, `🗑`, `🔗`, `💡` 같은 기호는 가능한 실제 글자로 유지해. 원문에 없는 의미 기호는 추가하지 마. 예외로 8절의 유의사항 항목 시작 ‘•’와 승인된 장·절 번호·참조·경로 디자인 표기는 해당 규칙을 따라. 글꼴 대체로 기호가 빠지거나 복사 시 다른 문자로 바뀌지 않는지도 확인해.
- Chrome 출력 시 tagged PDF를 생성해. 제목·문단·목록·표의 읽기 구조가 포함됐는지 확인하고, 책갈피는 내용 기준 PDF의 목차 표기와 실제 이동할 페이지에 맞춰 생성하거나 교정해. `tools/export_pdf.py`가 Chrome 책갈피를 자동으로 고친다. 절 번호 뒤에 띄어쓰기를 넣고(「1.1 필드」), 줄바꿈으로 붙은 제목은 HTML 원문 글자로 되돌리고, 단계는 HTML h1~h4를 따르고, 쪽을 넘어 잇달아 들어간 같은 항목은 하나만 남긴다. 메타데이터의 Chrome 이름(Creator·Producer)은 지운다(2026-11-09). 태그 존재만으로 선택 순서가 정상이라고 판정하지 마.
- 선택 순서를 확인하지 않고 글자가 추출된다는 이유만으로 복사 검수를 끝내지 마.
- Codex PDF 미리보기에서 문단별 드래그·복사를 우선 검사해. 화면 설명의 설정·결과·참고, 유의사항 카드, 표의 각 셀, 참조 위첨자, 페이지를 넘기는 문단을 포함해. 붙여넣은 결과를 원문과 대조하고 다른 줄의 글자 혼입·공백 누락·문단 순서 오류를 고쳐.
- 단어·문장·문단 단위를 각각 실제 마우스 드래그로 검사해. 참조 번호 앞뒤, 다른 카드에 인접한 문장, 줄을 넘는 문장을 포함하고, 선택하지 않은 위·아래 문장이 섞이면 통과시키지 마. 공백을 정리한 비교와 원문자 비교를 구분하고, `µ`와 `μ`처럼 뷰어에서 바뀐 문자도 별도 기록해.
- PDF를 이미지로 렌더링해 표지·목차·간지·본문·표·유의사항을 확인해. 잘림, 겹침, 원형 변형, 원치 않는 영어 줄바꿈을 고쳐.
- 내용 누락, 잘못된 목차 쪽번호, 참조 번호, 깨진 이미지가 없는지 확인해.
- 번역본은 넘기기 전에 아래 두 가지를 반드시 통과해야 해. 하나라도 실패하면 결과물로 넘기지 말고 고친 뒤 다시 출력해.
  1. 원문 언어 노출 0: PDF 텍스트·책갈피·메타데이터의 한글 글자 수 0, 화면 이미지 OCR 한글 0 (1절 ‘번역본에 원문 언어 노출 금지’).
  2. 헤더 위치: 모든 본문 페이지에서 헤더가 y=0에서 시작하고, 헤더와 경로(첫 블록) 사이가 22px 이상 (6절).
- 검수 기록에는 위 두 검사의 실제 측정값(페이지별 한글 수, 헤더 위끝·아래끝, 경로 위끝)을 적어. ‘확인했다’고만 적지 마.
- 확인하지 못한 뷰어에서 정상이라고 단정하지 마. 실제 확인한 환경과 범위를 적어.
- 최종 PDF, 편집 가능한 원본, 사용한 이미지와 글꼴 정보를 함께 제공해. 바뀐 내용은 짧게 알려줘.

### 13. 여러 분권·여러 언어 제작 흐름

34개 분권(화면별 18권 · CRF 필드 16권)을 한국어·영어·독일어·일본어 A4 PDF와 HTML로 만들 때의 고정 흐름이야. 빠르고 정확하게 만드는 것이 목적이고, 같은 검수를 분권마다 반복하지 않게 하는 구조야.

#### 결정 사항

- **원본은 데이터야.** 분권별 구조 데이터(JSON: 절·블록·항목·카드·표·이미지·화면 번호)를 단일 원본으로 둬. HTML과 PDF는 모두 이 데이터에서 만들어지는 결과물이고, HTML이나 PDF를 직접 고치지 마. 글을 고칠 때는 데이터를, 디자인을 고칠 때는 공통 템플릿을 고쳐.
- **HTML은 A4 쪽 형태로 만들어.** 인쇄용 PDF와 같은 템플릿·쪽 나눔을 쓰는 HTML을 납품용 HTML로 써. 화면에서 본 HTML이 그대로 PDF가 되게 해. 웹 열람용(폭에 따라 흐르는) HTML은 요청이 있을 때만 같은 데이터로 별도 템플릿을 만들어 추가해.
- **템플릿은 하나야.** CSS·쪽 나눔 JS·생성 스크립트는 전 분권·전 언어가 공유해. 언어별로 다른 것은 글꼴(일본어 Pretendard JP), 자간, 용어집뿐이야. 분권이나 언어마다 템플릿을 복사해 따로 고치지 마.
- **PDF는 HTML을 Chrome으로 인쇄해서만 만들어**(tagged PDF). 후처리는 책갈피·메타데이터 교정만 해.

#### 순서

1. **한국어 데이터화(분권당 1회):** 원본 PDF에서 데이터를 추출하고 1절 규칙대로 원문·띄어쓰기를 대조해. 한국어 리디자인 HTML·PDF도 이 데이터로 바로 출력해.
2. **언어별 공통 용어집 확정(번역 전):** 버튼·메뉴·탭·필드 라벨·경로·고정 문구·예시값을 34개 분권에서 모아, 언어마다 용어집 하나로 정해. 번역은 용어집이 확정된 뒤에 시작해. 분권마다 번역어가 달라지는 것을 막는 단계야.
3. **번역은 데이터의 글자열에만 해.** 마크업(강조·코드·참조)은 기호로 고정해 두고 글만 번역해. 번역 후 원문과 1:1로 대조하고(1절), 번역자와 다른 검수자가 확인해.
4. **화면 이미지 현지화는 3단계와 동시에 따로 진행해(11절).** 먼저 영어·독일어·일본어 UI로 다시 캡처할 수 있는지 확인해. 가능하면 재캡처를 기본으로 하고, 불가능한 화면은 11절 ‘2순위의 실제 도구’ 순서대로 글자 영역을 교체해. 재캡처가 없다는 이유로 한국어 캡처를 그대로 두고 넘기지 마. 이미지별 방법과 교체 목록은 `quality-manifest.json`에 기록해.
5. **HTML 생성 → 자동 검사 → 화면 검토:** 문제가 없어질 때까지 이 단계에서 반복해. PDF는 이 단계를 통과한 뒤에만 만들어.
6. **PDF 출력 → 최종 검사(12절) → 납품.**

#### 시범 후 일괄

- 처음에는 분권 1개를 4개 언어로 끝까지 만들어 검수해. 여기서 나온 문제는 공통 템플릿·용어집·이 MD에 반영해.
- 시범을 통과한 뒤 나머지 분권을 일괄로 진행해. 분권·언어 단위 작업은 서로 독립이니 병렬로 처리해도 돼. 다만 템플릿과 용어집은 한 곳에서만 고쳐.
- 일괄 진행 중 공통 문제가 발견되면 개별 파일을 고치지 말고 템플릿·용어집을 고친 뒤 영향받는 분권을 모두 다시 출력해.

#### 자동 검사(분권 × 언어마다, 하나라도 실패하면 납품 금지)

- 원문 대비 구조: 절·블록·카드 항목·표 행·열·참조 번호·화면 번호 개수가 같다.
- 내용 대조: 원문 단위가 모두 출력물에 있다(누락 0).
- 번역본 한글 0: PDF 텍스트·책갈피·메타데이터, 이미지 OCR (1절).
- 헤더: 모든 본문 쪽에서 y=0 시작, 헤더–경로 간격 22px 이상 (6절).
- 넘침·겹침: 영역을 넘친 블록 0, 쪽 아래에 혼자 남은 탭 제목 0.
- 원형 숫자 중앙 오차: PDF·화면 배율 2·고배율 가로·세로 0.3px 이하, 화면 배율 1은 0.4px 이하 (7절 ‘원형 번호 숫자: 정중앙 고정 규칙’. 자동 도구 없음 [확인 필요]).
- 원·아이콘 + 제목 + 설명 구성: 위 정렬, 제목–설명 첫 줄 기준선 차이 0px, 원 중심 − 첫 줄 글자 높이 중심 0.3px 이하 (7절).
- 빈 공간: 같은 절이 이어지는 쪽의 본문 채움 60% 이상 (11절 ‘쪽 나눔: 빈 공간 채우기 우선 규칙’).
- 글꼴: Pretendard(일본어는 Pretendard JP) 외 글꼴은 컬러 이모지만 (12절).
- 이미지: 배치 크기 기준 300dpi 픽셀 수, 무손실 포함 (11절).
- 결과는 분권 × 언어 표 하나로 검수 기록에 남겨. 측정값을 적고, 실패 항목은 원인과 조치를 함께 적어.

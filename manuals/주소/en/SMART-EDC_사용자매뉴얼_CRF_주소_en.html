What is an Address field?

  • 1.1Adding a field and the property panel layout
Path CRF ManagementDataForm DesignEdit form

Overview

Address (ADDRESS) is an input field that takes the three boxes postal code · main address · detailed address grouped into one field. This is where it differs most from other types — the screen shows three boxes, but only one value is stored, and settings such as Required · Validation · Hidden all apply to all three boxes at once.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

[+ Add field] — Specify the type here to create the field.

A new field is added to the structure tree. Its icon is a location pin.

Three boxes appear together on the WYSIWYG canvas — postal code and main address side by side on top, and detailed address on one line below.

fieldKey — The actual key under which the value is stored. It is one key grouping the three boxes. 2.1

label (display name) · description (help) — The name and supporting description shown on screen. 2.1

Required · SDV target — Covered in 2.2 · 2.3.

AE semantic role — As the on-screen notice states, the targets are Yes/No or single-choice fields, so do not set it for this type.

Allow not-measured declaration — Covered in 2.4.

Type badge “Address” — The type of the selected field. It cannot be changed after the field is added.

5 property tabs — Basic · Type settings · Validation · UI · Conditional. Of these, the Type settings tab has no setting items at all for Address, so this manual does not cover it — that is why Chapter 2 is Basic and Chapter 3 is the Validation tab. 6.2

Precautions

Must check Data corruption · Form cannot be completed

  • • ⛔ An address is personal information. A subject's place of residence leads directly to identification, so collect it only when truly necessary, and use conditional display so that subjects to whom it does not apply are not asked at all. Ch. 5
  • • The type cannot be changed after the field is added, and after publishing (PUBLISH) the structure itself cannot be changed. If you chose the wrong type, delete the field and add it again.

Easily misunderstood behavior

  • • It has three boxes but is one field. There is no setting to make only the postal code required or to validate only the detailed address. 2.2 · 3.1
  • • There is no postal code search. All three boxes are typed directly, and no map or address lookup window opens. 6.2

Basic tab — name · required · verification target · not measured

  • 2.1fieldKey · display name · help
  • 2.2Required
  • 2.3SDV target (CRA source data check)
  • 2.4Allow not-measured declaration
Path CRF ManagementDataForm DesignEdit formField propertiesBasic tab

Overview

This area sets the field's name. The storage key (fieldKey) and the name shown on screen (label) are different values, and the points at which you may change them differ. For an address, whose address and which address must be clear, so write a specific display name.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

label (display name) — Enter the item name to show on the entry screen. In the capture it is Subject's home address.

It appears as the field title on the canvas. It is one title covering all three boxes.

description (help) — Enter a supporting description to show below the display name. If left blank, nothing is shown.

It appears in gray text below the three boxes. In the capture it is “Enter the subject's current home address.”

fieldKey — The actual key under which the value is stored. It is assigned automatically when you add a field, like field_xhhk, and as the on-screen notice says, “Changing after save breaks existing data matching”.

Precautions

Must check Data corruption · Form cannot be completed

  • • State in the display name which address at which point in time. “Address” alone does not tell whether it is the address at enrollment or the current residence, so addresses from different points in time get mixed in the same box.
  • • Note in the help that the address may change. In long-term follow-up studies, subjects do actually move — you must record which point in time the address refers to so it can be interpreted later.
  • • Do not change the fieldKey after saving. The link to data already entered is broken, and the validation rules 3.3 and conditional display Ch. 5 that reference this field also break.

Easily misunderstood behavior

  • • The display name (label) can be changed at any time. It does not affect stored values.
Path CRF ManagementDataForm DesignEdit formField propertiesBasic tab

Overview

Sets whether this field must be entered before the form can be completed. For Address, this setting behaves far more loosely than you might think — because if even one of the three boxes is filled, it is judged as 'entered'. Be sure to read the precautions below.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Required — When selected, this field becomes a required item.

A red * appears to the right of the display name on the canvas. Only one mark is added, next to the field title — not one per box.

label · description — The values entered in 2.1 are shown as is.

Precautions

Must check Data corruption · Form cannot be completed

  • • ⛔ Filling just one of the three boxes passes the required check. Even if only the postal code is entered and the main address is left blank, the form is completed — the system only checks whether the whole group is empty. If you need all three boxes, say so in the help and check it at the SDV step. 2.1 · 2.3
  • • ⛔ Per-box Required is not available. A setting like “postal code only required” does not exist in any tab. If the boxes must be managed separately, it is better to create three Single-line text fields. 1.1
  • • Hidden fields are excluded from the required check. While hidden by conditional display Ch. 5, the form is completed with the field empty even if it is required.

Note

  • • If Allow not-measured declaration is on and the recorder declares it, the form can be completed even for a required item. 2.4
Path CRF ManagementDataForm DesignEdit formField propertiesBasic tab

Overview

SDV (Source Data Verification) is the procedure in which the clinical research associate (CRA) checks entered values against the site's source data. Here you decide whether this field is a target of that procedure. This setting is the same for all field types, so the screen is also the same regardless of type.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

SDV target (CRA source data check) — When selected, this field is included in the CRA's check list.

When it becomes selected, the sub-item is enabled.

Verification required (if unverified, quality PENDING) — Can be set only after ① is selected. When selected, the quality status of the data stays at PENDING until the CRA finishes the check.

Before ① is selected, ② is grayed out and disabled. As the on-screen notice says, “Set the field as a verification target first to choose whether verification is required.”

Precautions

Must check Data corruption · Form cannot be completed

  • • ⛔ The system does not check addresses at all. Neither the number of postal code digits nor whether the main address and postal code match is checked — SDV is the only step where you can judge whether the address actually exists. 3.1
  • • ⛔ Whether all three boxes are filled must also be checked at SDV. Required passes with only one box, so it cannot catch blank boxes. 2.2

Easily misunderstood behavior

  • • When the value changes, verification is cleared. Editing even one of the three boxes returns the quality status of the whole group to PENDING, and the CRA must check it again.

Note

  • • The quality status progresses in the order PENDING → VERIFIED → CLEAN. If even one field marked verification required is unverified, the data cannot become CLEAN.
Path CRF ManagementDataForm DesignEdit formField propertiesBasic tab

Overview

A feature that records, as a value, cases where the answer cannot be confirmed. For an address, “not asked yet” and “asked but not disclosed” are entirely different situations, but if the box is left blank, the two cannot be told apart — this declaration separates them.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Allow not-measured declaration — When selected, a “Not measured” checkbox is created on the entry screen and the two items below appear.

Display label — If left blank, the default “Not measured” is used.

If you change it to Address unknown, this text is applied to both the checkbox on the entry screen and the lock notice.

Indicator — The default is None.

If you change it to Caution (amber), a mark in that color appears next to the declared value.

Precautions

Must check Data corruption · Form cannot be completed

  • • ⛔ Address especially needs this declaration. If it is not on, the recorder ends up filling just one box roughly, such as Seoul, and moving on, and the required check passes it as is. 2.2
  • • ⛔ Declaring deletes all three boxes at once. As the on-screen notice says, “When declared, the value is deleted and excluded from the required-item count.” — partial retention, such as keeping only the postal code, is not possible.

Easily misunderstood behavior

  • • Declared fields are excluded from the required-item count. Therefore the form can be completed even if the item is required.

Note

  • • If no indicator is set, no color mark is applied. If emphasis is needed, select Caution (amber) or another option.

Validation tab — checking values before saving

  • 3.1No validation rules
  • 3.2Adding a rule
  • 3.3Completed rule — Compare with another field
Path CRF ManagementDataForm DesignEdit formField propertiesValidation tab

Overview

This tab collects rules that check whether a value meets conditions before saving. Address is a type with no checks applied by the system at all — neither whether the postal code has five digits nor whether the main address is blank is checked. That makes this tab important, but in practice only one kind of rule can be used. 3.3

Screen guide

Setting Where you operate
Result What the setting above changes
Note

[+ Add rule] — Creates the first rule. The screen after selecting it is explained in 3.2.

The Validation rules area and the number of registered rules. It is 0 items at first, and for Address no check is applied in this state.

When there are no rules, the notice “No validation rules registered. Add your first rule with the button below.” is shown.

Notice at the bottom — “Rules here are checked before saving. Register validations that reference values in other forms in Project validation rules.”

Precautions

Must check Data corruption · Form cannot be completed

  • • ⛔ There is no means to enforce the number of postal code digits. The Type settings tab has no item for it, and the Validation tab's Format (regex) does not work correctly for Address — the reason is explained in 3.2. If the number of digits matters, split the postal code into a separate Single-line text field.
  • • ⛔ You cannot check whether the three boxes match each other. It is saved even if the postal code and main address are in different regions — a person must cross-check them at the SDV step. 2.3
  • • ⛔ Validations that reference values in other forms cannot be created here. Register such rules in the “Project validation rules” screen — however, in that screen you cannot choose an Address field as the reference target. 6.2

Easily misunderstood behavior

  • • The capture has two fields: “Address collection consent” (Single choice) and “Subject's home address” — whether input is allowed depends on the answer to the first field, so in 3.3 a rule linking the two fields is created.
Path CRF ManagementDataForm DesignEdit formField propertiesValidation tab

Overview

Selecting [+ Add rule] in 3.1 creates a Rule 1 block. Initially “Value range” is set, but an address is neither a number nor a string — it is a bundle grouping three boxes, so size comparison does not work. Change it to “Compare with another field” — the only kind that works correctly for Address. 3.3

Screen guide

Setting Where you operate
Result What the setting above changes
Note

[+ Add rule] — Creates one more rule. (It is the same button you selected in 3.1.)

A “Rule 1” badge appears next to the display name on the canvas.

The number of rules changes to 1 item.

Active checkbox and Delete icon — You can pause a rule without deleting it.

ruleType — The kind of rule. Right after creation it is “Value range”, so be sure to change it to “Compare with another field”.

min — The lower-limit box that appears when Value range is chosen.

max — The upper-limit box that appears under the same condition.

message (shown on violation) — The message shown to users when the rule is violated.

On violation — Choose either Block save or Warning. (Depending on ruleType, it may not be selectable — 3.3)

The faint 0 · 100 and “Defining only one side is valid.” are guidance for Value range, not set values.

Precautions

Must check Data corruption · Form cannot be completed

  • • ⛔ Do not apply “Format (regex)” to Address — saving stays blocked for good. The regex checks the bundle of three boxes after converting it to a fixed internal string, so if you apply an expression such as ^\d{5}$, any input becomes a violation and the recorder has no way to save the form.
  • • ⛔ “Value range” · “Decimal places” do nothing. An address is not a number, so comparison does not work, yet the screen lets you choose them and shows no error — the author believes a rule is applied, but no check takes place.
  • • If message is left blank, users cannot tell why saving was blocked. Be sure to enter it.

Easily misunderstood behavior

  • • The only kind that actually works for Address is “Compare with another field”. That is because only this rule looks at the value of another field rather than the address's own value. 3.3
Path CRF ManagementDataForm DesignEdit formField propertiesValidation tab

Overview

Changing ruleType to Compare with another field checks the value against the value of another field in the same form. It can express relationships where whether input is allowed depends on the answer to a previous question, such as “collect the address only if collection was consented to”, and it is the only rule that works correctly for Address. 3.2

Screen guide

Setting Where you operate
Result What the setting above changes
Note

ruleType = Compare with another field — When selected, the boxes below change for comparison.

Field to compare — Choose another field in the same form. In the capture it is field_35nj(Address collection consent), a Single choice field.

operator — The comparison method. In the capture it is == (equals).

Compare against — Choose between Field and Direct input. In the capture, 1 was entered by direct input — the stored value of “Address collection consent”.

message (shown on violation) — In the capture it is Address entry allowed only with address collection consent.

On violation — Grayed out and disabled. As the on-screen notice says, “Field comparison is server-enforced, so it always blocks saving.” — for this rule, Warning cannot be chosen and it is fixed to Block save.

On-screen notice — “You can only choose from the 2 items in the form. For the comparison target, you can also enter a value directly (number · "string" · true/false).” This list also includes the Address field itself, but do not choose it.

Precautions

Must check Data corruption · Form cannot be completed

  • • ⛔ In Compare against, enter the stored value, not the text shown on screen. “Address collection consent” in the capture appears on screen as O · X, so first check in that field's option list whether the stored value really is 1 — if it differs, saving is blocked even when consent is given.
  • • ⛔ Do not choose the Address field itself as the field to compare. It appears in the list, but comparison does not work on a bundle of three boxes, so the rule is silently disabled. 3.2

Easily misunderstood behavior

  • • Even if an address is entered and then fully erased, this rule keeps checking. That is because even with all three boxes empty, the field stays “touched” — if consent was withdrawn, leaving the boxes blank does not settle it. 4.3
  • • This rule cannot be set to Warning. Use it only for relationships that must be blocked. If you only want to inform, it is better not to ask at all by using conditional display Ch. 5.

Overview

This tab sets how the field is laid out on screen and how users are guided, not the value itself. Settings in this tab do not change the stored data itself. For Address, one of the five items does not work — because it is a type to which placeholder does not apply. 4.4

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Layout width — The width this field takes on one row of the form. 4.2

Read-only (input blocked) — Shows the field but prevents changes. All three boxes are locked at once. 4.3

Hidden (no UI render · data kept) — Hides the field from the screen. All three boxes disappear at once. 4.3

placeholder — Does not apply to Address. The hint texts of the three boxes are values set by the type, so they cannot be changed here. 4.4

helpText (help) — Guidance text shown below the field. This one works correctly. 4.4

Type badge “Address”

Precautions

Must check Data corruption · Form cannot be completed

  • • ⛔ Entering text in placeholder does not change the screen. “Postal code” · “Main address” · “Detailed address” in the three boxes are texts fixed by the type, and the author cannot change them. If guidance is needed, write it in helpText. 4.4
  • • ⛔ Hidden does not erase a stored address. It is hidden only on screen; the value remains and is included in extraction and the audit trail. 4.3

Easily misunderstood behavior

  • • Settings in this tab do not change stored values. Only layout and guidance change.

Note

  • • Do not use Read-only and Hidden together. Hidden takes precedence, so the Read-only setting has no effect. 4.3
Path CRF ManagementDataForm DesignEdit formField propertiesUI tab

Overview

Sets the width this field takes on one row of the form. Address is a structure where the three boxes are split again within one row, so narrowing the width breaks the postal code box, the narrowest, first.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Layout width — Choose from Full · Half (1/2) · 1/3 · 1/4.

As the input box on the canvas shrinks to half, the hint text in the postal code box is cut off to Postal c. There are still three boxes, but you can no longer read what each box is for.

Based on 12-col grid — As the on-screen notice says, “full (12) · half (6) · third (4) · quarter (3)”. Address splits this width into three again, so the effective width is even narrower.

Precautions

Must check Data corruption · Form cannot be completed

  • • ⛔ Do not reduce it to 1/3 · 1/4. At half, the hint text is already cut off — narrowing it further leaves the recorder unable to tell what to write in which box.
  • • Full width is recommended. An address is effectively three boxes in one field, so it needs more room than any other type. 1.1

Easily misunderstood behavior

  • • Only the hint text is cut off; the boxes still work. Input and saving work correctly — it just looks narrow, which makes it all the harder to notice.

Note

  • • If not set, Full width is applied.

Overview

Settings that show the field but prevent changes, or hide it from the screen while keeping the value. Neither deletes the stored address, and both apply to all three boxes at once — there is no setting to lock only the postal code or hide only the detailed address.

Screen guide

Read-only (input blocked) — When selected, the address is shown but the recorder cannot edit it. All three boxes are locked.

  • • ⛔ Do not use Hidden to cover an incorrectly entered address either. If another subject's address was entered, the value must be corrected. 1.1

Easily misunderstood behavior

  • • Use Read-only for addresses brought in from elsewhere. Do not use it for items the recorder must take down directly.
  • • To hide depending on a condition, use conditional display. Hidden in this tab always hides the field. Ch. 5

Screen guide

Setting Where you operate

Note

placeholder — Faint text shown in the input box when there is no value. In the capture it is blank, and only the hint “Input hint (e.g. YYYY-MM-DD)” is visible.

Conditional tab — showing a field based on another value

  • 5.1Enabling conditional display
  • 5.2Setting the condition
Path CRF ManagementDataForm DesignEdit formField propertiesConditional tab

Overview

A feature that shows or hides this field depending on the value of another field. It suits Address especially well — not asking for an address at all from subjects who did not consent to collection means personal information is not collected without grounds.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Enable conditional display (condition) — When selected, the condition settings below appear.

An 🔗 eq badge appears above the field on the canvas to show that a condition is applied.

Reference field fieldKey — Another field in the same form on which the condition is based. Sibling fields in the same form are autocompleted, and you can also type a value not in the list.

operator — The comparison method. The default is eq (equals).

value — The value to compare. Enter the stored value of the reference field. 5.2

⚠ On-screen notice — “Hidden fields are exempt from required validation (affects data integrity).” The condition is evaluated by the system.

Example at the bottom — fieldKey="gender" · operator="eq" · value="M" → show this field only when gender is M.

Precautions

Must check Data corruption · Form cannot be completed

  • • ⛔ Setting a condition exempts the field from required validation. While it is hidden because the condition is not met, the form is completed with the field empty even if it is required.
  • • ⛔ If the condition becomes false after the address was entered, the address disappears from the screen. The values in the three boxes remain, so if consent is withdrawn later, the remaining address must be erased separately. 4.3

Easily misunderstood behavior

  • • The principle is to ask for personal information only when needed. Linking collection consent and address input by a condition means addresses of subjects who did not consent never come in in the first place. 3.3

Note

  • • If you enable the condition and leave the reference field blank, the condition is never met. Be sure to fill in all of ②~④. 5.2
Path CRF ManagementDataForm DesignEdit formField propertiesConditional tab

Overview

The state with the condition enabled in 5.1 filled in completely. With this setting, the address input box is shown on screen only when the value of the “Address collection consent” field is 1. The reference field is Single choice, so the value box must contain the stored value of that option.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Reference field fieldKey = field_35nj — Points to the “Address collection consent” field in the same form.

Result of entering all of ①–③ — the canvas badge becomes specific as 🔗 field_35nj(Address collection consent) eq 1.

operator = eq (equals)

value = 1 — Enter the option's stored value, not the O shown on screen.

⚠ On-screen notice — “Hidden fields are exempt from required validation (affects data integrity).”

Example at the bottom — fieldKey="gender" · operator="eq" · value="M" → show this field only when gender is M.

Precautions

Must check Data corruption · Form cannot be completed

  • • ⛔ In value, enter the stored value, not the on-screen text. If you write O because “Address collection consent” appears on screen as O · X, the condition is never met and the address boxes are never shown. First check the stored value in the option list of the field you reference.
  • • ⛔ Changing the stored value of the reference field silently breaks the condition. If the stored value is changed from 1 to Y, this condition simply stops being met without any error — that is why changing stored values after publishing is risky.
  • • The same relationship can also be created as a validation rule 3.3. Applying both results in a duplicate that both does not ask and blocks saving, so use only one.

Easily misunderstood behavior

  • • After setting it, check it in Preview. Change the reference value back and forth to confirm that the three boxes actually appear and disappear.

Must remember

Must check Data corruption · Form cannot be completed

  • • Do not apply the Validation tab's “Format (regex)” to Address. Any input becomes a violation, and the recorder has no way to save the form. 3.2
  • • Required passes when just one of the three boxes is filled. The form is completed even with only the postal code, so if you need all three boxes, say so in the help and check at SDV. 2.2 · 2.3
  • • Text written in placeholder is not shown anywhere. Write all guidance in helpText. 4.4
  • • “Value range” · “Decimal places” do nothing. They show no error either, so you move on believing a rule is applied. 3.2
  • • An address is personal information. Link it to collection consent and ask conditionally, and if consent is withdrawn, erase all three boxes. 3.3 · 4.3 · 5.1
  • • Do not use 1/3 · 1/4 width. At half, the hint text in the postal code box is already cut off. 4.2

Easily misunderstood behavior

  • • There are no checks applied by the system at all. It is saved even if the postal code and main address are in different regions — a person must cross-check them at the SDV step. 2.3 · 3.1
  • • It has three boxes but is one field. Required · Read-only · Hidden · not-measured declaration all apply to the three boxes at once. 1.1 · 4.3
  • • If the boxes must be managed separately, split the type. If you want to enforce the number of digits only for the postal code, it is better to create three Single-line text fields. 2.2 · 3.1

Note

  • • The change history records the three boxes as one bundle. It is kept on one line, like (06234) 123 Teheran-ro, Gangnam-gu, Seoul, 5F, Unit 501.

Not covered in this document

※ Type settings tab — Address has no setting items at all. Not even the Default value (defaultValue) item found in Phone number · Email is shown — because the value groups three boxes, there is no means to prefill it. That is why this manual has no Type settings chapter, and Chapter 2 is followed by the Validation tab. 1.1

Postal code search (address lookup) — Not available. All three boxes are typed directly, and no map or search window opens. 1.1

Per-box Required · per-box validation — A setting like “postal code only required” does not exist in any tab. The system handles the three boxes as one value. 2.2

Postal code format check — There is no item to enforce the number of digits. Regex does not work for Address either 3.2, so if the number of digits matters, split it into a Single-line text field.

Auto calculation (calculation) — The Type settings tab has a checkbox, but Address has no representation to carry a computed value, so it becomes a locked empty box. It is a feature that computes values with a formula, so use it with the Number type.

Reference in project validation rules — In the “Project validation rules” screen, which looks at values in other forms, you cannot choose an Address field as the reference target. The value is a bundle of three boxes, so size comparison does not work. 3.1

AE semantic role — The item exists in the Basic tab, but this type is not a valid target. Assign it to Yes/No or single-choice fields. 1.1

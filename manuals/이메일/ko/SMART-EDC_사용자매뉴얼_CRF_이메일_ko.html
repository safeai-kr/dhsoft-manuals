개요

개요

필드의 이름을 정하는 영역입니다. 저장 키(fieldKey)와 화면에 표시되는 이름(label)은 서로 다른 값이며, 변경해도 되는 시점이 다릅니다. 이메일은 누구의 주소인지 분명해야 하므로 표시명을 구체적으로 적으십시오.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

label (표시명) — 입력 화면에 표시할 항목 이름을 입력합니다.

캔버스 필드 제목으로 표시됩니다.

description (도움말) — 표시명 아래에 표시할 보조 설명을 입력합니다. 공란으로 두면 표시되지 않습니다.

입력란 아래 회색 글씨로 표시됩니다. 캡처는 “임상 대상자의 이메일을 입력합니다.” 입니다.

fieldKey — 값이 저장되는 실제 키입니다. 필드를 추가하면 field_u4vp 처럼 자동으로 부여되며, 화면 안내와 같이 “저장 후 변경 시 기존 데이터 매칭 깨짐” 입니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 누구의 주소인지 표시명에 밝히십시오. 「이메일」 만으로는 피험자 본인인지 보호자인지 담당 연구자인지 알 수 없어, 같은 칸에 서로 다른 사람의 주소가 섞입니다.
  • • 무엇에 쓰는 주소인지 도움말에 적으십시오. 결과 통보용인지 일정 안내용인지에 따라 피험자가 알려 줄 주소가 달라집니다 — 업무용과 개인용은 보통 다릅니다.
  • • fieldKey 는 저장한 뒤에 변경하지 마십시오. 이미 입력된 데이터와의 연결이 끊어지고, 이 필드를 참조하던 검증 규칙4.3과 조건부 표시6장도 함께 깨집니다.

오해하기 쉬운 동작

  • • 표시명(label)은 언제든 변경할 수 있습니다. 저장된 값에는 영향을 주지 않습니다.

개요

이 필드를 반드시 입력해야 폼을 완료할 수 있게 할지 정합니다. 이메일은 없는 사람도 있고 알려 주지 않는 사람도 있는 항목이라, 필수로 지정하기 전에 그런 경우를 어떻게 기록할지 먼저 정하십시오. 2.4

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 이메일을 필수로 두면 기록자가 임의의 주소를 채워 넣게 됩니다. 고령 피험자처럼 주소가 없는 경우가 실제로 많습니다 — 필수로 지정한다면 미측정 선언2.4을 반드시 함께 켜십시오.
  • • 숨겨진 필드는 필수 검사에서 제외됩니다. 조건부 표시6장로 감춰진 동안에는 필수여도 비어 있는 상태로 폼이 완료됩니다.

오해하기 쉬운 동작

  • • 필수와 형식 검사는 서로 다른 검사입니다. 필수는 비어 있지 않은지만 보고, 형식은 모양이 맞는지만 봅니다. 빈 값은 형식 검사를 건너뛰므로 둘 다 걸고 싶다면 필수를 함께 지정해야 합니다. 4.1

참고

  • • 미측정 선언이 켜져 있고 기록자가 선언하면, 필수 항목이어도 폼을 완료할 수 있습니다. 2.4
경로 CRF 관리DataForm 설계폼 편집필드 속성기본 탭

개요

SDV(Source Data Verification) 는 임상연구모니터요원(CRA)이 입력값을 의료기관 원자료와 대조하는 절차입니다. 이 필드를 그 대상으로 지정할지 여기에서 정합니다. 이 설정은 모든 필드 타입에서 동일하므로 화면도 타입과 무관하게 같습니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

SDV 검증 대상 (CRA 원자료 대조) — 선택하면 이 필드가 CRA 의 대조 목록에 포함됩니다.

선택 상태로 바뀌면서 하위 항목이 활성화됩니다.

검증 필수 (미검증 시 품질 PENDING) — ①을 선택한 뒤에야 지정할 수 있습니다. 선택하면 CRA 가 대조를 마치기 전까지 해당 데이터의 품질 상태가 PENDING 에 머무릅니다.

①을 선택하기 전에는 ②가 흐리게 비활성입니다. 화면 안내와 같이 “검증 대상으로 지정해야 필수 여부를 정할 수 있습니다.”

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 형식 검사를 통과했다고 대조가 끝난 것이 아닙니다. 시스템은 모양만 보므로 오타가 섞인 주소도 통과합니다 — 실제로 존재하는 주소인지는 CRA 가 원자료와 대조해야 알 수 있습니다. 4.1
  • • 값이 변경되면 검증이 해제됩니다. 주소를 고치면 품질 상태가 PENDING 으로 되돌아가고 CRA 가 다시 대조해야 합니다.

오해하기 쉬운 동작

  • • SDV 는 입력한 사람이 직접 수행할 수 없습니다. 시스템이 교차 검증(Cross-User SoD)을 강제하므로 입력자와 검증자는 반드시 달라야 합니다.

참고

  • • 품질 상태는 PENDING → VERIFIED → CLEAN 순으로 진행됩니다. 검증 필수로 지정한 필드가 하나라도 미검증이면 해당 데이터는 CLEAN 이 되지 못합니다.

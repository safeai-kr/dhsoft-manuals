電話番号フィールドとは

  • 1.1フィールドの追加と属性パネルの構成
パス CRF管理DataForm設計フォーム編集

概要

電話番号(PHONE)は、被験者 · 保護者 · 担当者の連絡先を受け付ける入力欄です。追加すると、キャンバスに 010-0000-0000 の案内が入った入力欄が表示されます。最大の特徴はハイフンが自動的に付くことです — 記録者が数字だけを押しても、システムが桁数を見て 010- 1234-5678 の形に変えてくれます。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

[+ フィールド追加] — ここでタイプを指定するとフィールドが作成されます。

構造ツリーに新しいフィールドが追加されます。アイコンは受話器の形です。

WYSIWYG キャンバスに入力欄が表示され、010-0000-0000 の案内が表示されます。この文言は UI タブで変更できます。5.4

fieldKey — 値が保存される実際のキーです。2.1

label (表示名) · description (ヘルプ) — 画面に表示される名前と補足説明です。2.1

必須入力 · SDV検証対象 — 2.2 · 2.3 で扱います。

AE意味ロール — 画面の案内が示すとおり、はい/いいえか単一選択フィールドが指定対象なので、このタイプでは指定しません。

未測定宣言を許可 — 2.4 で扱います。

タイプバッジ「電話番号」 — 選択したフィールドのタイプです。追加した後は変更できません。

属性タブ 5種 — 基本 · タイプ設定 · 検証 · UI · 条件付き。このマニュアルの2~6章が各タブに対応します。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 電話番号は個人情報です。被験者の特定につながるおそれがあるため、ロールに応じて伏せて表示されます — 画面上部の「マスキング ON」がその表示です。本当に必要な連絡先だけを収集し、なぜ必要なのかをヘルプに記載しておいてください。2.1
  • • タイプは追加した後に変更できず、発行(PUBLISH)後は構造そのものを変更できません。誤って選択した場合は、フィールドを削除して再度追加してください。

誤解しやすい動作

  • • ハイフンは自動的に付きます。記録者に「- を入れて入力する」よう案内する必要はありません — 数字だけを押してもシステムが入れてくれます。ただし、保存される値にもハイフンが含まれるため、検証規則を作るときは注意が必要です。4.2

パス CRF管理DataForm設計フォーム編集フィールド属性基本タブ

概要

フィールドの名前を決める領域です。保存キー(fieldKey)と画面に表示される名前(label)は別々の値であり、変更してもよい時点が異なります。連絡先は誰の番号かが明確である必要があるため、表示名を具体的に記入してください。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

label (表示名) — 入力画面に表示する項目名を入力します。

キャンバスのフィールドタイトルとして表示されます。

description (ヘルプ) — 表示名の下に表示する補足説明を入力します。空欄にすると表示されません。

入力欄の下にグレーの文字で表示されます。キャプチャでは「親、知人など保護者の連絡先を入力します。」です。

fieldKey — 値が保存される実際のキーです。フィールドを追加すると field_9w65 のように自動的に付与され、画面の案内にあるとおり「保存後の変更で既存データの紐付けが切れる」です。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • 誰の番号かを表示名で明示してください。「連絡先」だけでは被験者本人か保護者かが分からず、同じ欄に別々の人の番号が混在します。キャプチャのように「保護者連絡先」と記入してください。
  • • どのような場面で使う番号なのかをヘルプに記載してください。緊急連絡用か来院案内用かによって、記録者が聞き取って書き留める番号が変わります。
  • • fieldKey は保存した後に変更しないでください。すでに入力されたデータとの紐付けが切れ、このフィールドを参照していた検証規則4.3と条件付き表示6章も一緒に壊れます。

誤解しやすい動作

  • • 表示名(label)はいつでも変更できます。保存された値には影響しません。
パス CRF管理DataForm設計フォーム編集フィールド属性基本タブ

概要

このフィールドを必ず入力しないとフォームを完了できないようにするかを決めます。連絡先はない場合もあり、教えてもらえない場合もある項目なので、必須に指定する前に、そうした場合をどう記録するかを先に決めてください。2.4

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

必須入力 — 選択すると、このフィールドが必須項目になります。

キャンバスの表示名の右に赤い * が表示されます。

label · description — 2.1 で入力した値がそのまま表示されます。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 連絡先を必須にすると、記録者が適当な番号を埋めることになります。保護者がいない場合や番号を教えてもらえない場合は実際に起こります — 必須に指定するなら、未測定宣言2.4を必ず一緒にオンにしてください。
  • • 形式が正しいかどうかは必須設定とは関係ありません。必須は空でないかどうかだけを見ます — 桁数が足りなくても通過します。形式を制限するには検証規則を使用してください。4.2
  • • 非表示のフィールドは必須チェックから除外されます。条件付き表示6章で隠されている間は、必須であっても空のままフォームが完了します。

参考

  • • 未測定宣言がオンになっていて記録者が宣言すると、必須項目であってもフォームを完了できます。2.4
パス CRF管理DataForm設計フォーム編集フィールド属性基本タブ

概要

SDV(Source Data Verification) は、臨床開発モニター(CRA)が入力値を医療機関の原資料と照合する手順です。このフィールドをその対象に指定するかどうかを、ここで決めます。この設定はすべてのフィールドタイプで共通なので、画面もタイプに関係なく同じです。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

SDV検証対象 (CRA原資料照合) — 選択すると、このフィールドが CRA の照合リストに含まれます。

選択状態に変わると、下位項目が有効になります。

検証必須 (未検証時は品質 PENDING) — ①を選択した後でなければ指定できません。選択すると、CRA が照合を終えるまで、そのデータの品質ステータスが PENDING のままになります。

①を選択する前は、②が薄く表示されて無効です。画面の案内のとおり「検証対象に指定した場合のみ必須かどうかを設定できます。」

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 連絡先を SDV 対象に指定するかどうかは慎重に決めてください。照合するには CRA が伏せられていない番号を見る必要がありますが、電話番号は個人情報なのでロールによってマスキングされます。照合が本当に必要な連絡先かどうかを先に確認してください。1.1
  • • 値が変更されると検証が解除されます。番号を修正すると品質ステータスが PENDING に戻り、CRA が再度照合する必要があります。

誤解しやすい動作

  • • SDV は入力した本人が実施することはできません。システムがクロス検証(Cross-User SoD)を強制するため、入力者と検証者は必ず別の人である必要があります。

参考

  • • 品質ステータスは PENDING → VERIFIED → CLEAN の順に進みます。検証必須に指定したフィールドが一つでも未検証であれば、そのデータは CLEAN になりません。
パス CRF管理DataForm設計フォーム編集フィールド属性基本タブ

概要

回答を確認できない場合を値で区別して記録する機能です。連絡先では「まだ尋ねていない」と「尋ねたが教えてもらえなかった」はまったく異なる状況ですが、空欄のままにすると両者を区別できません — この宣言がその二つを分けてくれます。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

未測定宣言を許可 — 選択すると、入力画面に「未測定」チェックボックスが作成され、下の二つの項目が表示されます。

表示ラベル — 空欄にすると、デフォルト値「未測定」が適用されます。

保護者不明 に変更すると、この文言が入力画面のチェックボックスとロック案内の両方に適用されます。

表示灯 — デフォルト値はなしです。

注意(amber) に変更すると、宣言された値の横にその色の表示が現れます。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 連絡先には特にこの宣言が必要です。オンにしないと、記録者が 010-0000-0000 のような偽の番号を埋めることになり、その値は形式上正常なので、どの検証にも引っかかりません。
  • • 宣言すると値が削除されます。画面の案内のとおり — 「宣言時に値が削除され、必須項目の集計から除外されます。」

誤解しやすい動作

  • • 宣言されたフィールドは必須集計から除外されます。そのため、必須項目であってもフォームを完了できます。

参考

  • • 表示灯を指定しないと、色の表示は適用されません。強調が必要な場合は、注意(amber) などを選択してください。

パス CRF管理DataForm設計フォーム編集フィールド属性タイプ設定タブ

概要

電話番号はタイプ固有の設定がないタイプです。形式を選ぶ必要がないためです — 桁数を見てハイフンを入れる規則がすでに決まっています。そのため、このタブには案内 1 行と、すべてのタイプに共通で付く 2 項目だけが残ります。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

デフォルト値 (defaultValue) — 新規入力時にあらかじめ入れておく値です。最初は空です。3.2

画面の案内 — 「このフィールドタイプには追加設定がありません。」許容桁数 · 市外局番 · 国の選択といった項目は指定できません。

自動計算 (calculation) — 項目は表示されますが、このタイプでは使用しません。計算式で電話番号を算出することはないためです。

タイプバッジ「電話番号」 — 設定中のフィールドのタイプです。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 韓国の形式だけが適用されます。国外の番号を受け付ける必要がある場合、桁数が合わないため、誤った位置にハイフンが入ります。そのような項目は、このタイプではなく単一行テキストで作成してください。

誤解しやすい動作

  • • 形式はシステムが決めます。数字を押すにつれて、ソウル(02)は 02-123-4567 · 02-1234-5678、それ以外は 010-123-4567 · 010-1234-5678 の形に整えられます。作成者が変更できる項目ではありません。
  • • 桁数を強制したい場合は検証タブを使用してください。ただし、保存値にハイフンが含まれるため、書き方に注意が必要です。4.2

参考

  • • 国コードの選択項目は画面にありません。システムには定義がありますが、作成画面には提供されていません。(※ 7.2)
パス CRF管理DataForm設計フォーム編集フィールド属性タイプ設定タブ

概要

新規入力時にあらかじめ入れておく番号を決めます。最初は空です。他のタイプとは異なり、編集画面ですぐに確認できます — プレビューに移らなくても、キャンバスの入力欄にその値が表示されます。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

デフォルト値 (defaultValue) — あらかじめ入れておく番号を入力します。キャプチャでは 010-1234-5678 です。

キャンバスの入力欄にその番号がそのまま表示されます。真/偽 · 単一選択とは異なり、[プレビュー] に移動しなくても確認できます。

自動計算 (calculation) — このタイプでは使用しません。3.1

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 連絡先にデフォルト値を設定しないでください。記録者が確認しなくても番号が入っているため、他人の番号が保存されるおそれがあります。臨床試験データにおいて、これは単なる入力ミスではなく、個人情報が誤って記録される事故です。1.1
  • • ⛔ 例示用の番号をデフォルト値に入れるのは特に危険です。010-1234-5678 のような値は形式が正常なので、どの検証にも引っかからずにそのまま保存されます。できるだけ空のままにしてください。
  • • デフォルト値を設定したフィールドは、記録者が手を付けなくても必須チェックを通過します。必須入力2.2と一緒に使用する場合は特に注意してください。

誤解しやすい動作

  • • デフォルト値に入力した番号も、ハイフンが自動的に整えられて表示されます。

パス CRF管理DataForm設計フォーム編集フィールド属性検証タブ

概要

保存する前に値が条件に合っているかをチェックする規則をまとめておくタブです。電話番号はハイフンが自動的に付くだけで、桁数が足りなくてもそのまま保存されます — 形式を強制するには、このタブで規則を作成する必要があります。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

[+ 規則追加] — 最初の規則を作成します。選択した後の画面は 4.2 で説明します。

検証規則領域と、登録された規則数です。最初は 0 件 です。

規則がない場合は、「登録された検証規則はありません。下のボタンから最初の規則を追加してください。」という案内が表示されます。

下部の案内 — 「ここの規則は保存前にチェックします。他のフォームの値を参照する検証はプロジェクト検証規則で登録してください。」

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 自動ハイフンは形式チェックではありません。010-12 のように桁数が足りなくても保存されます — ハイフンが付いたからといって正しい番号という意味ではありません。完全な番号を求めるには規則が必要です。4.2
  • • ⛔ 他のフォームの値を参照する検証はここでは作成できません。そのような規則は「プロジェクト検証規則」画面で登録してください。
  • • 検証タブはタイプによって制限されません。電話番号に合わない規則も選べるため、選んだ規則がこのタイプで成り立つかどうかを自分で確認する必要があります。4.2

誤解しやすい動作

  • • キャプチャにはフィールドが二つあります。「保護者の有無」(単一選択)と「保護者連絡先」— 前のフィールドの回答によって連絡先を入力できるかどうかが分かれる関係なので、4.3 で二つのフィールドを結ぶ規則を作成します。
パス CRF管理DataForm設計フォーム編集フィールド属性検証タブ

概要

4.1 の [+ 規則追加] を選択すると、規則 1 ブロックが作成されます。最初は「値の範囲」が設定されていますが、電話番号は数値ではなくハイフンが混ざった文字列なので、大小比較が成り立ちません — 「形式 (正規表現)」または「他フィールドと比較」に変更する必要があります。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

[+ 規則追加] — 規則をもう一つ作成します。(4.1 で選択したのと同じボタンです。)

キャンバスの表示名の横に「規則 1」バッジが表示されます。

規則数が 1 件 に変わります。

有効チェックボックスと削除アイコン — 規則を削除せずに一時的に停止できます。

ruleType — 規則の種類です。作成直後は「値の範囲」なので、使用したい規則に変更してください。

min — 値の範囲を選んだときに表示される下限の欄です。

max — 同じ条件で表示される上限の欄です。

message (違反時表示) — 規則に違反したときに、ユーザーに表示する文言です。

違反時 — 保存ブロックまたは警告から選択します。(ruleType によっては選べなくなることもあります — 4.3)

薄い文字の 0 · 100 と「片方だけ定義しても有効です。」は値の範囲に関する案内であり、設定された値ではありません。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 正規表現にはハイフンを含めて記述してください。保存される値は数字だけではなく、ハイフンが付いた文字列(010-1234-5678)です。数字だけを想定した式(^01[0-9]{8,9}$)は正常な入力もすべて拒否します — ^01\d-\d{3,4}-\d{4}$ のようにハイフンの位置を入れて記述してください。

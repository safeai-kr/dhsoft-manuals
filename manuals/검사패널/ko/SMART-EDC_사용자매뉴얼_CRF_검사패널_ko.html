개요

검사 패널(LAB_PANEL) 은 검사 항목 × 입력 컬럼 두 축으로 짜인 표입니다. 행은 검사 항목(혈당 · 백혈구 …), 열은 항목마다 똑같이 받는 값(검사값 · 판정 · 임상적 의의)입니다. 표(테이블형)·필드 그룹과 가장 다른 점은 추가하자마자 쓸 수 있는 구성이 들어 있다는 것입니다 — 다른 컨테이너는 빈 안내만 나오지만, 검사 패널은 혈당 한 항목과 세 개의 열이 미리 채워진 채 생성됩니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 기본 구성은 예시이지 표준이 아닙니다. 「혈당」 한 항목은 모양을 보여 주기 위한 seed 입니다 — 반드시 실제로 받을 검사 항목으로 바꾸십시오. 3.3 · 3.4
  • • ⛔ 기록자는 행을 추가할 수 없습니다. 표(테이블형)와 달리 행은 저작자가 정한 검사 항목으로 고정됩니다 — 받을 항목을 빠짐없이 넣어야 합니다. 3.4 · 7.1
  • • 타입은 추가한 뒤에 변경할 수 없고, 발행(PUBLISH) 이후에는 구조 자체를 변경할 수 없습니다. 잘못 선택했다면 필드를 삭제하고 다시 추가하십시오.

오해하기 쉬운 동작

  • • 정상범위는 이 화면에서 적지 않습니다. 기관 · 성별 · 연령마다 다르기 때문에 좌측 메뉴 「LAB 정상범위」 화면에서 따로 저작합니다. 3.2 · 3.7

개요

표의 이름을 정하는 영역입니다. 저장 키(fieldKey)와 화면에 표시되는 이름(label)은 서로 다른 값이며, 변경해도 되는 시점이 다릅니다. 검사 패널은 언제 채혈한 어떤 검사인지가 드러나야 하므로 표시명을 구체적으로 적으십시오.

설정 직접 조작하는 위치

참고

label (표시명) — 표 위에 표시할 제목을 입력합니다. 캡처는 혈액검사 결과 입니다.

캔버스 표 제목으로 표시됩니다. 검사 항목 이름이나 열 이름과는 다른 층입니다 — 그 둘은 타입 설정 탭에서 따로 정합니다. 3.2 · 3.5

description (도움말) — 표 아래에 표시할 보조 설명을 입력합니다. 공란으로 두면 표시되지 않습니다.

표 아래 회색 글씨로 표시됩니다. 캡처는 “대상자의 혈액검사 결과를 입력하고, 각 검사항목의 정상범위 여부 및 임상적 의미를 기록합니다.” 입니다.

fieldKey — 표 전체가 저장되는 키입니다. 필드를 추가하면 field_fh7f 처럼 자동으로 부여되며, 화면 안내와 같이 “저장 후 변경 시 기존 데이터 매칭 깨짐” 입니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 검사 시점을 표시명에 밝히십시오. 「혈액검사 결과」 만으로는 선별 검사인지 추적 검사인지 알 수 없습니다 — 같은 양식을 여러 방문에서 쓸 때 특히 중요합니다.
  • • 채혈일을 어디에 적을지 도움말에 안내하십시오. 검사일은 이 표 안이 아니라 폼의 날짜 필드에 적는 것이 원칙이며, 자동 판정을 쓰려면 반드시 그렇게 해야 합니다. 3.7
  • • fieldKey 는 저장한 뒤에 변경하지 마십시오. 이미 입력된 데이터와의 연결이 끊어지고, 이 필드를 참조하던 검증 규칙4.3 · 조건부 표시6장 · 자동 판정 지정3.7 도 함께 깨집니다.

오해하기 쉬운 동작

  • • 표시명(label)은 언제든 변경할 수 있습니다. 저장된 값에는 영향을 주지 않습니다.

개요

이 표를 반드시 채워야 폼을 완료할 수 있게 할지 정합니다. 검사 패널에는 다른 컨테이너에 없는 배려가 하나 있습니다 — 손도 대지 않은 행은 미완료로 치지 않습니다. 그래서 일부 검사만 시행한 상황을 그대로 기록할 수 있습니다.

설정 직접 조작하는 위치

참고

필수 입력 — 선택하면 이 표가 필수 항목이 됩니다. 실제로 입력한 행이 한 건도 없으면 폼을 완료할 수 없습니다.

캔버스 표 제목 오른쪽에 빨간 * 가 표시됩니다. 열마다 붙는 별은 3.5 에서 따로 정합니다.

label · description — 2.1 에서 입력한 값이 그대로 표시됩니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 한 칸이라도 건드린 행은 전부 검사합니다. 검사값만 적고 필수 열을 비우면 그 행이 미완료로 남습니다 — 쓰지 않을 행은 아무것도 입력하지 않은 채로 두십시오. 3.5
  • • ⛔ “검사 안 함” 을 표시할 수단이 없습니다. 미측정 선언을 켤 수 없는 타입이므로, 시행 여부를 남겨야 한다면 앞에 예/아니오 질문을 두고 조건부로 묶거나 표시전용 열로 메모를 남기십시오. 3.5 · 6장 · 7.2

오해하기 쉬운 동작

  • • 전 컬럼이 빈 행은 검사하지 않습니다. 일곱 항목 중 셋만 시행했다면 나머지 네 행은 비워 두어도 폼이 완료됩니다 — 검사 패널은 행이 미리 깔려 있어 이런 배려가 필요합니다. 3.6
  • • 숨겨진 필드는 필수 검사에서 제외됩니다. 조건부 표시6장로 감춰진 동안에는 필수여도 비어 있는 상태로 폼이 완료됩니다.

개요

SDV(Source Data Verification) 는 임상연구모니터요원(CRA)이 입력값을 의료기관 원자료와 대조하는 절차입니다. 검사 패널은 원자료가 분명한 자료(검사실 결과지)라 SDV 의 효용이 가장 큰 타입입니다. 이 설정은 모든 필드 타입에서 동일하므로 화면도 타입과 무관하게 같습니다.

SDV 검증 대상 (CRA 원자료 대조) — 선택하면 이 필드가 CRA 의 대조 목록에 포함됩니다. 지정 단위는 표 전체이며 검사 항목이나 열마다 따로 지정할 수 없습니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 자동 판정이 붙은 값도 대조 대상입니다. 시스템이 적은 판정은 그 시점의 정상범위로 계산한 결과일 뿐이고, 검사실 결과지의 판정과 다를 수 있습니다 — CRA 가 원자료와 맞춰 보아야 합니다. 3.7
  • • ⛔ 단위가 맞는지도 대조해야 합니다. 시스템은 단위를 검사하지 않습니다 — 검사실이 mg/dL 로 주는 값을 mmol/L 칸에 적어도 그대로 저장됩니다. 3.3

오해하기 쉬운 동작

  • • 값이 변경되면 검증이 해제됩니다. 행 하나의 셀 하나만 고쳐도 표 전체의 품질 상태가 PENDING 으로 되돌아가고 CRA 가 다시 대조해야 합니다.

참고

  • • 품질 상태는 PENDING → VERIFIED → CLEAN 순으로 진행됩니다. 검증 필수로 지정한 필드가 하나라도 미검증이면 해당 데이터는 CLEAN 이 되지 못합니다.

열을 참조하는 검증 · 조건 — 열의 fieldKey 는 표 안에서만 유효해서 다른 필드의 검증 규칙이나 조건부 표시에서 직접 참조할 수 없습니다. 4.3 · 6.1

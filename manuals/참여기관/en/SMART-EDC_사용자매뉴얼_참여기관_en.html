Site list

  • 1.1Screen layout
  • 1.2When registration is available
Path Project settingsSites

Overview

This screen manages the sites that recruit subjects for this project. Each site has a principal investigator and IRB approval information, and you assign investigators to work at that site. You can register subjects only after sites exist, so this is setup work that must be finished before subject registration.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Search — Narrows the rows by principal investigator name.

Status filter — Narrows the rows to Active or Closed.

Register — Moves to the Investigator assignment screen for that site 3.1. The number on the left is the number of investigators currently assigned.

Row actions — There are two: Edit 2.3 and Investigator assignment 3.1. There is no option to close a site here, because all sites under the project are closed automatically when you close the project.

Subject count — Select it to go to the subject list for that site.

The path is Dashboard / Project settings / Sites.

The number in parentheses next to the title is the number of registered sites.

List · Summary view tabs — The summary view shows each site's registration status as cards. Auditors cannot view the summary view.

Site code · Site name — The site code is not the site's own code. It is a number assigned within this project (siteCode) 1.2. The small text under the site name is the code from the site master.

Status — Active or Closed.

Principal investigator — Shows the name entered on the register or edit screen as-is.

IRB approval date / Approval number — The approval number is optional, so if it is empty, — is shown.

Access paths

  • • Left menu Settings > Sites
  • • Shortcut to Sites on the project settings screen
  • • Shortcut to Investigator assignment on the project settings screen (opens with the investigator count column highlighted)
  • • A row in the Sites widget on the project dashboard, or View all

Precautions

Easily misunderstood behavior

  • • A principal investigator (PI) can edit and assign only the rows for their own site. No action menu appears on rows for other sites. Research nurses, monitors and auditors can only read the list.

Path SitesRegister site

Overview

This is the first step in adding a site. You do not type in a new site. Instead, you select it from the list of sites already registered. After you select a site, fields for site number · principal investigator name · IRB approval information follow below it (for the field layout, see 2.3).

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Site search — Narrows the list by site name, code or country.

Select site — Select a site from the list. Selecting one opens the input fields below and the Register button.

+ Request site registration — Use this when the site you want is not in the list 2.2.

Register — Saves your input and returns to the list. It stays faded and cannot be selected until you fill in site · site number · principal investigator name · IRB approval date.

← Site list — Returns to the list without saving.

Confirm which project you are adding the site to by the project name and protocol number.

Site card — The area where you select a site. You cannot edit the site's own information (name, address, type) here.

The small text under each item is the site code · country · English name. If sites have similar names, use these values to tell them apart.

The list scrolls. The four items you can see are not all of them, so narrow it down with search to check.

Cancel — Discards your input and returns to the list.

Precautions

Must check Data corruption · Form cannot be completed

  • • If you select the wrong site, you cannot change it after registration. The site selection area itself is not shown on the edit screen 2.3. To change the site, you must register the site again, so check the code and country before you select.
Path Register siteRequest site registration

Overview

Use this dialog when the site you want to add is not in the site list. The site is not created here right away. It appears in the list only after a system administrator reviews and approves it, and you receive a notification when it is approved. So you continue site registration after the approval.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Proposed code — Required. Propose a short code to identify the site (e.g., “SNUH” · “AMC”). The administrator sets the final code.

Site name — Required. Enter the official name.

English name — Optional. Enter it when you need to tell sites apart in a multi-country study.

Site type — Required. Select a type, such as hospital.

Country — Required. The default is South Korea. Narrow the list by search and select.

Reason for request — Optional. Writing the grounds for the administrator's decision speeds up the review.

Submit request — Sends the request. After you submit, the dialog does not close right away. It changes to a completion notice, so check the content and then close it.

Notice — “This site is not registered in Site management. You will receive a notification once the system administrator reviews and approves it.”

Close — Closes the dialog without sending a request.

Country input note — “ISO-3166-1 alpha-2 code (narrow by search and select).” It uses two-letter country codes, and values not in the list cannot be entered.

Cancel — Discards your input and closes the dialog.

Precautions

Easily misunderstood behavior

  • • If a request with the same code is already pending, the request is rejected. In that case, do not request again. Wait until the administrator's review is complete. Someone else may already have requested the same site. Until it is approved, you cannot add that site as a Site.

This screen edits the values of a registered site. Its input fields are the same as on the register screen, but you cannot change the site itself. The capture shows an Active project, so every field is disabled. In the Setup · Test stages, you can edit and save the values in the same place.

Path SitesInvestigator assignment

Overview

This screen is where you decide who works at each site. Each site has its own tab, and the investigators assigned to that site are listed inside the tab. You can keep assigning investigators during live operation, because replacing staff is normal work that happens while the study is running.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Add investigator — Assigns a person to this site 3.2.

Site tabs — If there are several sites, they are split into tabs. A principal investigator sees only the tab for their own site.

Release — Removes the assignment. You can run it only after you enter a reason of at least 5 characters. The confirmation dialog explains the scope of the impact 3.3.

The path is Dashboard / Project settings / Sites / Investigator assignment.

Change history — Cannot be selected at the moment. Assignment and release records are kept in the system, and the screen for viewing them is being prepared.

The site number · site name · principal investigator of the selected site. Before you work, check here which site you are looking at.

Role — The role the person holds at this site 3.3.

Assigned date — The date and time of the assignment.

Status — Active or Released. A person who has been released does not disappear from the list. They remain listed as Released.

Email — Use this value to tell people apart when several have the same name.

Precautions

Easily misunderstood behavior

  • • Releasing does not erase the record. It is not physical deletion but deactivation, and the data and signatures that person entered up to that point remain as they are. This is because clinical trial data must stay traceable to who did what and when.

Overview

This dialog assigns a person to the selected site. You cannot pick just anyone; you choose only from users who already belong to the workspace. After you choose a person and a role and select Assign, it takes effect immediately.

Path Investigator assignmentRole permissions summary

Overview

Below the assignment screen, a card shows which roles can be assigned. There are two rules: only roles that work at the site level can be assigned, and one person is assigned to only one site in one project. The system enforces both rules, so an assignment that breaks them is not saved.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Role permissions summary — Lists all roles defined for this project. Whether a role can be assigned is shown by the Site restriction label below.

Roles without the Site restriction label (auditor · data manager) see all sites together, so they are not assigned to a specific site. These roles are granted at the project level on the Role management screen.

Site restriction — A label for roles that handle only their own site. In the role list of the Add investigator dialog, only roles with this label appear.

The on-screen notice states both rules as they are: “Only Site-restricted roles can be assigned. One investigator can be assigned to only one Site within a project (UNIQUE constraint).”

Five roles and whether they can be assigned

RoleWhat they doSite assignment
PI (principal investigator)Is responsible for the subjects and data at their own siteAllowed
CRC (research nurse)Enters subject data for their own siteAllowed
CRA (clinical research associate)Checks the data for their own site against source dataAllowed
DM (data manager)Manages data from all sites togetherNot allowed
AUDITOR (auditor)Reviews all sites in read-only modeNot allowed

Precautions

Must check Data corruption · Form cannot be completed

  • • Releasing an assignment also removes that person's role in the project. Site assignment and role assignment move together, so to move a person to another site, you must first release them and then assign them again at the new site. You cannot assign someone to two sites at the same time.

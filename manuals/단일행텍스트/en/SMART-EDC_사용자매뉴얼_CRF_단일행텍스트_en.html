What is a Single-line text field?

  • 1.1Adding a field and the property panel layout
Path CRF ManagementDataForm DesignEdit form

Overview

Single-line text (TEXT) is a one-line free-text input. Use it to collect short strings that need no line breaks, such as subject initials · specimen numbers · short notes. If you need multiple lines, use Multi-line text; if you need numeric calculation · range comparison, use the Number type.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

[+ Add field] — Specify the type here to create the field.

The new field is added to the structure tree. (Icon T)

The input box appears on the WYSIWYG canvas. The canvas is an entry screen preview, so setting changes are reflected immediately.

fieldKey — The actual key under which the value is stored. 2.1

label (display name) · description (help) — The name and supporting description shown on screen. 2.1

Required · SDV target · AE semantic role · Allow not-measured declaration — Each is explained in Chapter 2.

Type badge — The type of the selected field. It cannot be changed after the field is added.

5 property tabs — Basic · Type settings · Validation · UI · Conditional. Chapters 2–6 of this manual correspond to these tabs.

Precautions

Must check Data corruption · Form cannot be completed

  • • The type cannot be changed after the field is added. If you chose the wrong type, delete the field and add it again. (Only sub-items of table-type fields and field groups are an exception and allow a type change.)
  • • The structure cannot be changed after publishing (PUBLISH). If changes are needed during operation, publish a new version.

Easily misunderstood behavior

  • • When you change a setting, “Changes detected — auto-save pending” appears at the top. The change is saved automatically after a moment; you can also select [Save] to save immediately. To undo, press Ctrl+Z.

Overview

Sets the range of the number of characters that can be entered. The two items are independent, so entering only one of them works.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

minLength — The minimum number of characters. The 2 in the example means “two or more characters”.

maxLength — The maximum number of characters. The 10 in the example means “ten or fewer characters”.

Precautions

Must check Data corruption · Form cannot be completed

  • • Length limits do not change how the canvas looks. They cannot be seen on screen, and a value outside the range is blocked at the save step.
  • • If you narrow the limits on a form already in operation, existing data may remain in violation of the new limits. Such values are blocked when saved again, so decide carefully before reducing limits after publishing.

Easily misunderstood behavior

Path CRF ManagementDataForm DesignEdit formField propertiesType settings tab

Overview

Specifies, as a regular expression, the format the value must follow. Use it to apply rules that length limits alone cannot express (Korean (Hangul) only · English initials · specimen number schemes, etc.).

Screen guide

Setting Where you operate
Result What the setting above changes
Note

pattern (regex) — The ^[\uAC00-\uD7A3]+$ in the example means “Korean (Hangul) only, 1 or more characters”. It prevents English letters · digits from getting mixed into the name input. Values that do not match this format are not saved.

Precautions

Must check Data corruption · Form cannot be completed

  • • If the format does not match, users are blocked only at the save step. Tell them the format in advance with placeholder or helpText. 5.4

Easily misunderstood behavior

  • • ^ means the start and $ means the end. If you omit them, a value passes even if only part of it matches, so they are usually used together.
  • • You can apply the same check with a “Format (regex)” rule in the Validation tab. If you need to specify the message shown on violation yourself, use that instead. 4.3
  • • Regex checks are case-sensitive. To also allow lowercase letters, include them in the range, as in ^[A-Za-z]+$.

Note

  • • The regex and the length limits 3.2 apply together. A value is saved only if it satisfies both.
  • • Complex regexes cause input errors. Use only the minimum necessary.

Path CRF ManagementDataForm DesignEdit formField propertiesConditional tab

Overview

This feature shows or hides this field depending on the value of another field. Use it for branching, such as accepting the number of weeks of pregnancy only when “Pregnant = Yes”.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Enable conditional display (condition) — When selected, the condition settings below appear.

A 🔗 eq badge appears above the field on the canvas to show that a condition is applied.

⚠ On-screen notice — “Hidden fields are exempt from required validation (affects data integrity).” The condition is evaluated by the system.

Reference field fieldKey — Another field in the same form on which the condition is based. Sibling fields in the same form are autocompleted, and you can also type a value not in the list.

operator — The comparison method. The default is eq (equals).

value — The value to compare with.

Example at the bottom — fieldKey="gender" · operator="eq" · value="M" → show this field only when gender is M.

Precautions

Must check Data corruption · Form cannot be completed

  • • Setting a condition can exempt a field from required validation. While a field is hidden because the condition is not met, the form is completed with that field empty even if it is required. This is intended behavior, not a defect — requiring an item that is not shown would make the form impossible to complete.

Easily misunderstood behavior

  • • The condition is evaluated by the system. It does not just hide the field on screen; the validation result changes as well.

Note

  • • If you enable the condition and leave the reference field blank, the condition is never met. Be sure to fill in all of ②–④. 6.2

Must remember

Must check Data corruption · Form cannot be completed

  • • Changing the fieldKey after saving breaks the link to existing data. 2.1
  • • Only fields hidden by conditional display are excluded from the required-item count. Hiding in the UI tab does not exclude them, so hiding a required item makes the form impossible to complete. 5.3 · 6.1
  • • If you narrow length · format restrictions on a form in operation, existing values may be blocked when saved again. 3.2 · 3.3

Easily misunderstood behavior

  • • Editing a value clears SDV verification, and the quality status returns to PENDING. 2.3
  • • The pattern in Type settings and the Format (regex) rule in the Validation tab apply together — if they conflict, no value can be saved. 3.3 · 4.3

Note

  • • If your goal is numeric size comparison · statistics, use the Number type instead of Single-line text.

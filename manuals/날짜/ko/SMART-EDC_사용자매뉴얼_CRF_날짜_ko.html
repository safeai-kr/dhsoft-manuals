경로 CRF 관리DataForm 설계폼 편집

개요

날짜(DATE) 는 달력에서 날짜를 고르는 입력란입니다. 방문일 · 진단일 · 동의일처럼 하루 단위로 기록하는 항목에 사용합니다. 사용자가 직접 타이핑하지 않고 달력에서 선택하므로 형식이 어긋난 값이 들어오지 않습니다. 시각까지 필요하면 날짜시간 타입을 사용합니다.

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

[+ 필드 추가] — 여기에서 타입을 지정하면 필드가 생성됩니다.

구조 트리에 새 필드가 추가됩니다. (달력 아이콘으로 표시됩니다)

WYSIWYG 캔버스에 달력 아이콘이 붙은 입력란이 표시되고 YYYY-MM-DD 안내가 보입니다.

fieldKey — 값이 저장되는 실제 키입니다. 2.1

label (표시명) · description (도움말) — 화면에 표시되는 이름과 보조 설명입니다. 2.1

필수 입력 · SDV 검증 대상 · AE 의미 역할 · 미측정 선언 허용 — 2.2~2.4 에서 다룹니다.

동의일 이전 입력 금지 — 날짜 타입에만 있는 항목입니다. 피험자 동의일보다 이른 날짜를 거부합니다. 2.5

타입 배지 「날짜」 — 선택한 필드의 타입입니다. 추가한 뒤에는 변경할 수 없습니다.

속성 탭 5종 — 기본 · 타입 설정 · 검증 · UI · 조건부. 이 매뉴얼 2~6장이 각 탭에 대응합니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 타입은 추가한 뒤에 변경할 수 없습니다. 잘못 선택했다면 필드를 삭제하고 다시 추가하십시오. (테이블형 · 필드 그룹의 하위 항목만 예외로 타입 변경이 가능합니다.)
  • • 발행(PUBLISH) 이후에는 구조를 변경할 수 없습니다. 운영 중 수정이 필요하면 새 버전을 발행하십시오.

오해하기 쉬운 동작

  • • 설정을 변경하면 상단에 “변경 감지됨 — 자동 저장 대기” 가 표시됩니다. 되돌리기는 Ctrl+Z 입니다.

개요

필드의 이름을 정하는 영역입니다. 저장 키(fieldKey)와 화면에 표시되는 이름(label)은 서로 다른 값이며, 변경해도 되는 시점이 다릅니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

label (표시명) — 입력 화면에 표시할 항목 이름을 입력합니다.

캔버스 필드 제목으로 표시됩니다.

description (도움말) — 표시명 아래에 표시할 보조 설명을 입력합니다. 공란으로 두면 표시되지 않습니다.

입력란 아래 회색 글씨로 표시됩니다.

fieldKey — 값이 저장되는 실제 키입니다. 필드를 추가하면 field_0daq 처럼 자동으로 부여되며 영문 · 숫자 · 밑줄로 변경할 수 있습니다. 화면에는 표시되지 않습니다 — 아래 유의사항을 반드시 확인하십시오.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 저장한 뒤에는 fieldKey 를 변경하지 마십시오. 화면 안내와 같이 “저장 후 변경 시 기존 데이터 매칭 깨짐” — 이미 입력된 값이 새 키와 연결되지 않아 사실상 유실됩니다.
  • • 날짜 항목은 “무엇을 기준으로 한 날짜인지” 를 도움말에 적으십시오. 「진단일」 이 최초 진단인지 현재 질환의 진단인지, 「방문일」 이 내원일인지 검사일인지에 따라 기록자마다 다른 날짜를 넣게 됩니다.
  • • 폼이 ACTIVE 이후 PUBLISHED 상태가 되면 fieldKey 입력란은 자동으로 읽기 전용이 됩니다. 시스템이 변경을 막아 주는 것은 그 이후이므로, 그전까지는 사용자가 직접 주의해야 합니다.

오해하기 쉬운 동작

  • • 표시명은 언제든 변경해도 안전합니다. 저장 키가 아니라 화면 문구이기 때문입니다.

개요

이 항목을 반드시 입력해야 하는지 정합니다. 선택하면 입력 화면에서 날짜를 고르지 않았을 때 저장이 차단됩니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

필수 입력 — 선택하면 이 필드가 필수가 됩니다.

캔버스 표시명 오른쪽에 빨간 별표(*) 가 표시되어 사용자에게 필수임을 알립니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 날짜를 모르는 경우가 생기는 항목은 필수 지정 전에 대책을 정하십시오. 과거 병력의 발병일처럼 정확한 날짜를 확인할 수 없는 항목이 있습니다. 그런 경우에는 미측정 선언2.4을 허용하거나 조건부 표시6장로 해당자에게만 묻는 편이 안전합니다.
  • • 조건부 표시로 숨겨진 필드는 필수 검증이 면제됩니다. 6장 반면 UI 탭의 숨김은 제외되지 않으므로 혼동하지 마십시오. 5.3

오해하기 쉬운 동작

  • • 미측정 선언을 허용한 경우, 사용자가 선언하면 그 필드는 필수 집계에서 제외됩니다. 2.4

참고

  • • 필수 여부는 폼 완료 판정에 사용됩니다. 날짜를 고르지 않으면 값이 비어 있는 것으로 처리됩니다.
경로 CRF 관리DataForm 설계폼 편집필드 속성기본 탭

개요

SDV(Source Data Verification) 는 임상연구모니터요원(CRA)이 입력값을 의료기관 원자료와 대조하는 절차입니다. 이 필드를 그 대상으로 지정할지 여기에서 정합니다. 이 설정은 모든 필드 타입에서 동일하므로 화면도 타입과 무관하게 같습니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

SDV 검증 대상 (CRA 원자료 대조) — 선택하면 이 필드가 CRA 의 대조 목록에 포함됩니다.

선택 상태로 바뀌면서 하위 항목이 활성화됩니다.

검증 필수 (미검증 시 품질 PENDING) — ①을 선택한 뒤에야 지정할 수 있습니다. 선택하면 CRA 가 대조를 마치기 전까지 해당 데이터의 품질 상태가 PENDING 에 머무릅니다.

①을 선택하기 전에는 ②가 흐리게 비활성입니다. 화면 안내와 같이 “검증 대상으로 지정해야 필수 여부를 정할 수 있습니다.”

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 값이 변경되면 검증이 해제됩니다. 이미 VERIFIED 인 필드의 날짜를 수정하면 품질 상태가 PENDING 으로 되돌아가고 CRA 가 다시 대조해야 합니다.

오해하기 쉬운 동작

  • • 날짜는 SDV 대상으로 지정하기 좋은 항목입니다. 동의일 · 방문일 · 투여일처럼 원자료에 날짜가 그대로 남는 항목은 대조가 명확하고, 날짜 하나가 어긋나면 방문 창(window) 판정이나 노출 기간 계산이 모두 달라집니다.
  • • SDV 는 입력한 사람이 직접 수행할 수 없습니다. 시스템이 교차 검증(Cross-User SoD)을 강제하므로 입력자와 검증자는 반드시 달라야 합니다.

참고

  • • 품질 상태는 PENDING → VERIFIED → CLEAN 순으로 진행됩니다. 검증 필수로 지정한 필드가 하나라도 미검증이면 해당 데이터는 CLEAN 이 되지 못합니다.
경로 CRF 관리DataForm 설계폼 편집필드 속성기본 탭

개요

날짜를 확인할 수 없는 경우를 값으로 구분해 기록하는 기능입니다. 빈칸으로 두면 “아직 입력하지 않음” 과 “확인했으나 날짜를 알 수 없음” 을 구별할 수 없습니다. 이 선언이 그 둘을 구분해 줍니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

미측정 선언 허용 — 선택하면 입력 화면에 “미측정” 체크박스가 생성되고, 아래 두 항목이 표시됩니다.

표기 라벨 — 공란으로 두면 기본값 “미측정” 이 적용됩니다.

진단일 미상 으로 변경하면 이 문구가 입력 화면 체크박스와 잠김 안내에 함께 적용됩니다.

지시등 — 기본값은 없음 입니다.

주의(amber) 로 변경하면 선언된 값 옆에 해당 색 표시가 나타납니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 모르는 날짜를 임의의 날짜로 채우지 마십시오. “1월 1일” 이나 “오늘” 로 대신 넣으면 실제 기록과 구별되지 않아 분석에서 걸러낼 수 없습니다. 그것이 이 선언이 있는 이유입니다.
  • • 선언하면 값이 삭제됩니다. 화면 안내와 같이 — “선언 시 값이 삭제되고 필수 항목 집계에서 제외됩니다.”

오해하기 쉬운 동작

  • • 날짜 항목에서 특히 쓸모 있는 기능입니다. 과거 병력의 발병일처럼 피험자도 기억하지 못하는 날짜가 실제로 있습니다. 캡처의 진단일 미상 처럼 표기 라벨을 그 상황이 드러나게 적으십시오.

참고

  • • 지시등을 지정하지 않으면 색 표시가 적용되지 않습니다. 강조가 필요하면 주의(amber) 등을 선택하십시오.
경로 CRF 관리DataForm 설계폼 편집필드 속성기본 탭

개요

날짜 타입에만 있는 항목입니다. 켜면 피험자의 ICF 동의일보다 이른 날짜를 시스템이 거부합니다. 임상시험에서 동의 이후에만 발생할 수 있는 기록(시험 관련 검사 · 투여 · 방문)이 동의 전 날짜로 들어가는 것을 막는 안전장치입니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

동의일 이전 입력 금지 — 선택하면 이 필드에 동의일보다 이른 날짜를 저장할 수 없습니다.

화면 안내 — “피험자 ICF 동의일보다 이른 날짜를 거부합니다. 병력 · 과거 약물 · 생년월일처럼 동의 전 기록이 정상인 항목에는 켜지 마세요 — 저장이 막힙니다.”

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 병력 · 과거 약물 · 생년월일에는 켜지 마십시오. 이 항목들은 동의 전 날짜가 정상인데, 켜 두면 정상적인 기록이 저장되지 않습니다. 화면 안내가 직접 경고하는 내용입니다.
  • • ⛔ 운영 중에 켜면 기존 데이터가 막힙니다. 이미 동의일 이전 날짜로 저장된 값이 있으면, 그 데이터를 다시 저장할 때 차단됩니다. 발행 후에 켜는 것은 신중히 결정하십시오.

오해하기 쉬운 동작

  • • 기준이 되는 날짜는 피험자별 ICF 동의일입니다. 폼이 아니라 피험자 정보에서 가져오므로, 동의일이 등록되지 않은 피험자에게는 비교할 기준이 없습니다.
  • • 이 게이트는 저장 시점에 동작합니다. 달력에서 이전 날짜를 고르는 것 자체는 막히지 않고, 저장할 때 거부됩니다 — 사용자에게는 helpText 로 미리 안내해 주십시오. 5.4

개요

날짜를 어떤 형식으로 표기하고 어느 기간까지 받을지 정하는 탭입니다. 텍스트 타입의 길이 · 정규식이 없고, 이 타입에서 실제로 사용하는 항목은 세 가지입니다.

참고

format — 날짜를 화면에 표기할 형식입니다. 3.2

min · max — 입력 가능한 가장 이른 날짜와 가장 늦은 날짜입니다. 3.2

자동 계산 (calculation) — 항목은 표시되지만 날짜에서는 사용하지 않습니다. 다른 필드 값으로 수치를 산출하는 기능이므로 숫자 타입에서 사용하십시오.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • min · max 는 “차단” 축입니다. 범위를 벗어난 날짜는 저장되지 않습니다. 다만 캔버스에는 범위가 표시되지 않으므로 사용자는 저장 단계에서야 차단 사유를 알게 됩니다 — helpText 로 미리 안내하십시오. 5.4
  • • 동의일 이전 입력 금지2.5와 min 은 다른 장치입니다. min 은 폼 설계 시 정한 고정 날짜이고, 동의일 게이트는 피험자마다 다른 동의일을 기준으로 합니다. 함께 켜면 둘 다 만족해야 저장됩니다.

오해하기 쉬운 동작

  • • 입력란에 흐리게 보이는 YYYY-MM-DD 는 입력 예시이며 설정된 값이 아닙니다. min · max 를 공란으로 두면 날짜 범위 제한이 걸리지 않습니다.

개요

날짜를 어떤 순서로 표기할지와 어느 기간까지 받을지를 정합니다. 두 설정은 성격이 다릅니다 — format 은 보이는 방식이고, min · max 는 저장 가능 여부입니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

format — 날짜 표기 형식입니다. YYYY-MM-DD(연-월-일) 와 DD-MM-YYYY(일-월-연) 중 하나를 선택합니다. 캡처는 YYYY-MM-DD 입니다.

min — 입력 가능한 가장 이른 날짜입니다. 이보다 앞선 날짜는 저장되지 않습니다.

max — 입력 가능한 가장 늦은 날짜입니다. 이보다 뒤의 날짜는 저장되지 않습니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 한 프로젝트 안에서 format 을 섞지 마십시오. 어떤 폼은 연-월-일, 어떤 폼은 일-월-연이면 06-10-2026 을 보고 6월 10일인지 10월 6일인지 혼동하게 됩니다. 프로젝트 전체에서 하나로 통일하십시오.
  • • min · max 는 캔버스에 표시되지 않습니다. 숫자 타입이 입력란 좌우에 범위를 보여 주는 것과 달리, 날짜는 화면으로 확인할 수 없고 저장 단계에서만 차단됩니다. 3.1

오해하기 쉬운 동작

  • • format 은 표기 방식일 뿐 저장값을 바꾸지 않습니다. 추출 자료에는 시스템 표준 형식으로 저장된 날짜가 들어갑니다 — format 을 바꿔도 기존 데이터는 그대로입니다.
  • • “오늘 이후 금지” 같은 상대 조건은 여기서 지정할 수 없습니다. min · max 는 폼을 설계할 때 정하는 고정 날짜입니다. 미래 날짜를 막아야 한다면 검증 탭의 값 범위 규칙으로 상한을 두고 message 로 사유를 알려 주십시오. 4.3

참고

  • • 한쪽만 설정해도 됩니다 — 상한만 두려면 max 만 입력하십시오.

개요

새 입력을 시작할 때 미리 채워 둘 날짜입니다. 달력에서 날짜를 고르거나 직접 입력합니다. 이 타입은 설정 결과를 편집 화면에서 확인할 수 없어 [미리보기] 로 전환해야 합니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

기본값 (defaultValue) — 신규 입력 시 미리 채워질 날짜를 지정합니다. (선택)

편집 화면 캔버스에는 여전히 YYYY-MM-DD 안내만 보입니다. 설정이 반영되지 않은 것이 아니라 편집 화면이 기본값을 그리지 않기 때문입니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 측정 날짜 항목에는 기본값을 지정하지 마십시오. 방문일 · 검사일처럼 피험자마다 달라야 하는 날짜에 기본값이 들어 있으면, 확인하지 않은 날짜가 그대로 저장됩니다. 날짜는 겉보기에 그럴듯해 잘못된 값을 알아채기 어렵습니다.
  • • 기본값도 min · max 범위3.2와 동의일 게이트2.5를 만족해야 합니다. 범위를 벗어난 기본값은 저장 단계에서 차단됩니다.

오해하기 쉬운 동작

  • • 편집 화면만 보고 설정이 안 됐다고 판단하지 마십시오. 날짜 타입은 기본값이 편집 화면 캔버스에 나타나지 않습니다 — 반드시 [미리보기] 로 확인하십시오.
  • • 기본값은 새로 생성하는 입력에만 적용됩니다. 이미 저장된 데이터는 변경되지 않습니다.

  • • 프로젝트 안에서 format 을 섞지 마십시오. 06-10-2026 이 6월 10일인지 10월 6일인지 혼동됩니다. 3.2
  • • 모르는 날짜를 임의의 날짜로 채우지 마십시오. 실제 기록과 구별되지 않습니다 — 미측정 선언을 사용하십시오. 2.4
  • • 측정 날짜에 기본값을 두지 마십시오. 확인하지 않은 날짜가 그럴듯한 모습으로 저장됩니다. 3.3

오해하기 쉬운 동작

  • • 기본값은 편집 화면에 나타나지 않습니다. 설정이 안 된 것이 아니라 [미리보기] 에서만 확인됩니다. 3.3
  • • min 과 동의일 게이트는 다른 장치입니다. min 은 고정 날짜, 게이트는 피험자별 동의일 기준입니다. 3.1

이 문서에서 다루지 않은 것

※ AE 의미 역할 — 기본 탭에 있으나 설정 과정 캡처가 없어 별도 절을 두지 않았습니다. 이상사례(AE) 양식을 사용하는 프로젝트에서만 지정하며, 자세한 사용법은 AE 관련 문서를 참조하십시오.

자동 계산 (calculation) — 타입 설정 탭에 항목이 표시되지만 이 타입에서는 사용하지 않습니다. 다른 필드 값으로 수치를 산출하는 기능이므로 숫자 타입에서 사용하십시오. 3.1

값 범위 외의 검증 규칙 종류 — 날짜 필드에서 실제로 사용하는 것은 값 범위 하나이므로 다른 종류는 다루지 않았습니다. 다른 날짜와 비교하는 검증(예: 종료일이 시작일 이후인지)은 이 탭이 아니라 「프로젝트 검증 규칙」 화면에서 등록합니다. 4.1

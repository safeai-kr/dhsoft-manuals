日付フィールドとは

  • 1.1フィールドの追加と属性パネルの構成
パス CRF管理DataForm設計フォーム編集

概要

日付(DATE) は、カレンダーから日付を選ぶ入力欄です。来院日 · 診断日 · 同意日のように1日単位で記録する項目に使用します。ユーザーが直接入力せずカレンダーから選択するため、形式の異なる値が入ることはありません。時刻まで必要な場合は日時タイプを使用します。

構造ツリーに新しいフィールドが追加されます。(カレンダーアイコンで表示されます)

WYSIWYG キャンバスにカレンダーアイコン付きの入力欄が表示され、YYYY-MM-DD の案内が表示されます。

fieldKey — 値が保存される実際のキーです。2.1

label (表示名) · description (ヘルプ) — 画面に表示される名前と補足説明です。2.1

  • • 発行(PUBLISH)後は構造を変更できません。運用中に修正が必要な場合は、新しいバージョンを発行してください。

概要

フィールドの名前を決める領域です。保存キー(fieldKey)と画面に表示される名前(label)は別々の値であり、変更してよいタイミングが異なります。

結果 すぐ上の設定で変わる位置
参考

label (表示名) — 入力画面に表示する項目名を入力します。

キャンバスのフィールドタイトルとして表示されます。

description (ヘルプ) — 表示名の下に表示する補足説明を入力します。空欄にすると表示されません。

fieldKey — 値が保存される実際のキーです。フィールドを追加すると field_0daq のように自動で付与され、英字 · 数字 · アンダースコアで変更できます。画面には表示されません — 下の注意事項を必ず確認してください。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 保存した後は fieldKey を変更しないでください。画面の案内のとおり「保存後の変更で既存データの紐付けが切れる」 — すでに入力された値が新しいキーと結び付かず、事実上失われます。
  • • 日付項目では、「何を基準とした日付か」をヘルプに記載してください。「診断日」が初回診断なのか現在の疾患の診断なのか、「来院日」が来院した日なのか検査日なのかによって、記録者ごとに異なる日付を入れることになります。
  • • フォームが ACTIVE 以降 PUBLISHED 状態になると、fieldKey 入力欄は自動で読み取り専用になります。システムが変更を防ぐのはそれ以降なので、それまではユーザー自身が注意する必要があります。

誤解しやすい動作

  • • 表示名はいつ変更しても安全です。保存キーではなく画面の文言だからです。

パス CRF管理DataForm設計フォーム編集フィールド属性基本タブ

概要

SDV(Source Data Verification) は、臨床開発モニター(CRA)が入力値を医療機関の原資料と照合する手順です。このフィールドをその対象に指定するかどうかを、ここで決めます。この設定はすべてのフィールドタイプで共通なので、画面もタイプに関係なく同じです。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

SDV検証対象 (CRA原資料照合) — 選択すると、このフィールドが CRA の照合リストに含まれます。

選択状態に変わると、下位項目が有効になります。

検証必須 (未検証時は品質 PENDING) — ①を選択した後でなければ指定できません。選択すると、CRA が照合を終えるまで、そのデータの品質ステータスが PENDING のままになります。

①を選択する前は、②が薄く表示されて無効です。画面の案内のとおり「検証対象に指定した場合のみ必須かどうかを設定できます。」

注意事項

必須確認 データ破損 · フォーム完了不可

  • • 値が変更されると検証が解除されます。すでに VERIFIED のフィールドの日付を修正すると、品質ステータスが PENDING に戻り、CRA が再度照合する必要があります。

誤解しやすい動作

  • • 日付は SDV 対象に指定するのに適した項目です。同意日 · 来院日 · 投与日のように原資料に日付がそのまま残る項目は照合が明確で、日付が一つずれると来院ウィンドウ(window)の判定や曝露期間の計算がすべて変わります。
  • • SDV は入力した本人が実施することはできません。システムがクロス検証(Cross-User SoD)を強制するため、入力者と検証者は必ず別の人である必要があります。

参考

  • • 品質ステータスは PENDING → VERIFIED → CLEAN の順に進みます。検証必須に指定したフィールドが一つでも未検証であれば、そのデータは CLEAN になりません。
パス CRF管理DataForm設計フォーム編集フィールド属性基本タブ

概要

日付を確認できない場合を値として区別して記録する機能です。空欄のままでは、「まだ入力していない」と「確認したが日付が分からない」を区別できません。この宣言がその二つを区別します。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

未測定宣言を許可 — 選択すると、入力画面に「未測定」チェックボックスが作成され、下の二つの項目が表示されます。

表示ラベル — 空欄にすると、デフォルト値「未測定」が適用されます。

診断日不明 に変更すると、この文言が入力画面のチェックボックスとロック案内にあわせて適用されます。

表示灯 — デフォルト値はなしです。

注意(amber) に変更すると、宣言された値の横にその色の表示が現れます。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 分からない日付を任意の日付で埋めないでください。「1月1日」や「今日」で代用すると実際の記録と区別できず、分析で除外できません。それがこの宣言がある理由です。
  • • 宣言すると値が削除されます。画面の案内のとおり — 「宣言時に値が削除され、必須項目の集計から除外されます。」

誤解しやすい動作

  • • 日付項目で特に役立つ機能です。過去の病歴の発症日のように、被験者本人も覚えていない日付が実際にあります。キャプチャの 診断日不明 のように、表示ラベルにはその状況が分かるように記載してください。

参考

  • • 表示灯を指定しないと、色の表示は適用されません。強調が必要な場合は、注意(amber) などを選択してください。
パス CRF管理DataForm設計フォーム編集フィールド属性基本タブ

概要

日付タイプにのみある項目です。オンにすると、被験者のICF同意日より前の日付をシステムが拒否します。臨床試験で同意後にのみ発生しうる記録(試験関連の検査 · 投与 · 来院)が同意前の日付で入力されるのを防ぐ安全装置です。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

同意日前の入力禁止 — 選択すると、このフィールドには同意日より前の日付を保存できません。

画面の案内 — 「被験者のICF同意日より前の日付を拒否します。病歴 · 過去の薬剤 · 生年月日のように同意前の記録が正常な項目ではオンにしないでください — 保存がブロックされます。」

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 病歴 · 過去の薬剤 · 生年月日ではオンにしないでください。これらの項目は同意前の日付が正常ですが、オンにしておくと正常な記録が保存されません。画面の案内が直接警告している内容です。
  • • ⛔ 運用中にオンにすると既存データがブロックされます。すでに同意日より前の日付で保存された値がある場合、そのデータを再保存するときにブロックされます。発行後にオンにするかどうかは慎重に決めてください。

誤解しやすい動作

  • • 基準となる日付は被験者ごとのICF同意日です。フォームではなく被験者情報から取得するため、同意日が登録されていない被験者には比較の基準がありません。
  • • このゲートは保存時に動作します。カレンダーで前の日付を選ぶこと自体はブロックされず、保存時に拒否されます — ユーザーには helpText で事前に案内してください。5.4

パス CRF管理DataForm設計フォーム編集フィールド属性タイプ設定タブ

概要

日付をどの形式で表示し、どの期間まで受け付けるかを決めるタブです。テキストタイプの長さ · 正規表現はなく、このタイプで実際に使用する項目は三つです。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

format — 日付を画面に表示する形式です。3.2

min · max — 入力可能な最も早い日付と最も遅い日付です。3.2

自動計算 (calculation) — 項目は表示されますが、日付では使用しません。他のフィールドの値から数値を算出する機能のため、数値 タイプで使用してください。

デフォルト値 (defaultValue) — 新規入力時にあらかじめ入れておく日付です。3.3

注意事項

必須確認 データ破損 · フォーム完了不可

  • • min · max は「ブロック」の軸です。範囲外の日付は保存されません。ただし、キャンバスには範囲が表示されないため、ユーザーは保存の段階になって初めてブロックの理由を知ることになります — helpText で事前に案内してください。5.4
  • • 同意日前の入力禁止2.5と min は別の仕組みです。min はフォーム設計時に決めた固定の日付で、同意日ゲートは被験者ごとに異なる同意日を基準にします。両方をオンにすると、両方を満たした場合にのみ保存されます。

誤解しやすい動作

  • • 入力欄に薄く表示される YYYY-MM-DD は入力例であり、設定された値ではありません。min · max を空欄にすると、日付の範囲制限はかかりません。

参考

  • • このタブの構成は、フィールドを作成するときに選択したタイプで固定されます。タイプが異なると、このタブの項目も異なります。
パス CRF管理DataForm設計フォーム編集フィールド属性タイプ設定タブ

概要

日付をどの順序で表示するかとどの期間まで受け付けるかを決めます。二つの設定は性質が異なります — format は見え方で、min · max は保存できるかどうかです。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

format — 日付の表示形式です。YYYY-MM-DD(年-月-日) と DD-MM-YYYY(日-月-年) のいずれかを選択します。キャプチャは YYYY-MM-DD です。

min — 入力可能な最も早い日付です。これより前の日付は保存されません。

max — 入力可能な最も遅い日付です。これより後の日付は保存されません。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 一つのプロジェクト内で format を混在させないでください。あるフォームは年-月-日、あるフォームは日-月-年だと、06-10-2026 を見て6月10日なのか10月6日なのか混同することになります。プロジェクト全体で一つに統一してください。
  • • min · max はキャンバスに表示されません。数値タイプが入力欄の左右に範囲を表示するのとは異なり、日付は画面で確認できず、保存の段階でのみブロックされます。3.1

誤解しやすい動作

  • • format は表示方法にすぎず、保存値は変えません。抽出データにはシステム標準形式で保存された日付が入ります — format を変えても既存データはそのままです。
  • • 「今日以降は禁止」のような相対条件はここでは指定できません。min · max はフォームを設計するときに決める固定の日付です。未来の日付をブロックする必要がある場合は、検証タブの値の範囲規則で上限を設け、message で理由を知らせてください。4.3

参考

  • • 片方だけ設定しても構いません — 上限だけを設けるには max だけを入力してください。

  • • 病歴 · 過去の薬剤 · 生年月日に同意日前の入力禁止をオンにしないでください。同意前の日付が正常な項目のため、保存がブロックされます。2.5
  • • 制限はすべて画面に表示されません。範囲 · 同意日ゲート · 検証規則は保存時にのみ動作するため、helpText で事前に案内してください。5.4
  • • プロジェクト内で format を混在させないでください。06-10-2026 が6月10日なのか10月6日なのか混同されます。3.2
  • • 分からない日付を任意の日付で埋めないでください。実際の記録と区別できません — 未測定宣言を使用してください。2.4
  • • 測定日にデフォルト値を設けないでください。確認していない日付がもっともらしい形で保存されます。3.3

誤解しやすい動作

  • • デフォルト値は編集画面に表示されません。設定されていないのではなく、[プレビュー] でのみ確認できます。3.3
  • • min と同意日ゲートは別の仕組みです。min は固定の日付、ゲートは被験者ごとの同意日が基準です。3.1

※ AE意味ロール — 基本タブにありますが、設定手順のキャプチャがないため、別の節を設けていません。有害事象(AE)フォームを使用するプロジェクトでのみ指定します。詳しい使い方は、AE 関連の文書を参照してください。

自動計算 (calculation) — タイプ設定タブに項目が表示されますが、このタイプでは使用しません。他のフィールドの値から数値を算出する機能のため、数値タイプで使用してください。3.1

値の範囲以外の検証規則の種類 — 日付フィールドで実際に使用するのは値の範囲だけのため、他の種類は扱っていません。他の日付と比較する検証(例: 終了日が開始日以降か)は、このタブではなく「プロジェクト検証規則」画面で登録します。4.1

개요

척도(SCALE) 는 정해진 숫자 중 하나를 고르는 Likert 척도 입력입니다. 통증 정도 · 만족도 · 중증도처럼 등급으로 답하는 항목에 사용합니다. 숫자가 보이지만 자유롭게 입력하는 칸이 아니라 버튼이며, 저장되는 값은 사용자가 고른 정수 하나입니다. 고르지 않으면 값이 비어 있습니다. 수치를 직접 입력받아야 하면 숫자 타입을, 글자로 된 선택지가 필요하면 단일 선택 계열 타입을 사용합니다.

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

[+ 필드 추가] — 여기에서 타입을 지정하면 필드가 생성됩니다.

구조 트리에 새 필드가 추가됩니다.

WYSIWYG 캔버스에 선택 버튼이 한 줄로 표시됩니다. 처음에는 1~5 다섯 개이며, 개수와 범위는 타입 설정에서 바꿉니다. 3.2

fieldKey — 값이 저장되는 실제 키입니다. 2.1

label (표시명) · description (도움말) — 화면에 표시되는 이름과 보조 설명입니다. 2.1

타입 배지 「척도 (Likert 1~N)」 — 선택한 필드의 타입입니다. 추가한 뒤에는 변경할 수 없습니다.

속성 탭 5종 — 기본 · 타입 설정 · 검증 · UI · 조건부. 이 매뉴얼은 그중 검증 탭을 다루지 않습니다 — 선택지에서 고르는 방식이라 값 검증이 성립하지 않기 때문입니다. (6.1 ‘다루지 않은 것’)

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 타입은 추가한 뒤에 변경할 수 없습니다. 잘못 선택했다면 필드를 삭제하고 다시 추가하십시오. (테이블형 · 필드 그룹의 하위 항목만 예외로 타입 변경이 가능합니다.)
  • • 저장되는 값은 숫자입니다. 「거의 아프지 않다」 같은 양 끝 라벨은 화면에만 표시되고 데이터에는 고른 정수(예: 3)만 들어갑니다. 추출 자료를 읽을 사람이 그 숫자의 의미를 알 수 있도록 척도 정의를 프로토콜에 함께 기록하십시오.
  • • 발행(PUBLISH) 이후에는 구조를 변경할 수 없습니다. 운영 중 수정이 필요하면 새 버전을 발행하십시오.

오해하기 쉬운 동작

  • • 설정을 변경하면 상단에 “변경 감지됨 — 자동 저장 대기” 가 표시됩니다. 잠시 뒤 자동 저장되며, [저장] 을 선택해 즉시 저장할 수도 있습니다. 되돌리기는 Ctrl+Z 입니다.

개요

필드의 이름을 정하는 영역입니다. 저장 키(fieldKey)와 화면에 표시되는 이름(label)은 서로 다른 값이며, 변경해도 되는 시점이 다릅니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

label (표시명) — 입력 화면에 표시할 항목 이름을 입력합니다.

캔버스 필드 제목으로 표시됩니다.

description (도움말) — 표시명 아래에 표시할 보조 설명을 입력합니다. 공란으로 두면 표시되지 않습니다.

선택 버튼 아래 회색 글씨로 표시됩니다.

fieldKey — 값이 저장되는 실제 키입니다. 필드를 추가하면 field_haxk 처럼 자동으로 부여되며 영문 · 숫자 · 밑줄로 변경할 수 있습니다. 화면에는 표시되지 않습니다 — 아래 유의사항을 반드시 확인하십시오.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 저장한 뒤에는 fieldKey 를 변경하지 마십시오. 화면 안내와 같이 “저장 후 변경 시 기존 데이터 매칭 깨짐” — 이미 입력된 값이 새 키와 연결되지 않아 사실상 유실됩니다.
  • • 척도는 도움말이 특히 중요합니다. 숫자만 보이는 타입이라 어느 쪽이 심한 쪽인지를 글로 알려 주지 않으면 기록자마다 방향을 반대로 이해할 수 있습니다. 도움말2.1과 helpText4.4 를 함께 활용하십시오.
  • • 폼이 ACTIVE 이후 PUBLISHED 상태가 되면 fieldKey 입력란은 자동으로 읽기 전용이 됩니다. 시스템이 변경을 막아 주는 것은 그 이후이므로, 그전까지는 사용자가 직접 주의해야 합니다.

오해하기 쉬운 동작

  • • 표시명은 언제든 변경해도 안전합니다. 저장 키가 아니라 화면 문구이기 때문입니다.

개요

이 항목을 반드시 선택해야 하는지 정합니다. 선택하면 입력 화면에서 아무 버튼도 고르지 않았을 때 저장이 차단됩니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

필수 입력 — 선택하면 이 필드가 필수가 됩니다.

캔버스 표시명 오른쪽에 빨간 별표(*) 가 표시되어 사용자에게 필수임을 알립니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 척도에는 “해당 없음” 선택지가 없습니다. 버튼은 min 부터 max 까지의 숫자뿐이라, 증상이 없는 피험자는 고를 것이 없습니다. 그런 경우가 생기는 항목이라면 ① min 을 0 으로 두어 “0 = 없음” 을 선택지에 포함하거나, ② 조건부 표시로 해당하는 사람에게만 묻거나 5장, ③ 미측정 선언을 허용하십시오2.4. 셋 중 하나를 정하지 않고 필수로 지정하면 폼을 완료할 수 없습니다.
  • • 조건부 표시로 숨겨진 필드는 필수 검증이 면제됩니다. 5장 반면 UI 탭의 숨김은 제외되지 않으므로 혼동하지 마십시오. 4.3

오해하기 쉬운 동작

  • • 미측정 선언을 허용한 경우, 사용자가 선언하면 그 필드는 필수 집계에서 제외됩니다. 2.4

참고

  • • 필수 여부는 폼 완료 판정에 사용됩니다. 아무 버튼도 고르지 않으면 값이 비어 있는 것으로 처리됩니다.
경로 CRF 관리DataForm 설계폼 편집필드 속성기본 탭

개요

SDV(Source Data Verification) 는 임상연구모니터요원(CRA)이 입력값을 의료기관 원자료와 대조하는 절차입니다. 이 필드를 그 대상으로 지정할지 여기에서 정합니다. 이 설정은 모든 필드 타입에서 동일하므로 화면도 타입과 무관하게 같습니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

SDV 검증 대상 (CRA 원자료 대조) — 선택하면 이 필드가 CRA 의 대조 목록에 포함됩니다.

선택 상태로 바뀌면서 하위 항목이 활성화됩니다.

검증 필수 (미검증 시 품질 PENDING) — ①을 선택한 뒤에야 지정할 수 있습니다. 선택하면 CRA 가 대조를 마치기 전까지 해당 데이터의 품질 상태가 PENDING 에 머무릅니다.

①을 선택하기 전에는 ②가 흐리게 비활성입니다. 화면 안내와 같이 “검증 대상으로 지정해야 필수 여부를 정할 수 있습니다.”

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 값이 변경되면 검증이 해제됩니다. 이미 VERIFIED 인 필드의 선택을 바꾸면 품질 상태가 PENDING 으로 되돌아가고 CRA 가 다시 대조해야 합니다.

오해하기 쉬운 동작

  • • SDV 는 입력한 사람이 직접 수행할 수 없습니다. 시스템이 교차 검증(Cross-User SoD)을 강제하므로 입력자와 검증자는 반드시 달라야 합니다.
  • • 피험자가 스스로 답하는 척도(환자 보고 결과)는 대조할 원자료가 없을 수 있습니다. 설문지 원본이 남는 경우에만 SDV 대상으로 지정하는 것이 현실적입니다.

참고

  • • 품질 상태는 PENDING → VERIFIED → CLEAN 순으로 진행됩니다. 검증 필수로 지정한 필드가 하나라도 미검증이면 해당 데이터는 CLEAN 이 되지 못합니다.
경로 CRF 관리DataForm 설계폼 편집필드 속성기본 탭

개요

평가를 수행하지 못한 경우를 값으로 구분해 기록하는 기능입니다. 아무 버튼도 고르지 않으면 “아직 응답하지 않음” 과 “평가할 수 없었음” 을 구별할 수 없습니다. 이 선언이 그 둘을 구분해 줍니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

미측정 선언 허용 — 선택하면 입력 화면에 “미측정” 체크박스가 생성되고, 아래 두 항목이 표시됩니다.

표기 라벨 — 공란으로 두면 기본값 “미측정” 이 적용됩니다.

문구를 바꾸면 입력 화면 체크박스와 잠김 안내에 그 문구가 함께 적용됩니다.

지시등 — 기본값은 없음 입니다.

주의(amber) 로 변경하면 선언된 값 옆에 해당 색 표시가 나타납니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ “증상이 없음” 을 미측정으로 기록하지 마십시오. 캡처의 표기 라벨 통증 없음 은 이 함정을 그대로 보여 줍니다 — 통증이 없다는 것은 평가 결과이지 평가를 못 한 상태가 아닙니다. 미측정으로 선언하면 값이 삭제되고 필수 집계에서도 빠지므로 “통증 없음” 이라는 임상 정보가 사라집니다. 증상 없음을 기록해야 한다면 min 을 0 으로 두어 선택지에 포함하십시오. 3.2
  • • 선언하면 값이 삭제됩니다. 화면 안내와 같이 — “선언 시 값이 삭제되고 필수 항목 집계에서 제외됩니다.”

오해하기 쉬운 동작

  • • 미측정은 “평가 자체가 불가능했던 경우” 에 씁니다. 의식 저하로 통증을 물을 수 없었던 경우, 방문 자체가 이루어지지 않은 경우 등입니다. 표기 라벨도 그런 뜻이 드러나게 적으십시오 (예: 평가 불가).

참고

  • • 지시등을 지정하지 않으면 색 표시가 적용되지 않습니다. 강조가 필요하면 주의(amber) 등을 선택하십시오.

개요

선택지를 만드는 탭입니다. 다른 타입과 달리 길이 · 정규식 · 단위가 없고, 어디부터 어디까지 몇 칸 간격으로 버튼을 만들지와 양 끝에 붙일 설명만 정합니다. 이 타입에서 실제로 사용하는 항목은 세 가지입니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

min · max · step — 선택지의 시작 · 끝 · 간격입니다. 처음부터 1 · 5 · 1 이 들어 있어 그대로 두면 1~5 다섯 칸이 됩니다. 3.2

minLabel · maxLabel — 양 끝 버튼에만 붙는 설명 문구입니다. 3.2

화면 안내 — “Likert 스케일 (min ~ max · step 간격). min/max 라벨은 양 끝 표시용”

자동 계산 (calculation) — 항목은 표시되지만 척도에서는 사용하지 않습니다. 다른 필드 값으로 수치를 산출하는 기능이므로 숫자 타입에서 사용하십시오.

기본값 (defaultValue) — 신규 입력 시 미리 골라 둘 값입니다. 3.3

유의사항

오해하기 쉬운 동작

  • • min · max · step 은 비워 둘 수 없습니다. 세 값이 곧 선택지이므로, 지우면 버튼을 만들 수 없습니다. 다른 타입의 타입 설정 항목이 대부분 “선택” 인 것과 다른 점입니다.
  • • 흐린 글씨로 보이는 전혀 그렇지 않다 · 매우 그렇다 는 입력 예시이며 설정된 값이 아닙니다. 공란이면 양 끝에 아무 문구도 표시되지 않습니다.
  • • 이 탭에는 값 범위를 벗어난 입력을 막는 설정이 없습니다. 필요가 없기 때문입니다 — 사용자는 만들어 둔 버튼 중에서만 고를 수 있어 범위를 벗어난 값이 애초에 생기지 않습니다.

참고

  • • 이 탭의 구성은 필드를 생성할 때 선택한 타입으로 고정됩니다. 타입이 다르면 이 탭의 항목도 달라집니다.

개요

선택지를 몇 개, 어떤 숫자로 만들지와 양 끝의 뜻을 정합니다. 버튼은 min 부터 max 까지 step 간격으로 자동 생성됩니다 — 캡처는 1부터 7까지 1칸씩이라 7개가 됩니다.

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

min — 선택지의 시작 숫자입니다. 기본값은 1 입니다.

max — 선택지의 끝 숫자입니다. 캡처는 7 로 바꿔 7단계 척도가 되었습니다.

step — 숫자 간격입니다. 1 이상이어야 하며, 보통 1 을 그대로 사용합니다.

①~③의 결과 — 캔버스에 1 2 3 4 5 6 7 버튼이 생성됩니다. 개수는 (max − min) ÷ step + 1 로 정해집니다.

minLabel · maxLabel — 양 끝 버튼에 붙일 설명입니다. 캡처는 거의 아프지 않다 · 매우 아프다 입니다.

버튼 줄 좌우 끝에 각각 표시됩니다. 가운데 숫자에는 아무 설명도 붙지 않습니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 발행한 뒤에 척도 범위를 바꾸지 마십시오. 1~5 로 모은 데이터와 1~7 로 모은 데이터는 같은 3 이라도 뜻이 다릅니다. 범위를 바꾸면 이전 데이터와 이후 데이터를 하나의 척도로 분석할 수 없게 됩니다. 범위는 프로토콜에서 확정한 뒤 설정하십시오.
  • • ⛔ “증상 없음” 을 표현해야 한다면 min 을 0 으로 두십시오. min 이 1 이면 가장 낮은 선택지가 “약간 있음” 이 되어, 증상이 없는 피험자가 고를 칸이 없습니다. 2.2 · 2.4
  • • step 을 범위보다 크게 지정해도 시스템이 막지 않습니다. 예를 들어 min 1 · max 5 · step 10 이면 버튼이 하나만 생겨 척도의 의미가 사라집니다. 저장 전에 캔버스에서 버튼 개수를 반드시 확인하십시오.

오해하기 쉬운 동작

  • • min 이 max 보다 크면 저장이 거부됩니다. 두 값을 함께 확인하십시오.
  • • 가운데 숫자의 뜻은 설명되지 않습니다. 양 끝 라벨만 표시되므로, 단계별 정의가 필요하면 helpText 에 적어 주십시오. 4.4

참고

  • • 단계 수가 많을수록 응답이 세밀해지지만 기록자 간 편차도 커집니다. 임상적으로 구분이 필요한 만큼만 두십시오.

⚠ 화면 안내 — “숨겨진 필드는 required 검증이 면제됩니다 (데이터 무결성에 영향).” 조건 판정은 시스템이 수행합니다.

참조 필드 fieldKey — 조건의 기준이 되는 같은 폼 안의 다른 필드입니다. 같은 폼의 형제 필드가 자동완성되며, 목록에 없는 값은 직접 입력할 수도 있습니다.

operator — 비교 방법입니다. 기본값은 eq (같음) 입니다.

value — 비교할 값입니다.

하단 예시 — fieldKey="gender" · operator="eq" · value="M" → 성별이 M 일 때만 본 필드 노출.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 조건을 설정하면 필수 검증이 면제될 수 있습니다. 조건이 맞지 않아 숨겨진 동안에는 그 필드가 필수여도 비어 있는 상태로 폼이 완료됩니다. 이는 결함이 아니라 의도된 동작입니다.
  • • 이미 고른 값이 있는 상태에서 조건이 거짓이 되면 그 값은 화면에서 사라집니다. 분기 기준이 되는 필드를 나중에 바꿀 때 주의하십시오.

오해하기 쉬운 동작

  • • “해당 없음” 문제를 푸는 가장 깔끔한 방법입니다. 증상이 있는 피험자에게만 정도를 묻게 하면, 척도에 “없음” 선택지를 억지로 넣지 않아도 되고 필수 지정도 안전해집니다. 2.2

참고

  • • 조건을 활성화하고 참조 필드를 공란으로 두면 조건이 성립하지 않습니다. 반드시 ②~④를 모두 입력하십시오. 5.2

반드시 기억할 것

필수 확인 데이터 손상 · 폼 완료 불가

  • • 발행한 뒤 척도 범위를 바꾸지 마십시오. 1~5 의 3 과 1~7 의 3 은 뜻이 다릅니다 — 앞뒤 데이터를 한 척도로 분석할 수 없게 됩니다. 3.2
  • • “증상 없음” 을 미측정으로 기록하지 마십시오. 평가 결과이지 평가 불가가 아닙니다. 기록하려면 min 을 0 으로 두십시오. 2.4 · 3.2
  • • “해당 없음” 대책 없이 필수로 지정하지 마십시오. min 0 · 조건부 표시 · 미측정 선언 중 하나를 먼저 정합니다. 2.2
  • • 척도에 기본값을 두지 마십시오. 주관적 평가라 응답이 그 값에 끌려갑니다. 3.3
  • • helpText 에 방향을 적으십시오. 「심할수록 높은 숫자」 한 문장이 척도를 거꾸로 이해하는 사고를 막습니다. 4.4

오해하기 쉬운 동작

  • • 저장되는 값은 숫자뿐입니다. 양 끝 라벨은 화면 문구이며 데이터에 들어가지 않습니다. 1.1
  • • 기본값을 지정해도 캔버스에는 선택 표시가 나타나지 않습니다. 설정이 안 된 것이 아닙니다. 3.3

참고

  • • step 을 범위보다 크게 두면 버튼이 하나만 생기는데 시스템이 막지 않습니다. 캔버스에서 개수를 확인하십시오. 3.2

이 문서에서 다루지 않은 것

※ AE 의미 역할 — 기본 탭에 있으나 설정 과정 캡처가 없어 별도 절을 두지 않았습니다. 이상사례(AE) 양식을 사용하는 프로젝트에서만 지정하며, 자세한 사용법은 AE 관련 문서를 참조하십시오.

검증 탭 — 속성 탭에 존재하지만 척도에서는 사용하지 않습니다. 검증은 사용자가 입력한 값이 조건에 맞는지 검사하는 기능인데, 척도는 만들어 둔 버튼 중에서만 고를 수 있어 범위를 벗어난 값이 애초에 생기지 않습니다. 선택지 자체를 바꾸려면 타입 설정 탭의 min · max · step 을 조정하십시오. 3.2

자동 계산 (calculation) — 타입 설정 탭에 항목이 표시되지만 이 타입에서는 사용하지 않습니다. 다른 필드 값으로 수치를 산출하는 기능이므로 숫자 타입에서 사용하십시오. 3.1

placeholder — UI 탭에 항목이 표시되지만 적용되지 않습니다. 글자를 입력하는 칸이 없는 타입이기 때문입니다. 안내는 helpText 로 하십시오. 4.1 · 4.4

## 만드는 방법

이전 CRF 분권을 만들던 스크립트는 남아 있지 않아 `template/` 아래에 다시 만들었다.

| 파일 | 하는 일 |
| --- | --- |
| `template/parse.py` | 원본 PDF에서 제목·경로·설명 항목·배지·캡처·유의사항·표를 뽑아 `data/model.json`으로 적는다 |
| `template/build.py` | model.json과 번역 파일로 A4 쪽 HTML을 만든다. `--export`를 붙이면 번역 단위 `data/units_ko.json`을 내보낸다 |
| `template/check.py` | Chrome으로 열어 쪽 넘침·머리글·참조·한글 잔존을 검사하고 `checks.json`을 남긴다 |
| `template/check_tr.py` | 번역 파일의 빠진 키·태그 수·참조 번호·한글 잔존을 검사한다 |
| `template/index_update.py` | `index.html`과 README의 분권 표를 checks.json 기준으로 다시 쓴다 |
| `template/make_all.sh` | 18권 × 언어를 한꺼번에 만들고 검사한 뒤 표를 갱신한다 |
| `template/TRANSLATION_BRIEF.md` | 번역 규칙(태그 유지, 참조 번호, 언어별 문체, 용어집) |

한 권을 다시 만들 때는 저장소 루트에서 다음 순서로 돌린다.

```bash
python3 template/parse.py 원본.pdf manuals/로그인
python3 -W ignore template/build.py 로그인 ko --export
python3 template/check.py 로그인 ko
```

번역 파일은 `manuals/<분권>/data/<언어>.json`, 번역자가 남긴 판단 메모는 `manuals/<분권>/i18n/<언어>_notes.md`, 새로 정한 용어는 같은 폴더의 `glossary_<언어>.json`에 있다.

## 캡처 속 글자 번역 (2026-10-30)

영어·독일어·일본어 판의 화면 캡처 202장에서 한국어 글자 자리만 번역어로 바꿨다(고정 프롬프트 11절 2순위). 방법과 도구는 고정 프롬프트 11절 「2순위의 실제 도구」에 적었고, 한 번에 돌리는 명령은 `sh template/localize_all.sh`다.

- 한국어 덩어리 3,490곳 × 3개 언어를 바꿨다. 검수는 권마다 에이전트 한 명이 확인 시트를 보고 했고(`img/loc/verified.json`), 번역은 권마다 한 명이 본문 번역·분권 용어집에 맞춰 했다(`i18n/image_<lang>.json`).
- 「확인 필요」는 번역어가 원래 칸보다 길어 85% 미만으로 줄인 곳이다. 독일어가 가장 많다. 45%로도 넘친 곳(en 102 · de 355 · ja 42)은 좁은 칩·배지가 대부분이라, 실제 현지화 화면을 다시 캡처하거나 승인된 약어를 쓰지 않으면 해결되지 않는다. 덩어리별 목록은 각 권 `<lang>/img/quality-manifest.json`의 `flags`에 있다.
- 「남은 한글」은 OCR이 한글로 읽었는데 픽셀이 그대로인 자리다. 눈으로 보면 모두 글자가 아니거나(아이콘·엑셀의 「가」 글꼴 보기) 모달 뒤에 흐려져 읽을 수 없는 배경 글이라 그대로 두었다. 목록은 `<lang>/img/hangul_check.json`.
- 같은 한국어가 역할에 따라 다르게 번역돼야 하는 곳(「취소」 버튼 Cancel / 상태 Canceled, 「선택」 버튼 Select / 상태 Optional)은 `원문@역할` 키로 나눴다.

남은 과제: 「워크스페이스 삭제」처럼 아이콘이 글자와 한 덩어리로 잡힌 분홍 버튼은 아이콘이 지워진다(검수에서 `icon_lead`를 적지 않은 곳). 「1 명」은 긴 이미지 조각 OCR로 풀렸고, 「삼중 맹검」 설명·데이터내보내기 1.1 「현재 프로젝트는…」·SAE통보 4.1 「변경」처럼 보통 크기 이미지에서 OCR이 못 읽은 줄은 아직 한국어로 남아 있다. 둘 다 검수 데이터를 보강해야 풀린다.

## 원본에서 발견한 것

번역하면서 원문 자체가 어긋나는 곳을 찾았고, 고치지 않고 그대로 옮겼다.

- Lock 1.2와 4.1 하단 안내가 「프로젝트 잠금 해제는 다음 단계에서」, 「Audit Trail 조회 준비 중」이라고 적지만 두 기능은 이미 있다.
- AuditTrail 안내는 카테고리를 「12종」, 부제는 「9종」으로 적는다.
- 플랫폼관리 「대상」 열이 `undefined`로 보이는 결함 설명이 본문에 들어 있다. 화면이 고쳐지면 문장도 지워야 한다.
- 프로젝트 3.3 안내 「다음 데이터가 물리 삭제됩니다」 뒤에 목록이 없다.
- 참여기관 2.3 배너는 상태를 「SETUP / TESTING」으로, 다른 곳은 「설정 중·테스트」로 적는다.

真/偽フィールドとは

  • 1.1フィールドの追加と属性パネルの構成
パス CRF管理DataForm設計フォーム編集

概要

真/偽(BOOLEAN)は、二つの値のどちらかで答える入力欄です。同意の有無 · 基準を満たすかどうか · 症状の有無のように、答えが二つに分かれる項目に使用します。追加するとすぐにラジオが二つ表示され、二つの値の名前は変更でき3.2、ドロップダウンに切り替えることもできます。3.3 答えが三つ以上に分かれる場合や、後で増える可能性がある場合は、単一選択タイプを使用してください。

構造ツリーに新しいフィールドが追加されます。

WYSIWYG キャンバスに「はい」 · 「いいえ」のラジオが二つすぐに表示されます。選択肢を別途作成する必要はありません。

fieldKey — 値が保存される実際のキーです。2.1

label (表示名) · description (ヘルプ) — 画面に表示される名前と補足説明です。2.1

必須入力 · SDV検証対象 — 2.2 · 2.3 で扱います。

AE意味ロール — 画面の案内が「『SAE の有無』は重大性判定を通知 · 抽出につなぐ軸なので、はい/いいえか単一選択フィールドに指定してください」と示すとおり、このタイプが指定対象です。有害事象フォームを使用するプロジェクトでのみ指定します。

未測定宣言を許可 — 2.4 で扱います。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 単一選択をラジオに設定すると、このタイプと画面がまったく同じになります。見た目では区別できないため、タイプバッジで確認してください。異なるのは保存される値です — 真/偽は true · false が、単一選択は Y のような文字列が保存されます。この違いが検証4.3と条件付き6章で表れます。
  • • 条件付き表示の基準にする項目であれば、単一選択を選んでください。真/偽フィールドを他のフィールドの条件の基準にすると、そのフィールドは表示されません。選択する前に、まず6章を確認してください。
  • • タイプは追加した後に変更できず、発行(PUBLISH)後は構造そのものを変更できません。誤って選択した場合は、フィールドを削除して追加し直してください。運用中に修正が必要な場合は、新しいバージョンを発行してください。

概要

フィールドの名前を決める領域です。保存キー(fieldKey)と画面に表示される名前(label)は別々の値であり、変更してよいタイミングが異なります。

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

label (表示名) — 入力画面に表示する項目名を入力します。

キャンバスのフィールドタイトルとして表示されます。

description (ヘルプ) — 表示名の下に表示する補足説明を入力します。空欄にすると表示されません。

ラジオの下にグレーの文字で表示されます。

fieldKey — 値が保存される実際のキーです。フィールドを追加すると field_tmxm のように自動で付与され、画面の案内のとおり「保存後の変更で既存データの紐付けが切れる」です。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • 表示名は、答えが二つに分かれるように書いてください。「BMI基準超過の有無」のように「の有無」で終わると、「はい」 · 「いいえ」が何を意味するかが明確になります。「BMI」のように書くと、何について「はい」 · 「いいえ」で答えるのかが分かりません。
  • • 判定基準はヘルプに書いてください。キャプチャの「BMI ≥ 25 かどうかを判定」のように境界を分ける基準を書いておくと、記録者間のばらつきが減ります — 二つの値の名前3.2だけでは基準が分かりません。
  • • fieldKey は保存した後に変更しないでください。すでに入力されたデータとの紐付けが切れ、このフィールドを参照していた検証規則4.3と条件付き表示6章も一緒に壊れます。

誤解しやすい動作

  • • 表示名(label)はいつでも変更できます。保存された値には影響しません。

パス CRF管理DataForm設計フォーム編集フィールド属性基本タブ

概要

SDV(Source Data Verification) は、臨床開発モニター(CRA)が入力値を医療機関の原資料と照合する手順です。このフィールドをその対象に指定するかどうかを、ここで決めます。この設定はすべてのフィールドタイプで共通なので、画面もタイプに関係なく同じです。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

SDV検証対象 (CRA原資料照合) — 選択すると、このフィールドが CRA の照合リストに含まれます。

選択状態に変わると、下位項目が有効になります。

検証必須 (未検証時は品質 PENDING) — ①を選択した後でなければ指定できません。選択すると、CRA が照合を終えるまで、そのデータの品質ステータスが PENDING のままになります。

①を選択する前は、②が薄く表示されて無効です。画面の案内のとおり「検証対象に指定した場合のみ必須かどうかを設定できます。」

注意事項

必須確認 データ破損 · フォーム完了不可

  • • 値が変更されると検証が解除されます。「はい」を「いいえ」に変えると、品質ステータスが PENDING に戻り、CRA が再度照合する必要があります。

誤解しやすい動作

  • • 判定基準をヘルプに残しておいてください。真/偽は結果だけが残り、判断の根拠は残りません — 「はい」だけでは、CRA が原資料の何と照合すべきかが分かりません。基準を書いておくと照合が速くなります。2.1
  • • SDV は入力した本人が実施することはできません。システムがクロス検証(Cross-User SoD)を強制するため、入力者と検証者は必ず別の人である必要があります。

参考

  • • 品質ステータスは PENDING → VERIFIED → CLEAN の順に進みます。検証必須に指定したフィールドが一つでも未検証であれば、そのデータは CLEAN になりません。
パス CRF管理DataForm設計フォーム編集フィールド属性基本タブ

概要

答えを確認できない場合を値として区別して記録する機能です。真/偽は選択肢が二つしかないため、「まだ入力していない」と「確認したが不明」を区別する方法がありません — この宣言がその二つを区別します。このタイプで特に必要な設定です。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

未測定宣言を許可 — 選択すると、入力画面に「未測定」チェックボックスが作成され、下の二つの項目が表示されます。

表示ラベル — 空欄にすると、デフォルト値「未測定」が適用されます。

bmi 不明 に変更すると、この文言が入力画面のチェックボックスとロック案内に共通で適用されます。

表示灯 — デフォルト値はなしです。

注意(amber) に変更すると、宣言された値の横にその色の表示が現れます。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 真/偽には「わからない」を置く場所がありません。選択肢を増やせないため、確認不可を記録する必要がある場合は、この宣言をオンにすることが唯一の方法です。オンにしないと、記録者が「いいえ」で代わりに入力することになり、「違う」と「わからない」が一つの値に混ざります。
  • • 宣言すると値が削除されます。画面の案内のとおり — 「宣言時に値が削除され、必須項目の集計から除外されます。」

誤解しやすい動作

  • • 宣言されたフィールドは必須集計から除外されます。そのため、必須項目であってもフォームを完了できます。

参考

  • • 表示灯を指定しないと、色の表示は適用されません。強調が必要な場合は、注意(amber) などを選択してください。

  • • 薄い文字の はい · いいえ は入力された値ではなく案内です。空欄にするとその文言がそのまま適用されるため、そのまま使う場合は空欄のままでもかまいません。3.2

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 文言を変えても、保存される値は true · false です。YES と表示していても、データには true が入ります。検証規則4.3と条件付き6章で比較するときは、画面の文言ではなく true · false を書く必要があります。
  • • ⛔ 左が常に true です。二つの欄の順序を入れ替えて入力すると、意味が反転したまま保存されます — 画面は正常に見え、エラーも表示されません。「いいえ」を trueLabel に入れていないか、必ず確認してください。

誤解しやすい動作

  • • 文言は発行後も変更できます。保存された値には影響しないため、表現が不自然であればいつでも修正してください。

概要

新規入力時にあらかじめ選択しておく値を決めます。最初は未設定で、指定すると入力画面が開いたときからその値が選択された状態で表示されます。編集画面には反映されないため、指定したかどうかはプレビューでのみ確認できます。

画面説明

設定 直接操作する位置
結果 すぐ上の設定で変わる位置
参考

デフォルト値 (defaultValue) — 未設定 · 真 (true) · 偽 (false) から選択します。

[プレビュー] では「はい」が選択された状態で表示されます。

注意事項

必須確認 データ破損 · フォーム完了不可

  • • ⛔ 選択肢は作成した文言に従いません。trueLabel を YES に変えても、この欄は「真 (true)」と表示されます — どちらが YES なのかを画面は示さないため、左の欄(trueLabel)が「真」であることを覚えておいて指定してください。3.2
  • • ⛔ 臨床試験の記録にデフォルト値を置くことは慎重に決めてください。記録者が確認しなくても値が入っているため、尋ねていない回答が保存されるおそれがあります。できるだけ未設定のままにしてください。

  • • ⛔ その結果、このフィールドは最後まで表示されません。さらに、非表示のフィールドは必須検証が免除されるため、必須項目なのに値がないままフォームが完了します。エラーも警告も表示されないため、発行後になって初めてデータが空であることに気づくことになります。
  • • ⛔ 条件の基準にする項目は単一選択タイプで作成してください。単一選択は保存値が文字列なので、value 欄と形式が合います — Y のように保存値をそのまま入力すると正常に動作します。1.1
  • • 設定した後は、必ずプレビューで確認してください。バッジが表示されても条件が成立するとは限りません — 基準の値を変えながら、フィールドが実際に表示されるかを確認する必要があります。

誤解しやすい動作

  • • 参照フィールドの fieldKey を変更または削除しても条件が壊れます。条件は表示名ではなく fieldKey で結び付けられます。2.1

必ず覚えておくこと

必須確認 データ破損 · フォーム完了不可

  • • 保存される値は常に true · false です。文言を「YES」に変えてもデータは変わりません — 検証 · 条件付きで比較するときは、文言ではなく true · false を書きます。3.2 · 4.3
  • • 条件の基準にする項目は単一選択で作成してください。真/偽フィールドを参照フィールドに指定すると、対象フィールドが最後まで表示されず、必須検証まで免除されて値がないまま完了します。6.2
  • • 「値の範囲」 · 「小数桁数」 · 「形式 (正規表現)」を使用しないでください。画面では選べますが、このタイプでは成立せず、正規表現は正しい入力をブロックすることがあります。4.2
  • • 左の欄(trueLabel)が常に true です。二つの欄を入れ替えて入れると、意味が反転したまま保存され、エラーは表示されません。3.2
  • • 「わからない」を記録する必要がある場合は、未測定宣言をオンにしてください。選択肢を増やせないため、オンにしないと「違う」と「わからない」が一つの値に混ざります。2.4

誤解しやすい動作

  • • デフォルト値は編集画面に表示されません。[プレビュー] でのみ確認できます。選択肢も作成した文言ではなく「真 (true)」と表示されます。3.4
  • • 単一選択をラジオに設定すると、画面がまったく同じになります。区別はタイプバッジで行ってください — 異なるのは保存される値です。1.1
  • • デフォルトの表示方式はラジオです。単一選択はデフォルトがドロップダウンなので逆です。3.3

参考

개요

참/거짓(BOOLEAN) 은 두 값 중 하나로 답하는 입력란입니다. 동의 여부 · 기준 충족 여부 · 증상 유무처럼 답이 둘로 갈리는 항목에 사용합니다. 추가하면 바로 라디오 두 개가 표시되며, 두 값의 이름은 바꿀 수 있고3.2 드롭다운으로 바꿀 수도 있습니다. 3.3 답이 셋 이상으로 갈리거나 나중에 늘어날 수 있으면 단일 선택 타입을 사용하십시오.

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

[+ 필드 추가] — 여기에서 타입을 지정하면 필드가 생성됩니다.

구조 트리에 새 필드가 추가됩니다.

WYSIWYG 캔버스에 「예」 · 「아니오」 라디오 두 개가 바로 표시됩니다. 선택지를 따로 만들 필요가 없습니다.

fieldKey — 값이 저장되는 실제 키입니다. 2.1

label (표시명) · description (도움말) — 화면에 표시되는 이름과 보조 설명입니다. 2.1

필수 입력 · SDV 검증 대상 — 2.2 · 2.3 에서 다룹니다.

AE 의미 역할 — 화면 안내가 “‘SAE 여부’ 는 중대성 판정을 통보 · 추출로 잇는 축이라 예/아니오 또는 단일 선택 필드에 지정하십시오” 라고 밝히듯, 이 타입이 지정 대상입니다. 이상사례 양식을 사용하는 프로젝트에서만 지정합니다.

미측정 선언 허용 — 2.4 에서 다룹니다.

타입 배지 「참/거짓」 — 선택한 필드의 타입입니다. 추가한 뒤에는 변경할 수 없습니다.

속성 탭 5종 — 기본 · 타입 설정 · 검증 · UI · 조건부. 이 매뉴얼 2~6장이 각 탭에 대응합니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 단일 선택을 라디오로 설정하면 이 타입과 화면이 똑같아집니다. 겉모습으로는 구분할 수 없으므로 타입 배지로 확인하십시오. 다른 것은 저장되는 값입니다 — 참/거짓은 true · false 가, 단일 선택은 Y 같은 문자열이 저장됩니다. 이 차이가 검증4.3과 조건부6장에서 드러납니다.
  • • 조건부 표시의 기준으로 삼을 항목이면 단일 선택을 고르십시오. 참/거짓 필드를 다른 필드의 조건 기준으로 삼으면 그 필드가 표시되지 않습니다. 선택 전에 6장을 먼저 확인하십시오.
  • • 타입은 추가한 뒤에 변경할 수 없고, 발행(PUBLISH) 이후에는 구조 자체를 변경할 수 없습니다. 잘못 선택했다면 필드를 삭제하고 다시 추가하십시오. 운영 중 수정이 필요하면 새 버전을 발행하십시오.

개요

필드의 이름을 정하는 영역입니다. 저장 키(fieldKey)와 화면에 표시되는 이름(label)은 서로 다른 값이며, 변경해도 되는 시점이 다릅니다.

참고

캔버스 필드 제목으로 표시됩니다.

description (도움말) — 표시명 아래에 표시할 보조 설명을 입력합니다. 공란으로 두면 표시되지 않습니다.

라디오 아래 회색 글씨로 표시됩니다.

fieldKey — 값이 저장되는 실제 키입니다. 필드를 추가하면 field_tmxm 처럼 자동으로 부여되며, 화면 안내와 같이 “저장 후 변경 시 기존 데이터 매칭 깨짐” 입니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 표시명은 답이 둘로 갈리도록 적으십시오. 「BMI 기준 초과 여부」 처럼 “여부” 로 끝나면 「예」 · 「아니오」 가 무엇을 뜻하는지 분명해집니다. 「BMI」 처럼 적으면 무엇에 대해 예 · 아니오를 답하는지 알 수 없습니다.
  • • 판정 기준은 도움말에 적으십시오. 캡처의 “BMI ≥ 25 여부 판단” 처럼 경계를 가르는 기준을 적어 두면 기록자 간 편차가 줄어듭니다 — 두 값의 이름3.2만으로는 기준을 알 수 없습니다.
  • • fieldKey 는 저장한 뒤에 변경하지 마십시오. 이미 입력된 데이터와의 연결이 끊어지고, 이 필드를 참조하던 검증 규칙4.3과 조건부 표시6장도 함께 깨집니다.

오해하기 쉬운 동작

  • • 표시명(label)은 언제든 변경할 수 있습니다. 저장된 값에는 영향을 주지 않습니다.

개요

이 필드를 반드시 입력해야 폼을 완료할 수 있게 할지 정합니다. 참/거짓은 두 값 중 하나를 고르는 타입이라 “모름” 을 표현할 자리가 없습니다 — 필수로 지정하기 전에 확인할 수 없는 경우를 어떻게 기록할지 먼저 정하십시오. 2.4

  • • 숨겨진 필드는 필수 검사에서 제외됩니다. 조건부 표시6장로 감춰진 동안에는 필수여도 비어 있는 상태로 폼이 완료됩니다.

오해하기 쉬운 동작

  • • 「아니오」 는 빈 값이 아닙니다. 「아니오」 를 고른 것과 아무것도 고르지 않은 것은 시스템이 서로 다르게 다룹니다 — 미입력만 필수 검사에 걸립니다.

참고

  • • 미측정 선언이 켜져 있고 기록자가 선언하면, 필수 항목이어도 폼을 완료할 수 있습니다. 2.4

개요

SDV(Source Data Verification) 는 임상연구모니터요원(CRA)이 입력값을 의료기관 원자료와 대조하는 절차입니다. 이 필드를 그 대상으로 지정할지 여기에서 정합니다. 이 설정은 모든 필드 타입에서 동일하므로 화면도 타입과 무관하게 같습니다.

참고

선택 상태로 바뀌면서 하위 항목이 활성화됩니다.

검증 필수 (미검증 시 품질 PENDING) — ①을 선택한 뒤에야 지정할 수 있습니다. 선택하면 CRA 가 대조를 마치기 전까지 해당 데이터의 품질 상태가 PENDING 에 머무릅니다.

①을 선택하기 전에는 ②가 흐리게 비활성입니다. 화면 안내와 같이 “검증 대상으로 지정해야 필수 여부를 정할 수 있습니다.”

오해하기 쉬운 동작

  • • 판정 기준을 도움말에 남겨 두십시오. 참/거짓은 결과만 남고 판단 근거가 남지 않습니다 — 「예」 하나만으로는 CRA 가 원자료의 무엇과 대조해야 하는지 알 수 없습니다. 기준을 적어 두면 대조가 빨라집니다. 2.1
  • • SDV 는 입력한 사람이 직접 수행할 수 없습니다. 시스템이 교차 검증(Cross-User SoD)을 강제하므로 입력자와 검증자는 반드시 달라야 합니다.

참고

  • • 품질 상태는 PENDING → VERIFIED → CLEAN 순으로 진행됩니다. 검증 필수로 지정한 필드가 하나라도 미검증이면 해당 데이터는 CLEAN 이 되지 못합니다.

개요

참/거짓의 타입 설정은 네 칸뿐입니다. 선택지를 만들 필요가 없으므로 두 값의 이름3.2 · 표시 방식3.3 · 기본값3.4만 정하면 됩니다. 처음에는 모두 비어 있으며, 비워 두어도 기본값이 적용되어 필드는 정상 동작합니다.

설정 직접 조작하는 위치

  • • ⛔ 캡처의 설정은 동작하지 않습니다. 참조 필드가 참/거짓이면 저장된 값은 true · false 인데, value 칸은 언제나 문자열로 전달됩니다. 두 형식은 견줄 수 없어 시스템이 판정을 포기하고, 판정하지 못한 조건은 숨김으로 처리됩니다. true 라고 고쳐 적어도 결과는 같습니다.
  • • ⛔ 그 결과 이 필드는 끝까지 표시되지 않습니다. 그리고 숨겨진 필드는 필수 검증이 면제되므로, 필수 항목인데도 값 없이 폼이 완료됩니다. 오류도 경고도 표시되지 않아 발행 후에야 데이터가 비어 있는 것을 발견하게 됩니다.
  • • ⛔ 조건의 기준으로 삼을 항목은 단일 선택 타입으로 만드십시오. 단일 선택은 저장값이 문자열이라 value 칸과 형식이 맞습니다 — Y 처럼 저장값을 그대로 입력하면 정상 동작합니다. 1.1
  • • 설정한 뒤 반드시 미리보기로 확인하십시오. 배지가 표시된다고 조건이 성립하는 것은 아닙니다 — 기준 값을 바꿔 가며 필드가 실제로 나타나는지 확인해야 합니다.

오해하기 쉬운 동작

  • • 참조 필드의 fieldKey 를 변경하거나 삭제해도 조건이 깨집니다. 조건은 표시명이 아니라 fieldKey 로 연결됩니다. 2.1

반드시 기억할 것

필수 확인 데이터 손상 · 폼 완료 불가

  • • 저장되는 값은 언제나 true · false 입니다. 문구를 「YES」 로 바꾸어도 데이터는 변하지 않습니다 — 검증 · 조건부에서 비교할 때는 문구가 아니라 true · false 를 적습니다. 3.2 · 4.3
  • • 조건의 기준으로 삼을 항목은 단일 선택으로 만드십시오. 참/거짓 필드를 참조 필드로 지정하면 대상 필드가 끝까지 표시되지 않고, 필수 검증까지 면제되어 값 없이 완료됩니다. 6.2
  • • 「값 범위」 · 「소수 자릿수」 · 「형식 (정규식)」 을 사용하지 마십시오. 화면에서 고를 수는 있으나 이 타입에는 성립하지 않으며, 정규식은 정상 입력을 차단할 수 있습니다. 4.2
  • • 왼쪽 칸(trueLabel)이 항상 true 입니다. 두 칸을 바꿔 넣으면 뜻이 뒤집힌 채 저장되며 오류가 표시되지 않습니다. 3.2
  • • “모름” 을 기록해야 한다면 미측정 선언을 켜십시오. 선택지를 늘릴 수 없으므로, 켜지 않으면 “아니다” 와 “모른다” 가 한 값으로 섞입니다. 2.4

오해하기 쉬운 동작

  • • 기본값은 편집 화면에 나타나지 않습니다. [미리보기] 에서만 확인됩니다. 선택지도 저작한 문구가 아니라 「참 (true)」 로 표시됩니다. 3.4
  • • 단일 선택을 라디오로 설정하면 화면이 똑같아집니다. 구분은 타입 배지로 하십시오 — 다른 것은 저장되는 값입니다. 1.1
  • • 기본 표시 방식이 라디오입니다. 단일 선택은 기본이 드롭다운이라 반대입니다. 3.3

이 문서에서 다루지 않은 것

※ AE 의미 역할 — 이 타입이 지정 대상이지만 설정 과정 캡처가 없어 별도 절을 두지 않았습니다. 자세한 사용법은 AE 관련 문서를 참조하십시오. 1.1

placeholder — UI 탭에 항목이 표시되지만 이 타입에서는 적용되지 않습니다. 라디오와 드롭다운에는 문구를 놓을 자리가 없고, 드롭다운의 — 선택 — 도 고정입니다. 안내는 helpText 에 적으십시오. 3.3 · 5.4

자동 계산 (calculation) — 타입 설정 탭에 항목은 표시되지만 이 타입에서는 사용하지 않습니다. 수식으로 값을 산출하는 기능이므로 숫자 타입에서 사용하십시오. 3.1

공통 코드(CodeGroup) 연동 — 선택지를 프로젝트 공통 코드로 관리하는 기능은 선택지를 만드는 타입(단일 선택 · 다중 선택)의 것입니다. 참/거짓은 두 값이 고정이라 해당하지 않습니다.

활성화 조건 (activeParams) — 시스템에는 정의되어 있으나 이 화면에는 항목이 없습니다.

조건부 표시가 정상 동작하는 화면 — 6장 캡처는 참조 필드가 참/거짓이라 동작하지 않는 설정입니다. 정상 동작 예시는 단일 선택 분권의 6장을 참조하십시오. 6.2

다중 행 텍스트란

경로 CRF 관리DataForm 설계폼 편집

개요

다중 행 텍스트(TEXTAREA) 는 여러 줄을 입력할 수 있는 서술형 입력란입니다. 이상반응 경과 · 조치 내용 · 특이사항처럼 문장으로 기록해야 하는 내용을 입력받을 때 사용합니다. 입력한 줄바꿈이 그대로 보존되며, 입력란 오른쪽 아래 모서리를 끌어 크기를 넓힐 수 있습니다. 한 줄이면 충분하면 단일 행 텍스트를, 숫자 계산 · 범위 비교가 필요하면 숫자 타입을 사용합니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

[+ 필드 추가] — 여기에서 타입을 지정하면 필드가 생성됩니다.

구조 트리에 새 필드가 추가됩니다. (아이콘이 여러 줄을 뜻하는 모양으로 표시됩니다)

WYSIWYG 캔버스에 여러 줄 높이의 입력란이 표시됩니다. 캔버스는 입력 화면 미리보기이므로 설정을 변경하면 즉시 반영됩니다.

fieldKey — 값이 저장되는 실제 키입니다. 2.1

label (표시명) · description (도움말) — 화면에 표시되는 이름과 보조 설명입니다. 2.1

필수 입력 · SDV 검증 대상 · AE 의미 역할 · 미측정 선언 허용 — 2장에서 하나씩 설명합니다.

타입 배지 — 선택한 필드의 타입입니다. 추가한 뒤에는 변경할 수 없습니다.

속성 탭 5종 — 기본 · 타입 설정 · 검증 · UI · 조건부. 이 매뉴얼 2~6장이 각 탭에 대응합니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 타입은 추가한 뒤에 변경할 수 없습니다. 잘못 선택했다면 필드를 삭제하고 다시 추가하십시오. (테이블형 · 필드 그룹의 하위 항목만 예외로 타입 변경이 가능합니다.)
  • • 발행(PUBLISH) 이후에는 구조를 변경할 수 없습니다. 운영 중 수정이 필요하면 새 버전을 발행하십시오.

오해하기 쉬운 동작

  • • 설정을 변경하면 상단에 “변경 감지됨 — 자동 저장 대기” 가 표시됩니다. 잠시 뒤 자동 저장되며, [저장] 을 선택해 즉시 저장할 수도 있습니다. 되돌리기는 Ctrl+Z 입니다.

개요

필드의 이름을 정하는 영역입니다. 저장 키(fieldKey)와 화면에 표시되는 이름(label)은 서로 다른 값이며, 변경해도 되는 시점이 다릅니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

label (표시명) — 입력 화면에 표시할 항목 이름을 입력합니다.

캔버스 필드 제목으로 표시됩니다.

description (도움말) — 표시명 아래에 표시할 보조 설명을 입력합니다. 공란으로 두면 표시되지 않습니다.

입력란 아래 회색 글씨로 표시됩니다.

fieldKey — 값이 저장되는 실제 키입니다. 필드를 추가하면 field_oufn 처럼 자동으로 부여되며 영문 · 숫자 · 밑줄로 변경할 수 있습니다. 화면에는 표시되지 않습니다 — 아래 유의사항을 반드시 확인하십시오.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • ⛔ 저장한 뒤에는 fieldKey 를 변경하지 마십시오. 화면 안내와 같이 “저장 후 변경 시 기존 데이터 매칭 깨짐” — 이미 입력된 값이 새 키와 연결되지 않아 사실상 유실됩니다.
  • • 폼이 ACTIVE 이후 PUBLISHED 상태가 되면 fieldKey 입력란은 자동으로 읽기 전용이 됩니다. 시스템이 변경을 막아 주는 것은 그 이후이므로, 그전까지는 사용자가 직접 주의해야 합니다.

오해하기 쉬운 동작

  • • 서술형 항목일수록 도움말이 중요합니다. 무엇을 어느 수준까지 적어야 하는지 알려 주지 않으면 기록자마다 내용의 깊이가 달라져 데이터를 모아 쓰기 어려워집니다.

참고

  • • 도움말(description)과 UI 탭의 helpText 는 서로 다른 항목입니다. 차이는 5.4 에서 설명합니다.
경로 CRF 관리DataForm 설계폼 편집필드 속성기본 탭

개요

이 항목을 반드시 입력해야 하는지 정합니다. 선택하면 입력 화면에서 값이 비어 있을 때 저장이 차단됩니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

필수 입력 — 선택하면 이 필드가 필수가 됩니다.

캔버스 표시명 오른쪽에 빨간 별표(*) 가 표시되어 사용자에게 필수임을 알립니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 서술형 항목을 무조건 필수로 지정하지 마십시오. 적을 내용이 없을 때 “없음” 같은 의미 없는 문구를 채워 넣게 되어 데이터 품질이 오히려 떨어집니다. 기록할 내용이 없는 경우가 있다면 미측정 선언 허용2.4이나 조건부 표시6장를 함께 고려하십시오.
  • • 조건부 표시로 숨겨진 필드는 필수 검증이 면제됩니다. 6장 표시되지 않는 항목을 필수로 요구하면 폼을 완료할 수 없기 때문입니다.
  • • UI 탭의 숨김은 필수 집계에서 제외되지 않습니다. 조건부 표시와 혼동하지 마십시오. 5.3

참고

  • • 필수 여부는 폼 완료 판정에 사용됩니다. 필수 항목이 비어 있으면 해당 폼은 완료로 집계되지 않습니다.
경로 CRF 관리DataForm 설계폼 편집필드 속성기본 탭

개요

SDV(Source Data Verification) 는 임상연구모니터요원(CRA)이 입력값을 의료기관 원자료와 대조하는 절차입니다. 이 필드를 그 대상으로 지정할지 여기에서 정합니다. 이 설정은 모든 필드 타입에서 동일하므로 화면도 타입과 무관하게 같습니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

SDV 검증 대상 (CRA 원자료 대조) — 선택하면 이 필드가 CRA 의 대조 목록에 포함됩니다.

선택 상태로 바뀌면서 하위 항목이 활성화됩니다.

검증 필수 (미검증 시 품질 PENDING) — ①을 선택한 뒤에야 지정할 수 있습니다. 선택하면 CRA 가 대조를 마치기 전까지 해당 데이터의 품질 상태가 PENDING 에 머무릅니다.

①을 선택하기 전에는 ②가 흐리게 비활성입니다. 화면 안내와 같이 “검증 대상으로 지정해야 필수 여부를 정할 수 있습니다.”

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 값이 변경되면 검증이 해제됩니다. 이미 VERIFIED 인 필드의 값을 수정하면 품질 상태가 PENDING 으로 되돌아가고 CRA 가 다시 대조해야 합니다. 서술형 항목은 문구를 조금만 다듬어도 값이 바뀐 것으로 처리되므로, 대조가 끝난 뒤의 수정은 특히 신중해야 합니다.

오해하기 쉬운 동작

  • • SDV 는 입력한 사람이 직접 수행할 수 없습니다. 시스템이 교차 검증(Cross-User SoD)을 강제하므로 입력자와 검증자는 반드시 달라야 합니다.

참고

  • • 품질 상태는 PENDING → VERIFIED → CLEAN 순으로 진행됩니다. 검증 필수로 지정한 필드가 하나라도 미검증이면 해당 데이터는 CLEAN 이 되지 못합니다.
  • • 모든 필드를 SDV 대상으로 지정하면 모니터링 부담이 급격히 증가합니다. 1차 평가변수 · 안전성 항목 위주로 지정하십시오.
경로 CRF 관리DataForm 설계폼 편집필드 속성기본 탭

개요

기록을 남길 수 없는 경우를 값으로 구분해 기록하는 기능입니다. 공란으로 두면 “아직 입력하지 않음” 과 “확인할 수 없어 적지 못함” 을 구별할 수 없습니다. 이 선언이 그 둘을 구분해 줍니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

미측정 선언 허용 — 선택하면 입력 화면에 “미측정” 체크박스가 생성되고, 아래 두 항목이 표시됩니다.

표기 라벨 — 공란으로 두면 기본값 “미측정” 이 적용됩니다.

상세 정보 확인 불가 로 변경하면 이 문구가 입력 화면 체크박스와 잠김 안내에 함께 적용됩니다.

지시등 — 기본값은 없음 입니다.

주의(amber) 로 변경하면 선언된 값 옆에 해당 색 표시가 나타납니다.

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 선언하면 값이 삭제됩니다. 화면 안내와 같이 — “선언 시 값이 삭제되고 필수 항목 집계에서 제외됩니다.” 서술형 항목은 이미 길게 작성해 둔 내용이 통째로 사라질 수 있으므로 사용자에게 반드시 미리 안내하십시오.

오해하기 쉬운 동작

  • • 선언된 필드는 필수 집계에서 제외됩니다. 따라서 필수 항목이어도 폼을 완료할 수 있습니다.
  • • 표기 라벨은 그 항목에서 실제로 무엇을 못 했는지 드러나게 적는 편이 좋습니다. 캡처의 상세 정보 확인 불가 처럼 적으면 “측정” 이라는 표현이 어색한 서술형 항목에도 자연스럽게 맞습니다.

참고

  • • 지시등을 지정하지 않으면 색 표시가 적용되지 않습니다. 강조가 필요하면 주의(amber) 등을 선택하십시오.

타입 설정 탭 — 입력 형식

경로 CRF 관리DataForm 설계폼 편집필드 속성타입 설정 탭

개요

입력 형식을 정하는 탭입니다. 여기에서 지정한 값은 저장할 때 시스템이 다시 검사하므로, 화면에서만 안내하는 문구가 아니라 실제 차단 조건입니다. 다중 행 텍스트에서 실제로 사용하는 항목은 세 가지입니다.

화면 설명

설정 직접 조작하는 위치
결과 바로 위 설정으로 바뀌는 위치
참고

minLength · maxLength — 문자 수의 하한과 상한입니다. 3.2

pattern (정규식) — 값이 따라야 할 형식입니다. 3.3

prefix · postfix — 항목은 표시되지만 다중 행 텍스트에는 적용되지 않습니다. 입력란 좌우에 고정 문구를 붙이는 기능이라 여러 줄 입력란과는 맞지 않습니다. 입력해도 화면에 나타나지 않으므로 비워 두십시오.

자동 계산 (calculation) — 다른 필드 값으로 값을 산출하는 기능이라 이 타입에서는 사용하지 않습니다. 계산이 필요하면 숫자 타입에서 사용하십시오.

기본값 (defaultValue) — 신규 입력 시 미리 입력해 두는 값입니다. 3.4

유의사항

필수 확인 데이터 손상 · 폼 완료 불가

  • • 반대로 진한 글씨로 보이는 값(캡처의 maxLength 2000)은 이미 설정된 값입니다. 불필요하면 값을 지워야 제한이 해제됩니다.

  • • 형식 제한에 줄바꿈을 포함하지 않으면 여러 줄로 작성한 값이 저장되지 않습니다. 이 타입에서 가장 자주 발생하는 실수입니다. 3.3 · 4.3
  • • 서술형 항목의 기본값은 사용하지 마십시오. 확인하지 않은 내용이 “특이사항 없음” 으로 저장됩니다. 3.4
  • • 저장한 뒤 fieldKey 를 변경하면 기존 데이터와의 연결이 끊어집니다. 2.1
  • • 조건부 표시로 숨겨진 필드만 필수 집계에서 제외됩니다. UI 탭의 숨김은 제외되지 않아 필수 항목을 숨기면 폼을 완료할 수 없습니다. 5.3 · 6.1

오해하기 쉬운 동작

  • • 조건의 value 는 화면 문구가 아니라 선택지의 저장값입니다. 6.2
  • • 값을 수정하면 SDV 검증이 해제되어 품질 상태가 PENDING 으로 되돌아갑니다. 2.3

참고

  • • 레이아웃 너비는 전체 를 권장합니다. 폭을 줄이면 작성 중인 문장을 확인하기 어려워집니다. 5.2

이 문서에서 다루지 않은 것

※ AE 의미 역할 — 기본 탭에 있으나 설정 과정 캡처가 없어 별도 절을 두지 않았습니다. 이상사례(AE) 양식을 사용하는 프로젝트에서만 지정하며, 자세한 사용법은 AE 관련 문서를 참조하십시오.

prefix · postfix — 타입 설정 탭에 항목이 표시되지만 다중 행 텍스트에는 적용되지 않습니다. 입력란 좌우에 고정 문구를 붙이는 기능이므로 단일 행 텍스트 · 숫자 타입에서 사용하십시오. 3.1

자동 계산 (calculation) — 같은 이유로 이 타입에서는 사용하지 않습니다. 다른 필드 값으로 값을 산출하는 기능이므로 숫자 타입에서 사용하십시오. 3.1

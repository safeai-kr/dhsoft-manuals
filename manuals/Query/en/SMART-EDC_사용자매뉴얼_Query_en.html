Query list

  • 1.1Screen layout
  • 1.2Row action menu
Path Project dashboardQuery list

Overview

This screen handles query requests (Query) for entered data in one place. From top to bottom it has summary cards, filters and the list, and each row in the list is one Query. Answering, closing and reopening all start on this screen. You perform them from the action menu at the right end of each row 1.2.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Status filter — narrows the list by Unanswered, Answered, Closed and so on.

Severity filter — narrows the list by Minor, Major or Critical.

Scope filter — narrows the list by scope.

Creation source filter — narrows the list by Auto (rule) and Manual. Auto means a Query created by a validation rule.

Guidance under the title — “Look up the Data Queries for this project and handle answering, closing and reopening.”

OPEN — number of Queries not yet answered.

ANSWERED — number of Queries that have an answer but are not yet closed.

Overdue Query (>30 days OPEN) — number of Queries that have gone more than 30 days without an answer since they were created. Answered Queries never appear here, however old they are.

Target column — the Query title. Select the title to go to the Query details, where you can check the processing history and the resolution status for each target.

Scope column — one of four types: Single field · Cross-field · Cross-CRF · Cross-Visit.

Severity column — one of three levels: Minor · Major · Critical.

The small text under the title shows Field · Subject · Visit · CRF. Check here which data the Query is attached to.

Six Query statuses

StatusMeaningNext action
UnansweredWaiting for an answerThe assignee answers
AnsweredAn answer has been recordedThe data manager closes it
Partially answeredOnly some of several targets are resolvedProcess the remaining targets
ClosedResolution has been confirmedNone — if needed, Reopen it
ReopenedClosed and then queried againAnswer the new Query
CancelledA discarded QueryNone — this screen has no cancel function

Precautions

Easily misunderstood behavior

  • • Auditors can only view this screen. Users who have none of the processing rights (create, answer, close, reopen) see every action as disabled. The same applies when the project is closed or archived.
Path Query listRow action menu

Overview

This is the right-hand area of the same screen as 1.1. Query processing is done row by row. Select ⋯ at the right end of a row to open its menu. The items depend on the status of that row and on your permissions. The screenshot shows an Answered row, so Answer and Close appear together, and Reopen does not appear. Reopen opens only on Closed rows.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

New Query — create a Query manually 2.1. Shown only to the principal investigator, monitors and data managers.

Search — narrow by message, field or assignee.

Reset filters — clears all the conditions you have set at once.

⋯ — opens the action menu for that row. If there is nothing you can do, the ⋯ itself is not shown.

Data entry screen — moves to the CRF entry screen where the Query points 3.2. It is a read-only jump, so it is shown regardless of permissions, and auditors can use it too.

Answer — opens the answer window 3.1. It opens in the Unanswered · Answered · Reopened statuses.

The first row is Answered, so Answer and Close both appear.

The second row is Unanswered, so the same menu shows Answer only, without Close.

Precautions

Easily misunderstood behavior

  • • Some Queries do not show the “Data entry screen” item. If a Query has no subject, visit or CRF location recorded, there is nowhere to go, so the item is not drawn. This is not a fault. In that case, check the identifier in the target column and go find that CRF yourself.

Path Query listManual Query creation

Overview

This window creates a Query by hand. The steps are numbered, and ⓪ you cannot open the rest until you first select the subject, because the visit, CRF and field lists are all derived from that subject. This structure means there is no way to mix targets from different subjects.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

⓪ Target subject — required. Select this first.

Add target — adds a field to be confirmed. You can specify several targets 2.2.

③ Query title — required. It appears as is in the Target column of the list.

Content — required, 5 characters or more. Describe specifically the difference or contradiction between the source data and the entered value.

④ Severity — the level of importance. The default is Major, and you can change it to Minor or Critical.

⑤ Assignee — required. Specifies the person who will answer this Query.

Close — closes the window without creating anything.

Guidance in the target area — “Select the target subject first.” Until you select a subject, nothing can be added to this area.

② Query scope — empty. “The scope is set when you select targets.”

Scope note — “The server sets the scope from the distribution of the selected targets. The display here is a preview; the creation result is final.” It is not an item you choose directly.

The Assignee box is set to Direct input, with the message “There are no active researchers assigned to this site. Complete the site assignment first.” This is the fallback input used when there are no candidates to choose from, not a fault.

Automatic actions on creation — when the Query is created, the assignee is notified, the quality status of that CRF changes to Query open, and a creation record is added to the processing history.

Cancel · Create Query — until all required items are filled in, Create Query is dimmed and cannot be selected 2.2.

Precautions

Easily misunderstood behavior

  • • If there are no candidates for the assignee, finish the site assignment first. The assignee is required, so if no active researcher is assigned to that site, there is nothing to choose from. The normal path is to complete the researcher assignment on the participating sites screen first, then come back.
Path Manual Query creationSelecting targets

Overview

When you select a subject, the target area opens and narrows down in the order visit → CRF → field. Once you have selected all three, ② Query scope is filled in automatically. It is not an item you choose directly. It is the result the system decides by checking how many items the targets you set span.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Visit — choose from the visits generated for that subject.

CRF — choose from the CRFs linked to that visit.

Field — choose the items in that CRF that you want confirmed.

② Query scope is set to Single field, and “There is 1 target.” is shown alongside. Adding more targets changes it to a cross-scope.

Create Query — creates the Query. You can select it only after all required items (subject · target · title · content · assignee) are filled in.

The selected subject is confirmed and shown as Screening No. If you change it here, the targets below are reset, so confirm it first.

③ Query title — the name used to find this Query in the list, so state clearly what is being asked.

Content — state the basis so the assignee can check the source data.

④ Severity — used as is in the Severity column and in the list filter.

⑤ Assignee — if there is an assigned researcher, the field changes to a select-from-list method 2.1. The role is shown in parentheses next to the name.

Cancel — discards your input and closes the window.

Precautions

Easily misunderstood behavior

  • • The Query scope is confirmed only when the Query is created. The scope shown in the window is a preview, and the server makes the final decision. In a CRF collected repeatedly, the same visit and the same form can be treated as a cross-scope if the occurrence differs, so check the result in the Scope column of the list after you create the Query.
Path Manual Query creationCreation result

Overview

When you create the Query, the window closes and you return to the list. The new Query comes in at the top of the list, and the numbers on the summary cards change too. By this point the assignee has already been notified, and the quality status of that CRF has changed to Query open.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

The newly created Query — select the title to go to the Query details. The small text below shows Field · Subject · Visit · CRF.

OPEN has gone up by one. A new Query always starts as Unanswered.

ANSWERED stays the same, because it does not change until an answer comes in. The Overdue Query on the right also stays the same, since elapsed days are 0 and it is outside the 30-day threshold. Only Showing goes up.

The target of the new Query — the field, subject, visit and CRF you specified are shown as they are.

Scope is the value the server set at creation 2.2.

Precautions

Easily misunderstood behavior

  • • The person who created a Query can also answer it, because the answer right belongs to the assignee or the creator. However, if they do, the person asking and the person answering are the same, which removes the point of the check. Have the assignee check the source data and answer.

Answering

  • 3.1Answering a Query
  • 3.2Answering from the data entry screen
Path Query listAnswering a Query

Overview

This window records the result of the assignee checking the source data. If the target is in one place, you handle the value correction and the answer together in this window, and one save records both. A Query whose target spans several places receives an answer without any value correction and becomes Partially answered.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Value correction — if the value differs from the source data, correct it here. The bounds on each side are the allowed range, and a value outside it is blocked when you save. You can answer without changing the value.

Reason for change — required only when you changed the value, 5 characters or more. If you leave the value as it is, it is not required.

Answer — always required, 5 characters or more. Describe the result of checking the source data and whether the value was changed.

Save answer + value — saves the value and the answer together. If you did not change the value, the button shows Save answer.

In the list, the status changes to Answered, the OPEN count goes down and the ANSWERED count goes up. Now wait for the data manager to close it 4.1.

Status · Scope · Severity badges — check which Query you are answering.

Query content — title · body · target. Be sure to read it before you answer.

Current value — the value saved now. Compare it with the value in the input box below to see what changes.

Close — closes the window without answering.

Cancel — discards your input and closes the window.

Precautions

Easily misunderstood behavior

  • • Not everyone can answer. You must have a role with answer permission, and also be the assignee or the creator of that Query. If you do not see the answer item in the list, you are not the target, so check the Assignee column and pass the Query on to that person.
Path Query listData entry screen

Overview

Moving to the data entry screen from the row action opens the CRF that contains the item the Query is attached to. Here you can answer while looking at the actual values, which is more convenient when you need to compare against source data. If one item has several Queries, several cards stack up.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Close — closes an answered Query on the spot. Shown only to a data manager or to the assignee of that Query.

Answer comment — enter the answer to an unanswered Query here. It must be 5 characters or more, and it is saved together with the value when you select Save on the form.

Use this comment as the reason for change — if you changed the value, this comment takes the place of the separately required reason for change.

Unanswered Query N and Waiting to close N in the band at the top of the screen — the first is the number you need to answer, and the second is the number waiting to be closed. The tasks are different.

Answered card — a Query that already has an answer. It tells you the next step with “The answer is recorded. Review it, then close it.”

History · details — check the full conversation and processing history of that Query.

Unanswered card — a Query not yet answered. The count on the Query icon at the right end of the item is shown alongside.

Resolution method — not an item you choose, but a result judged by whether the value was changed. If you correct the value, it changes automatically to Value corrected, and if you do not, to Current value kept.

Precautions

Must check Data corruption · Form cannot be completed

  • • Answers on this screen are recorded only when you save the form. If you only write a comment and leave the screen, nothing is kept. This differs from the answer window in the Query list, which completes saving in one step. Once you write a comment, be sure to confirm it with Save.

Closing and reopening

  • 4.1Closing a Query

Path Query listClosing a Query

Overview

This window closes a Query after you have reviewed the answer. Only data managers can open it, and only in the Answered status. Closing is not the final step. It is a reversible closure, and if you need to check again later, you continue with a reopen 4.2.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Closing reason — required. State what resolved it. If you leave it blank, saving is rejected.

Close Query — closes the Query.

The status in the list changes to Closed, and the Query drops out of the ANSWERED count.

Header note in the window — “After reviewing the answer, switch to CLOSED · You can reopen it afterward to re-query.” It tells you that closing is not the final status.

The Query content and target — check what you are closing.

The label states the nature of the reason — “Basis for resolution · audit evidence — required”, because clinical trial data must keep a record of why it was closed.

Cancel — leaves the window without closing.

Close — the same action.

Precautions

Must check Data corruption · Form cannot be completed

  • • The closing reason is audit evidence. A phrase with no content, such as “Confirmed”, means you cannot later explain why the Query was resolved. Record what you checked and on what basis you closed it.
Path Query listQuery Reopen

Overview

This window asks again about a Query that was closed. It opens only in the Closed status, and only for monitors and data managers. The key point is that it does not bring back the original Query. The original item stays, marked as Reopened, and one more new Query is created to receive the answer.

Screen guide

Setting Where you operate
Result What the setting above changes
Note

Reason for reopening — required, 5 characters or more. State the basis for why the existing answer did not resolve the issue.

Additional query content — required, 5 characters or more. These are the items to confirm further with the assignee, and they become the content of the new Query.

Assignee — the person who receives the new Query. The existing assignee is the default, and you can change it.

Reopen — starts the re-query. It is dimmed and cannot be selected until both reasons are filled in.

The original Query's status changes to Reopened, and separately, a new Unanswered Query is added to the list. The new row also shows which reopen it is, such as (reopen #1).

Severity carries over from the original Query.

The content and target of the closed Query — check what is being asked again.

Cancel — closes the window without re-querying.

Close — the same action.

Precautions

Easily misunderstood behavior

  • • Reopening adds one more item to process. From now on you must answer the newly created Query, and the original item is kept in the Reopened status to preserve the history. Seeing two items in the list is normal, so handle the one that is Unanswered.
